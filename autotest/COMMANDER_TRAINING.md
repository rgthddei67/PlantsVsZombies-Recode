# 冷藏站指挥官训练

## 混合卡池与实战收益校准

当前继续训练入口：

```powershell
python autotest/train_commander_league.py --output build/clang-release/autotest/training/league_run --curriculum openings --long-seconds 900 --calibration off --generations 1
```

`--curriculum openings` 将正常开局作为训练和发布对照的主任务：包含正式第十章、全陆地与删减卡池，所有完整对局采用 `--long-seconds`，留出覆盖 10-1～10-9 的两种对手。候选冻结后另测预建成熟阵地、低库存经济残局和高库存片段，写入 `diagnostics.json`，不参与本轮选优，也不混入开局胜率。残局失败本身不等于开局策略无效；高库存无进展等异常仍需人工审查，不能因诊断不参与选优就忽略运行缺陷。旧课程保留用于复现，不把旧结果按新规则重新宣布合格。

`fortifier` 陪练沿用曙光莲/猎工反制，有基本向日葵经济后优先补各路输出、后排南瓜和冰瓜，再继续扩建经济。只改变合法动作顺序，不增加资金、不重置冷却、不影响原有陪练或正式 AI。`opening_review.json` 按正常开局/战术片段分别列出每分钟真实支出、补给、制冰/击杀收入、玩家资金、植物构成与小推车余量；残局另有 `fixture_review.json`。这些轨迹用于定位发育空档，不直接增加训练奖励，不把低库存自动标成必败，也不把相关变化称为因果结论。旧日志缺少植物构成时标为未知，独立复查可运行 `python autotest/commander_opening_review.py <联赛目录>`。

加 `--curriculum siege` 可切换守线反制课程：提高正式卡池下正常开局、中期与成型阵地对曙光莲/灰烬陪练的比例，同时保留全陆地、随机删减、精英菇和经营阵。候选冻结后使用新种子对照，继续覆盖第十章九关，并额外检查 10-1 同类防守；预建阵地是战术片段，须与正常开局成绩分开解释。课程名写入运行标识，切换时使用新输出目录，不能混用旧成绩。这只切换训练场景，不修改正式关卡卡池或单位数值。

`--curriculum endurance --long-seconds 900` 延长正式卡池与高库存成型阵地的评估，其余场景仍使用 `--seconds`。`banked` 是一次性布置双方资源、后排南瓜/西瓜和充好能量的曙光莲的战术夹具，不能称为真人存档重放。联赛仍优先真实胜场；胜场相同才比较消灭植物的实际返冰和消耗割草机，不奖励单纯库存、等待时长或波数，也不再因为超时未输就自动排在有推进但失败的探索之前。迟来的真实胜利与早期胜利同等计入，超时仍如实标记，不修改游戏胜负或强制出兵规则。

`--population` 控制每代候选数；`--reference-policy <备份文件>` 将额外基线纳入选优及独立验收，避免只超过较弱的试玩版本却退步于备份版本。参考基线和当前策略各自检查真实胜负门槛。整个运行期间不覆盖当前游戏权重。

`--restarts <数量>` 在每代加入重新抽取收益权重的候选，交替保留和重置兵种偏好/局势系数，再做随机变异，避免只围绕同一策略小幅扰动。正式卡池、净收支约束和搜索版本继承不变；不指定兵种模板或固定进攻库存线。它不能与冻结基础权重的 `--state-only` 同用；数量和实际候选都写入检查点。

`train_commander_fresh.py --paired-run <已完成联赛目录> --output <新目录>` 进行从零起步对照：使用代码初始权重、全零兵种偏好和局势系数，不复制旧生产校准。只复用继承组的训练场景、种子、代数和每代候选数，不使用旧候选或旧成绩选优；第一代从多个新目标起步，后续继续变异。此组不另拟合生产校准，继承组已有的校准及前置采集成本在对比时须注明。两组参数冻结后再抽另一批共同留出对局，与当前配置一起比较；通过核验及胜率门槛前不自动发布。这是一次起点对照，不把单次随机搜索的差异宣称为普遍结论。

`--state-model` 探索可选的局势评分层：以库存、现有工人的预计收入、植物火力与经济、可用反制和无植物击杀时长为输入，学习对八项收益评分的调整。系数从零或已训练模型继承，再由实战变异选优；没有固定的进攻库存线、最低投入或兵种组合。旧资源不带 `stateModel` 时保留原搜索，新模型可比较更大的编队、更长的分批到场与交战窗口，具体计算上限集中在 `ColdStorageSearch.cpp`；所有承诺仍须用当前库存支付，不预支预测产冰。产冰评价及校准保持原先统一的 60 秒窗口，避免将延长推演误记成生产增强。

`--net-economy` 为候选显式启用 `netEconomy` 评分版本：产冰与支出使用同一个正的冰价值，支出始终扣分，爆区损失只能作为非正的风险项；残存付费兵力按同一冰价折价计入，至多原价；击杀既有原来的战术价值，也计入兑现的冰收入。运行入口是 `ColdStorageSearch::AccountForIce`。训练不再变异独立支出槽位，局势层也不能翻转实际支出符号；仍由实战选择经济重要性、战斗价值和兵种偏好，不规定投资比例、等待门槛或阵容。旧配置缺少此标记时维持旧评分，主基线/参考基线不自动升级；本模式选优只在新评分候选之间进行，发布前再与原配置配对比较。

`--opponent-weight` 给候选引入可训练的 `opponentWeight`：比较“本案”和“不增援”在推演终点的玩家资产差，允许评价迫使对方消耗灰烬、破坏生产和压缩资源的价值。阳光按正式大额购冰汇率折算，现有植物按当前卡价及生命比例估值；买下仍存活的植物属于资产转移，不能算成白白花掉资源。预测同时扣除灰烬实际费用、计入付费僵尸死亡给玩家的返冰，并遵守 Board 提供的阳光/冰容量；免费技能和满仓溢出不产生虚假消耗。该值是有限预测，不能等同精确胜率或全部升级投资的清算价。`searchOpponent` / 对局决策中的 `opponent` 分开记录基线、终点资产、权重和评分贡献；缺省权重零维持旧评分，不能把它混入兵种偏好分。

`--calibration off` 跳过生产校准的采集/拟合，并移除候选继承的旧生产校准；基线保持原配置。这适合隔离校准误差，不能将“不使用校准”宣称为产冰预测已准确。

加 `--state-only` 只训练局势系数：基础评分、兵种偏好及继承的生产校准保持固定，变异按正负方向成对探索少量连接。此时参考策略只参加独立验收，不进入可变候选；数据收集仍可拟合校准，但不装入本轮候选。留出对照额外包含同样搜索能力的零局势层，区分搜索扩容和系数学得的收益，候选也必须通过这项对照。`--curriculum reserves` 混合正常开局与 `banked_varied` 战术片段，由记录的对局种子改变库存和逐路火力厚度；`cooling` 片段在开始前真实付费种下灰烬植物，使反制卡进入正常冷却。片段结束后仍按正式规则经营，不补钱或指定进攻编队。

`python autotest/audit_commander_forecasts.py <evaluation.json> --output <报告.json>` 可离线核对已冻结对照的逐次预测：分别列出所有窗口、没有后续购买的窗口和高库存窗口。击杀返冰从周期轨迹取样，允许最多 11 秒取证偏差；产冰按原先 60 秒及工人批次归属结算。报告排除截断的超时尾段，并明确后续增援/玩家补阵的干扰，不能当成单次行动的因果标签。需要隔离后续购买时使用下文单编队实测入口。

`python autotest/evaluate_commander_roster_ablation.py <联赛输出目录> --output <新目录> --exclude ZOMBIE_ELITE_DANCER` 对已冻结的全部对照策略，配对测试完整陆地池与仅移除该购买选项的池；场景、种子、玩家和其他参数一致。报告同时记录胜局是否实际购买该单位，不以“带了某单位”直接推断胜因。它衡量当前策略对卡池变化的依赖，不等于针对删减卡池重新训练后的能力，也不修改正式兵种数值或发布资源。

`--anticipate-building` 为候选启用可选的 `anticipateBuilding`：推演期间继续考虑玩家后续补阵。建设读取当前卡槽的真实价格、冷却、植物画像和合法格位，与灰烬共用阳光/冰预算；同卡多格共享冷却，新增曙光莲按正式充能周期及同时一株限制推演。第一版只计算新增植物的阻挡/火力，第二版也在玩家预测付费建设且植物随后被消灭时计入预期返冰；未建设或未消灭不产生该收益。所有预测都不增加真实余额，也不允许预支购买。仅从已入场的兵力判断补阵位置，不偷看尚未出生的队列。具体兵种、路线和攒兵决策仍由搜索与实战选优决定。

`--search-version 2` 只给候选启用完整编队采样，解除旧配置的小队上限，并扩大分批出兵及对应交战时域；不要求同时启用局势评分层。仍受正式预算、剩余名额和合法兵种/路线约束，比较同类、混编、集中、分散、连续或分批出生，也保留等待。参数上限集中在 `ColdStorageSearch.cpp`，`searchVersion` / `searchLargestPlan` 记录实际使用的版本和已评估的最大队伍，不能把“搜索过大队”当成“实际有效进攻”的证明。缺省版本 1 保持旧策略范围；旧权重不自动迁移到第二版。

对包含 `banked` 的旧混合验收课程，发布门槛额外检查高库存长局片段：没有真实取胜、消灭植物或消耗小推车进展的案例拒绝发布，无论它是一直攒冰超时，还是烧完库存后败北。`openings` 将这些片段单列为诊断，完整开局仍须满足三类卡池胜率和原有胜局保护；两类报告不可合并宣称全面通过。门槛不指定兵种、进攻路线或固定等待时限。

第二版补充尚持小鬼的巨人半血投掷与同格各层砸击。投手前摇被杀不会生成小鬼，脱手后不因投手死亡撤回；子单位不虚增购买资产或死亡返冰，但仍可引发灰烬反制。正式飞行时间与推演共用 `ImpThrowRules`，投掷前摇、落地动作、减速和视觉锚点修正仍为有限预测近似，不等于逐帧复刻真实动画；具体兵种价值仍须由正式对局检验。

第二版同时读取各行实际小推车的碰撞位置、速度和待机/行驶状态，先预测触发及扫过的地面单位，再计算进屋收益。已经扫过或尚未出生的部队不会被重复清除；屋脊指挥官的免疫及精英舞王消耗其他行小推车的能力分别表示，不把“付费为零”误当“不能触发”。

第二版的进屋特征至多计一次胜利，并结束这次推演；额外僵尸穿过已失守防线不重复增加胜利收益，胜利之后也不再虚构制冰和伤害。所有购买仍完整计入支出。旧版特征不隐式改变，迁移后的权重须重新进行实战比较。

此版本的玩家模型是有界近似：覆盖普通单格输出/阻挡/生产株、南瓜与曙光莲；尚不模拟紫卡前置建设、地面陷阱和累计配额株的后续种植、金盏花循环铲种或所有特殊技能。合法落点来自当前快照，不把当前非法格自动视作未来合法。`searchConstructionOptions` 和 `searchPredictedPlantings` 可核对预测是否接入；静态防线诊断可加 `audit_commander_forecast.py --static-defense`，只关闭后续陪练输入，结果标明 `playerActions=false`，禁止当成实战胜率。

这仍是有限推演与局势相关评分，尚非对未来玩家建造和未来再投资的完整多阶段模拟。`searchStateInputs`、`searchEffectiveWeights` 和 `searchAdaptive` 记录实际生效状态，训练逐次决策也保存它们。`smoke_commander_state_model.json` 使用明确的合成参数核对接口能表达等待与扩编，不将该测试当作训练成功或胜率证明；发布仍须通过独立真实对照。

搜索与旧战略层共用 `ColdStorageStrategy::MelonSplashContains/MelonSecondaryDps`：按碰撞箱与正式 60 像素命中窗口相交，先确定次要命中集合，再使用与正式弹丸一致的七倍直击总预算。群体减速不随伤害分摊而减少。这里只使用连续 DPS 近似，不宣称复刻逐发取整或弹丸飞行；没有修改玩家西瓜/冰瓜的真实伤害。

正式关卡仍保留各自出怪池和波次解锁。新流程混合全陆地兵种、按对局种子随机删减的兵种池、正式关卡卡池；同一配对案例的候选使用相同卡池。最终冻结候选后单独验证 10-1～10-9，以及未参与选优的全兵种和删减卡池对局。训练不会改正式卡池。`ColdStoragePolicy::Get` 的正式范围包含 10-1/10-2 和独立大乱斗小游戏，实验覆盖整个第十章；更新共享策略时也须核对小游戏的加载路径，不能把实验全兵种池当成各正式关卡的卡池。

`hunter` 是主动清理制冰工的植物陪练，沿用实际资金、卡牌冷却、合法格位和已提交灰烬判断；配合已有灰烬、发展、精英菇阵等对手，避免只在不针对经济单位的对手上评估护送。新注册且没有历史偏好的陆地单位先做实际付费出场探针；探针只证明获得探索机会，不代表已经理解其全部技能。

`builder` 在猎工基础上扩建中排经济，同时保留金盏花周转位置，补足旧陪练只维持少量向日葵、与真人后期发展差距较大的问题。仍走正式交易，不提高玩家初始资源或重置冷却；没有声称复刻真人操作。`--from-candidate` 可继承上一轮候选的权重与兵种偏好，旧分数不参加新一轮排名。

`lotus` 在扩建陪练中实际携带并充能使用曙光莲，通过 `player_activate_dawn_lotus` 走玩家操作门禁，不能直接改能量。全兵种时以曙光莲替换倭瓜，为对空卡保留正式卡槽。指挥官对场上曙光莲计入当前充能、每行威胁择敌、同行溅射和重复充能；普通前排不能假装拦住点名伤害。`searchRowStrikeCount` 记录本次纳入的来源，真人观测也保留曙光莲充能/可释放状态。未来主动种植和玩家选择延后释放仍属预测近似；现有制冰工推演在掉头阈值停产，不再把剩余本体生命全部当成生产时间。

兵种解锁依旧由正式付费波次推进。空场且能保留重组储备、下一次派兵能解锁可支付新兵种时，搜索允许用小额出兵提前推进，不必等满普通观望时限；`unlockProbe` 表示识别到这个机会。它不改变卡池、解锁波次或费用，也不在低库存时强行冲级。`smoke_commander_dawn.json` 验证实际点名与预测一致，以及仅需再出一波时不会永久卡在弱兵上。

生产校准使用小型本地回归树，不需要 API。输入是当前与计划工人、护卫、火力、控制、墙和资金等可见特征，只能折减简化推演的产冰预期，不改变实际结算。AutoTest 按时间与出兵批次记录真正到账的产冰；每次决策只使用当时已有和本次购买工人随后一分钟的收入，排除后来新工人的收益。后续护卫和玩家操作仍会影响实战，因此这些是观测回报，不能称为隔离干预后的精确收益。

拟合和误差验证按完整对局划分，截断的比赛尾部不充作零收益。只有独立对局上的预测误差改善才进入候选；是否更强仍看实战，不以拟合误差批准发布。留出门槛分别检查三种卡池，不允许全兵种提升掩盖正式卡池退步。新流程只生成候选，不自动替换正式资源；失败保留原策略。

生产校准按冰单位的平方误差拟合：比例误差相同时，大额预测偏差权重更高，避免大量微额产冰样本掩盖亏损的大批投资。倍率仍限制在原预测以内，验证继续报告实际冰单位 MAE 和偏差；后续玩家操作和护卫变化造成的观测限制不变。`python autotest/verify_commander_league.py <联赛目录>` 核对输入哈希、完整对局划分、正式胜负、收支、实际生效评分及静音状态；通过核验不代表通过胜率门槛。

输出的 `identity.json` 固定引擎、规则、源策略和程序哈希；省略 `--seed` 会生成并保存随机实验种子，相同目录可恢复，规则或程序改变须用新目录。`production_calibration.json` 保存模型、完整对局划分和误差，`new_unit_probes.json` 保存新单位出场证据，`checkpoint.json` 保存选优过程，`frozen_policy.json` 是留出前冻结的候选，`evaluation.json` 保存逐组胜负，`candidate_policy.json` 默认未发布。旧数据保留，但不能冒用旧引擎的分数。

从仓库根目录运行已编译的 `clang-release`。全兵种训练入口：

```powershell
python autotest/train_cold_storage_all.py --output build/clang-release/autotest/training/my_run --population 4 --generations 4 --seconds 180
python autotest/verify_commander_training.py build/clang-release/autotest/training/my_run
```

游戏窗口在桌面可见，训练默认全静音；启动器不传固定 `-Seed 42`，每局在开局前设置脚本记录的独立种子，同一配对案例的不同策略共用种子；普通 AutoTest 默认有音效、无背景音乐，不改玩家的游玩音量偏好。`batchStepsPerFrame` 只让非交互 AutoTest 在每次绘制间执行多个原始固定步，不改变技能或碰撞的单步时间；普通游戏和 `live.py` 不启用它。Codex 启动仍须从提升权限的 shell 执行。

## 学习与决策

程序进化全局局势权重和每个兵种的局势偏好；特征顺序见 `train_cold_storage_all.py` 的 `CONTEXT` 和生成策略中的 `contextFeatures`。友军伤势、密度、墙体、控制、火力、工人及后排保护用于区分能力发挥的场景。游戏内用有限位置推演搜索兵种、路线、出生间隔、队伍长度，也可以等待，没有预置“橄榄先行”或“巨人先行”模板。

候选推演包括前锋承伤、邻路西瓜溅射、减速、啃食、巨人砸击、制冰及连续清场反制。每张反制牌的落点共享该卡冷却，多张牌共同消耗玩家当前阳光、冰块及已在途冰块，付费僵尸的死亡返冰也会影响后续可用反制；倭瓜先索敌再在目标附近预测砸击。它不是完整游戏副本，特殊能力、伤害层和未来补阵仍有近似。**训练成绩来自正式引擎比赛**，特殊能力在那里真实执行；按兵种学习的偏好用于弥补近似预测的不足，不能称作已准确理解所有技能。

全兵种实验从实际注册表取得独立陆地单位，排除水路专用、仅召唤单位和视觉原型。每个陌生兵种先获得正常付费的出场探针，再由真实战果决定偏好。普通游戏不因此解锁兵种或跳过波次门槛。当前策略仅接入 10-1/10-2；其他地图的地形规则不受影响。

训练混合正式卡池与全兵种场景。保留总体冠军和各场景的优秀候选，并使用宽范围参数重启，避免只沿一个快攻解局做微调。最终先在正式卡池选择迁移策略，再冻结参数进入未参与选优的留出对照。

## 陪练与验收

植物陪练通过正式种植、买冰、收阳光、铲除接口操作，使用金盏花和模仿者金盏花。后排输出植物会补南瓜；全兵种陪练还带对空植物。没有对局中免费种植或重置冷却。

`train_cold_storage_all.py --curriculum counter` 继承已有兵种经验，在正式卡池续训“坚果拖延＋樱桃、辣椒、倭瓜连续反制”。`developing` 战术片段从橄榄刚解锁、坚果防线已存在的阶段开始，补足正常开局中不易稳定重复的决策窗口。逐场 `playerPlantings` 记录真正成功种下的植物，确认陪练确实使用了反制，而不是只带着卡。

反制课程先按真实获胜场数选优，再比较落败场数及有界评分，避免大量超时掩盖缺乏进攻；源策略、已发布策略和训练候选都参加迁移对照。`--generations 0` 跳过变异，用现有候选做当前引擎复测。空场有可支付行动时，搜索受 Board 的最长观望时间约束；低于重组储备且计划缺乏增量收益时允许暂缓，避免强制探路耗尽恢复资本。长期没有消灭植物且最近窗口制冰收入不超过出兵支出、低库存、活动与在途敌军清空的收尾判定由正式 Board 执行，训练和真人对局共用；补给不算经营回报，具体门槛以 `BoardColdStorage.cpp` 和 `ColdStorageState.h` 为准。

场景包含正常开局、成型阵地 `fortress` 和低库存、完整防线的 `economy`。后两者是预先设置双方资源与阵型的战术片段，不能冒充完整开局胜率。经营压力用于检验持久战，并不保证只有制冰工这一条解法。另做允许/禁止制冰工的对照，记录实际部署和产冰，不能把低库存直接认定为经营失败，也不能把存冰高当成胜利。

评价使用实际破阵和扣除外来补给的净资产变化，包含已经正常付费的存活/待出生单位；毛产冰不直接算成绩，经营塑形封顶，真实胜负优先。升级夹具先等实体清理再记录初始阵地，避免把升级前后两株重复计入火力。

冻结策略后可另测未见过的精英胆小菇阵：四株集中两路或分散四路，正常累计配额、后排南瓜和双发支援，不免费恢复精英配额。此报告不自动挑选或覆盖策略；若之后拿它训练，应换新布局/种子做下一轮验收。

```powershell
python autotest/evaluate_commander_formations.py --policy build/clang-release/autotest/training/my_run/candidate_policy.json --output build/clang-release/autotest/training/unseen_elite --seed 401000
python autotest/verify_commander_training.py build/clang-release/autotest/training/unseen_elite
```

加 `--opponent ash` 可测试纯灰烬＋坚果拖延：保留经济植物、坚果/南瓜和三种即时清场，不带持续输出植物；正常开局，无免费预建阵地。这套对手应留在训练结束后检验，不参与本轮参数选优。

全兵种训练器的发布门槛是：至少十二个配对留出场景，比旧 AI 多取得至少两次真实胜利，且不丢掉旧 AI 已获胜的场景。获胜来自 Board 的真实输赢状态；限时未结束记为 timeout。评分塑形有界，不能靠无限存冰压过真实胜负。门槛是有限样本工程检查，不代表对所有玩家更强。

`--publish` 只在通过门槛后写入 `build/clang-release/resources/ai/cold_storage_policy.json`。普通游戏读取有效且标记通过的资源，缺失或非法时回退旧 AI；资源每次进程首次使用时加载，替换后需重启游戏。正式发布资源应纳入 Git 和资源清单。

主人明确要求试玩未过门槛的候选时，先将当前资源原样备份到 `autotest/policy_backups/` 的独立时间戳目录并校验哈希，再替换运行资源，显式设置 `userRequestedTrial: true`。保留候选的 `validated: false` 与真实门槛结果；此开关只允许试用，不跳过参数结构、有限值或兵种名称校验，也不改变训练器的自动发布门槛。恢复时将备份的 `cold_storage_policy.json` 复制回原路径并重启游戏，原训练输出不覆盖。

旧的 `train_cold_storage.py` 保留为只训练全局权重的基础对照，使用独立的较严格评分门槛；正式全兵种流程使用上面的 `_all.py`。

## 数据与继续训练

输出目录包含：

- `identity.json`：引擎、训练程序、gamedata 哈希及实验设置。
- `catalog.json`、`probes.json`：可探索兵种、能力探针或继承来源。
- `checkpoint.json`：每代候选、逐场成绩、冠军及来源。
- `report.json`：冻结策略的留出对照、正式卡池结果及经营对照。
- `candidate_policy.json`：候选参数和验证状态。

游戏证据位于 `build/clang-release/autotest/out/<批次名>/`，包含逐场结果、轨迹、`run.log`、`status.json`。运行脚本同目录保存 stdout/stderr；未捕获 C++ 异常另记录错误内容及匹配 EXE/PDB 的栈地址。

改了引擎或陪练后继承已有经验，并使用新目录、新留出种子重新验证：

```powershell
python autotest/train_cold_storage_all.py --from-checkpoint build/clang-release/autotest/training/my_run/checkpoint.json --skip-probes --output build/clang-release/autotest/training/continued --heldout-seed 201000 --generations 4 --publish
```

`--skip-probes` 用于已经完成兵种探针的检查点。旧记录保留，但旧 EXE/陪练的成绩不能冒充当前验证。完全相同设置可复用已完成批次；改引擎、训练程序或实验设置必须换输出目录。训练不写玩家存档、不改游戏单位数值。每批有墙钟超时，只关闭本程序启动的游戏进程；已完成引擎批次若在 Python 后处理时中断，可用 `recover_commander_checkpoint.py` 验证并恢复。

## 决策校准与混合防守续训

`audit_commander_forecast.py <output>` 对正常付费的一批队伍运行其战斗预测时域，禁止后续增援；加 `--policy <候选> --arenas <场景...> --opponent <陪练>` 可检查冻结候选。第二版搜索交战窗口为 120 秒，第一版按局势模型是否启用使用 90/60 秒；产冰始终按前 60 秒的事件记录结算。它隔离了追加购买的干扰，但植物陪练会真实补阵，因此差距也包含推演尚未表达的后续补阵。`searchFeatures`、`searchBaselineFeatures` 和 `searchPreferenceScore` 分别解释计划、无增援基线和兵种经验加分；逐场 `decisions` 记录搜索编号、付款和预测，包含观望。这些诊断不进玩家存档。

`train_commander_robust.py --from-checkpoint <checkpoint> --output <output>` 使用自适应反制、原反制和发育陪练混合课程。自适应陪练优先救险、避免往已提交爆炸的范围重复交灰烬，并向已突破路线的后方补坚果；仍走正式费用、卡槽和冷却。每代共用一组新种子，兵种偏好的后续变异集中在课程的正式卡池；除逐兵种变异外，还按实际冰价在同一局势特征上做相关变异，让课程有机会学出随火力/墙体等变化的投入倾向。没有参与变异的兵种保留起点中的经验。先在迁移集选出方案，再冻结它跑独立留出集。

本入口的主基线是**当前发布参数**：至少十二个配对留出场景，比现版多赢至少两场，且不丢掉现版已赢的案例；同时不能低于旧规则 AI 的胜负排序。程序只写候选和证据，不自动覆盖正式资源。成绩不合格时保留数据，不能把候选选优、模型诊断通过或单个阵容全胜说成整体升级。
