# 工坊配电与修复补给

已落地的确认范围（2026-11-01）：

- 总站 → 配电箱 → 耗电机器，单层支路、单机唯一供电来源；跨格直连，交叉不相接。开局一个配电箱，后续25阳光。
- 耗电生产机取消 A 信号口，保留手动停机；冷凝机保留 B 配方口。物流、炮台和逻辑元件保留各自用途的端口。信号教学与控制在守住第2波后开放。
- 配电箱 A 为整支路许可，B 在普通/优先供电之间切换，未接线时手动操作。优先层先取电，同层按实际需求比例分配，普通层取剩余；不足时各支路产速为供电比的平方。待机15%，断电保留进度，物流继续搬运缓存。
- 维修包生产机第10波解锁：1残骸+10阳光→1维修包。维修包经原物流与装填口进入前线，占每路80份公共容量。冰仓坚果每次修复（手动/自动）同时扣1包和原100阳光，仍回血1000、冷却10秒。仅影响工坊。
- 首版维修机造价、功率、生产周期由实现与实测确定；参数集中在 Workshop 模型。旧档兼容不作前提，禁止自动覆盖真人旧档，提供明确的新基地入口。

实现入口：`Workshop.h/.cpp`（物料与事务）、`WorkshopPower.cpp`（配电）、`WorkshopScene*`（线路工具与解释）、`WorkshopPractice`（独立练习）、`IceStorageNut` / `BoardWorkshop`（原子修复付款）。

验收包括：断线/拆箱、两层公平分配、优先切换、无料待机、准备期冻结、暂停与原生战斗存读档、维修包生产/运输/消费/失败不扣资源、端口与接线真实鼠标操作、教程跟随解锁。

验证入口：CTest `workshop`，可见 `smoke_workshop_power_network` 与 `smoke_workshop_maintenance`，配套同名 Python verifier。供需压力测试仅验证多波调度收益，不代表原生战斗胜率；最终强度仍需真人连续经营测试。
