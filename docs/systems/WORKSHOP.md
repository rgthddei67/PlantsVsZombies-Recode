# 戴夫工坊

主菜单的独立经营模式。先搭建生产线，再主动开启袭击；胜利后保留整个基地，准备好才开启下一波。支持普通/寒冰两种弹药及独立工厂地图，不承诺图灵完备。

## 玩家操作

- 选择右侧机器，再点击空地建造；`R` 旋转待放机器，右键取消建造。查看工具选中现有机器后，旋转和配置按钮作用于该机器。
- 在建造按钮或已建机器上悬停可查看 tooltip：用途、输入输出、生产/输送速率、容量、当前库存与停机原因；暂停时也可阅读。
- 查看工具选中集光器、育豆机、冷凝机或弹药仓后，可在右下角花阳光升级；前线直接点击一株射手，在该行左侧升级。每个对象独立保存三级等级，守住第 2/5 波开放二/三级；升二级花原建造价，升三级再花原价两倍。tooltip 与选中面板显示当前和下一级收益、费用及解锁条件。
- 射手升级提高冷却、索敌与射击动画的速度，单颗伤害和每颗弹丸耗一颗弹药的规则不变。机器升级保留库存、布线与生产周期完成比例；射手升级保留生命、冷却进度与在播前摇。运输带、分流器、装填口和逻辑设备保持基础等级；仓库扩容不改变每行前线弹仓容量。
- 集光器提供全基地共享的阳光能源，育豆机生产实体豌豆，运输带沿箭头运输。装填口明确选择前线第 1–5 路与弹种，工厂格子的行不限制供货路线；射手有对应弹药且本行存在敌人时才发射。
- 分流器默认轮流向前方和右侧供货。A 接入信号后，高电平优先右侧，低电平优先前方；优先出口堵塞时可走另一出口。设置弹种筛选后，匹配类型只走右侧，其余只走前方；堵塞时等待，避免串料。弹药仓可设置收货弹种，切换时保留已有库存。装填口切换弹种后，只收取和装填匹配弹种；缓冲中的其他弹药保留，改回原类型或混合后继续运输。
- 接线先点击来源，再点击目标；A 控制生产/运输机器启停。与门、或门、记忆器支持 B 口。库存器读取 A 来源的实体库存，未接线时读取指定路线弹仓，两种方式均可选择普通、寒冰或总库存。敌情器也显式指定路线。定时器的 A 控制运行，未接线时持续运行；记忆器 A 置位、B 复位，复位优先。
- 暂停允许规划与建造。机器拆除返还建造和全部升级能源，仍受全基地储能上限约束，内部弹药丢弃。前线可付费增援射手、修复基地；界面说明每行同时部署上限与费用。射手被吃掉会失去该株升级，增援的新株从一级开始。
- 工厂和前线是同一基地的两个视图，切换不暂停模拟。工厂右侧显示五行库存与敌情摘要；开战自动切到完整草坪，角色使用原版 reanim 的正常尺寸，可随时返回工厂调整。
- 机器解锁来自本模式守住的波次，新基地为 10×10，扩建宽高各增加两格，分别封顶 20 格。没有冒险植物库导入，也不向冒险发放奖励。
- 前线复用正式 `Board`、`PeaShooter` / `SnowPeaShooter`、`Zombie` 和 `Bullet`：阴影、射击/啃食/受伤/死亡动作、音效、命中与断肢粒子都走冒险已有流程。后续波次逐步加入路障、报纸与铁桶，使用各自既有能力和耐久。被吃掉的射手需要增援补种。

- 守住第 3 波后，冷凝机将一颗普通豌豆与阳光加工成一颗寒冰弹；寒冰射手只吃寒冰弹，普通射手只吃普通弹。两种射手共用每行同时部署上限。寒冰命中沿用正式子弹的减速、粒子、动画和阴影。
- 每路前线共用总容量，普通/寒冰配额由右侧按钮调整。降低配额不销毁库存，达到对应配额后停止继续装填。
- 默认以清晰建造尺寸进入，缩到总览时省略机器上的细小数字；中键拖动、滚轮以鼠标为中心缩放，方向键平移；“适应地图”和加减按钮固定在工具栏。格线始终独立绘制，悬停与选中高亮跟随同一格位坐标。

## 独立存档与失败恢复

`GameInfoSaver::GetWorkshopSavePath()` 返回中央保存目录中的 `workshop.json`。文件拥有独立 `schemaVersion`，与 `PlayerInfo.json` 和关卡快照分离。修改、阶段切换、定期自动保存以及离开场景均经 `FileManager` 原子替换；不模拟离线生产。

存档保存基地、库存、生产/运输时钟、信号、前线、在途弹丸、敌人、波次与生成余量。开战前保存一份检查点；死亡状态也会保存，重进仍可选择：

- **继续经营**：恢复本次袭击开始前的基地，可重新规划后再挑战。该波开战后的施工与消耗一并回退。
- **重开基地**：经过确认，清空整个工坊的建设、资源、解锁和波次，从初始配置重新开始。
- **保存返回**：保留败局及检查点，稍后再选择。

工厂数据先在临时模型中验证，真实前线在新建 Board 中走正式关卡 schema 和对象恢复流程。坏档、未知版本、非法引用或恢复异常会停止整个场景并保护原文件，不继续运行或保存部分恢复的对象。开发期简化前线旧档保留基地；未完成袭击回到原开战检查点，再创建原生前线。

工厂 schema 2 使用固定 20 列存储跨度，保存独立宽高、两类库存、路由、过滤与配额。schema 1 的 5×12 数据同时迁移当前状态和死亡检查点，按原坐标重映射电线；旧厂买到的第 11/12 列保留。镜头位置只是当前视图状态，不写入经营档。

机器等级随工厂格保存，射手等级由原生 `Shooter::SaveExtraData/LoadExtraData` 保存。旧档缺少等级时按一级恢复；非法等级或尚未开放的等级会拒绝加载。死亡继续恢复开波时的等级与投入，该波中途的升级也随检查点一起回退。

## 实现与验证入口

- `PlantVsZombies/Game/Workshop/Workshop.h/.cpp`：Board 独占的工厂值对象；机器定义、费用、解锁、容量、生产与生成排期集中在此。它不模拟植物、僵尸或弹丸。
- `PlantVsZombies/Game/Board/BoardWorkshop.cpp`：真实战斗的接入、工坊出怪组成、清波、补种、基地越线伤害、前线与工厂的组合存档。普通 Board 没有工坊子域，既有冒险流程保持原样。
- `PlantVsZombies/Game/WorkshopScene.h/.cpp`：输入、原版素材复用、状态提示、保存与死亡选择。工厂使用独立相机，绘制、点击和信号线共用世界坐标与变换；自绘庭院只作背景，不赋予隐藏地形规则。原生战场维持原五行草坪，不新增 Board 背景枚举。
- `PlantVsZombies/Game/MainMenuScene.cpp`：原版按钮皮肤的独立入口。
- `tests/WorkshopTests.cpp` / CTest `workshop`：资源守恒、单拍运输、生成提交、电路与记忆、工厂存档恢复及坏档事务性拒绝；真实战斗由可见 AutoTest 验证。
- `autotest/scripts/smoke_workshop.json`：真实主菜单/建造/弹窗点击、前线战斗、解锁扩建、继续经营、取消重置与确认重置，以及同步截图。AutoTest 只访问当前脚本输出目录的 `workshop.json`，同进程可从菜单继续测试基地；新测试进程不读取上次遗留档。
- `python autotest/verify_workshop.py`：比较可见测试的存读档完整投影、失败恢复结果以及冒险关卡/植物解锁前后不变，核实截图产物存在。
- `smoke_workshop_upgrades.json` / `verify_workshop_upgrades.py`：实际升级按钮、单体等级与费用、旧档、缺钱/满级拒绝、退款、真实射速与耗弹、前摇中升级后恢复、被吃掉后重建及败局检查点。`workshop_snapshot` 只在 AutoTest 内使用脚本隔离文件构造边界，不暴露玩家改资源入口。

物流使用同一节拍的库存快照，每颗弹药每拍至多跨一格；所有目标先预留容量再提交。电路读取上一拍信号，反馈环不递归求值。射手前摇提交时预留一颗弹药，发弹继续使用既有动画事件；预留后的射手被杀会损失该颗弹药。工坊不新加动画帧事件，生产和信号按工厂节拍推进。工坊文档的 `battle` 与 `battleCheckpoint` 复用正式关卡序列化，恢复前摇和在途弹丸不会再次收费或重发。

新地图原图与生成提示见 `docs/art/workshop-garden-prompt.txt`。`smoke_workshop_cold_map.json` / `verify_workshop_cold_map.py` 验证四角与中心点击、鼠标锚定缩放、中键拖动、扩建、类型供弹、真实寒冰命中、阴影、前摇与混合库存恢复。
