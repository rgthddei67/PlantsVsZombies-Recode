# 戴夫工坊

主菜单的独立经营模式。先搭建生产线，再主动开启袭击；胜利后保留整个基地，准备好才开启下一波。当前首版使用普通豌豆供弹，不承诺图灵完备。

## 玩家操作

- 选择下方机器，再点击空地建造；`R` 旋转待放机器，右键取消建造。查看工具选中现有机器后，旋转和配置按钮作用于该机器。
- 在建造按钮或已建机器上悬停可查看 tooltip：用途、输入输出、生产/输送速率、容量、当前库存与停机原因；暂停时也可阅读。
- 集光器提供全基地共享的阳光能源，育豆机生产实体豌豆，运输带沿箭头运输。装填口供应所在行的前线弹仓；射手有弹药且本行存在敌人时才发射。
- 分流器默认轮流向前方和右侧供货。A 接入信号后，高电平优先右侧，低电平优先前方；优先出口堵塞时可走另一出口。
- 接线先点击来源，再点击目标；A 控制生产/运输机器启停。与门、或门、记忆器支持 B 口。库存器读取 A 来源的实体库存，未接线时读取本行弹仓。定时器的 A 控制运行，未接线时持续运行；记忆器 A 置位、B 复位，复位优先。
- 暂停允许规划与建造。拆除返还建造能源，内部弹药丢弃。前线可付费增援射手、修复基地；界面说明每行同时部署上限与费用。
- 工厂和前线是同一基地的两个视图，切换不暂停模拟。工厂右侧显示五行库存与敌情摘要；开战自动切到完整草坪，角色使用原版 reanim 的正常尺寸，可随时返回工厂调整。
- 机器解锁来自本模式守住的波次，扩建增加工厂列数。没有冒险植物库导入，也不向冒险发放奖励。
- 前线复用正式 `Board`、`PeaShooter`、`Zombie` 和 `Bullet`：阴影、射击/啃食/受伤/死亡动作、音效、命中与断肢粒子都走冒险已有流程。后续波次逐步加入路障、报纸与铁桶，使用各自既有能力和耐久。被吃掉的射手需要增援补种。

## 独立存档与失败恢复

`GameInfoSaver::GetWorkshopSavePath()` 返回中央保存目录中的 `workshop.json`。文件拥有独立 `schemaVersion`，与 `PlayerInfo.json` 和关卡快照分离。修改、阶段切换、定期自动保存以及离开场景均经 `FileManager` 原子替换；不模拟离线生产。

存档保存基地、库存、生产/运输时钟、信号、前线、在途弹丸、敌人、波次与生成余量。开战前保存一份检查点；死亡状态也会保存，重进仍可选择：

- **继续经营**：恢复本次袭击开始前的基地，可重新规划后再挑战。该波开战后的施工与消耗一并回退。
- **重开基地**：经过确认，清空整个工坊的建设、资源、解锁和波次，从初始配置重新开始。
- **保存返回**：保留败局及检查点，稍后再选择。

工厂数据先在临时模型中验证，真实前线在新建 Board 中走正式关卡 schema 和对象恢复流程。坏档、未知版本、非法引用或恢复异常会停止整个场景并保护原文件，不继续运行或保存部分恢复的对象。开发期简化前线旧档保留基地；未完成袭击回到原开战检查点，再创建原生前线。

## 实现与验证入口

- `PlantVsZombies/Game/Workshop/Workshop.h/.cpp`：Board 独占的工厂值对象；机器定义、费用、解锁、容量、生产与生成排期集中在此。它不模拟植物、僵尸或弹丸。
- `PlantVsZombies/Game/Board/BoardWorkshop.cpp`：真实战斗的接入、工坊出怪组成、清波、补种、基地越线伤害、前线与工厂的组合存档。普通 Board 没有工坊子域，既有冒险流程保持原样。
- `PlantVsZombies/Game/WorkshopScene.h/.cpp`：输入、原版素材复用、状态提示、保存与死亡选择。网格绘制、点击和信号线使用同一套几何常量；原版庭院仅作背景，不赋予隐藏地形规则。
- `PlantVsZombies/Game/MainMenuScene.cpp`：原版按钮皮肤的独立入口。
- `tests/WorkshopTests.cpp` / CTest `workshop`：资源守恒、单拍运输、生成提交、电路与记忆、工厂存档恢复及坏档事务性拒绝；真实战斗由可见 AutoTest 验证。
- `autotest/scripts/smoke_workshop.json`：真实主菜单/建造/弹窗点击、前线战斗、解锁扩建、继续经营、取消重置与确认重置，以及同步截图。AutoTest 只访问当前脚本输出目录的 `workshop.json`，同进程可从菜单继续测试基地；新测试进程不读取上次遗留档。
- `python autotest/verify_workshop.py`：比较可见测试的存读档完整投影、失败恢复结果以及冒险关卡/植物解锁前后不变，核实截图产物存在。

物流使用同一节拍的库存快照，每颗弹药每拍至多跨一格；所有目标先预留容量再提交。电路读取上一拍信号，反馈环不递归求值。射手前摇提交时预留一颗弹药，发弹继续使用既有动画事件；预留后的射手被杀会损失该颗弹药。工坊不新加动画帧事件，生产和信号按工厂节拍推进。工坊文档的 `battle` 与 `battleCheckpoint` 复用正式关卡序列化，恢复前摇和在途弹丸不会再次收费或重发。
