## 每种文档负责什么

| 位置 | 职责 | 不应放入的内容 |
|---|---|---|
| 根 README | 项目介绍和阅读入口 | 另一套详细构建命令、未经维护的进度清单 |
| AGENTS.md | 始终适用的工作规则与任务路由 | 单个功能的实现日志 |
| agent-guide | 当前构建、验证和公共工程契约 | 每次任务的过程记录 |
| systems | 面向阅读的系统职责、源码入口和使用说明导航 | 全量函数签名副本 |
| .agents/skills | SKILL.md 保留核心契约与任务路由，references 按机制保存条件细节 | 无条件加载的全品种清单、重复的公共规则与当前数值表 |
| agent-memory | 子系统历史决策、踩坑与带日期的验证记录 | 无需核实即可当作当前事实的承诺 |
| superpowers/specs、plans | 设计意图和实施安排 | 单凭存在或勾选就宣称已上线 |
| operations | 部署、备份与恢复步骤 | 游戏内部 API 说明 |

## 如何判断可信程度

- 当前规则读 AGENTS.md；具体工作还要遵循主人本次指令。
- 当前接口与行为以源码为准；当前测试结果以本次构建和测试证据为准。
- 项目指南和系统说明应随实现更新；发现冲突时先核对源码，再修文档。
- 带日期的方案、记忆和测试结论只说明当时的情况。设计状态的解释见[设计与计划阅读说明](superpowers/README.md)。

## 后续如何维护

1. 同一条完整说明只维护一处。其他文档给摘要和链接，不复制整段规则或命令。
2. 函数参数、返回值、单位和生命周期约束优先写在头文件 Doxygen；跨类调用顺序、所有权与使用示例写在系统说明中，并链接源码。
3. 改行为时同步修改对应说明；改历史结论时追加日期和替代入口，不把旧测试结果改写成今天通过。
4. 新文档必须接入本导航或所属目录索引；只有出现独立主题时才新建文件。
5. 文档交付检查相对链接、源码路径、旧入口及相关技能引用。纯文档整理不要求构建游戏。
