# 制作 PvZ 可玩地图背景

地图不是一张“看起来像草坪”的插画，而是美术、Cell 几何、场景语义和资源接入共同组成的可玩契约。AI 生成图只负责候选画面；当前源码中的 Board 坐标和最终实机截图才是几何事实。

遵循根目录 `AGENTS.md`，按任务范围读取项目指南和 [references/map-contract.md](references/map-contract.md) 的相关章节。当前几何、资源键和数值直接查源码；需要设计原因、历史例外或排查入口时再搜索记忆，不反复加载无关地图案例。

若需要生成或编辑位图，必须同时使用 `imagegen` 技能；地图内新增天气、粒子、植物、僵尸或复用 reanim 时，再叠加对应仓库技能。新增动画帧事件前仍须先询问主人。

## 先明确地图契约

在画图和改代码前，先明确：

1. **玩法几何**：平地、泳池还是屋顶；行列数、Cell 尺寸、是否有斜坡或水路。
2. **场景语义**：昼夜、天气、阳光生成、蘑菇睡眠、推车资格、右侧出生入口等是否改变。
3. **绘制变换**：背景贴图在运行时的起点、偏移、缩放，以及最终世界坐标中的可玩区边界。
4. **构图禁区**：左侧建筑、右侧入口、上方卡槽和下方字幕分别能占多少空间；哪些景物不得压住 Cell、推车或僵尸入口。
5. **资源闭环**：背景枚举、关卡映射、纹理键、选择页缩略图、AutoTest 状态与截图名称。

这些契约可在当前讨论及代码注释中明确，不要求每次另写文档；只有需跨任务接续或暂不实现的复杂设计才保存一份简短规格，按根目录 AGENTS.md 执行。不要让美术暗示未实现的机制。帐篷、观测站、洞穴或护栏默认只是景物；只有规格明确时才赋予碰撞、出生或防御行为。

## 选择参考图

- **先按几何选底图，再按主题借风格。** 目标是正视平地时，应从现有正视平地地图继承透视和空间关系；即使主题来自雪原，也不要从带倾斜或收束透视的雪地图继承草坪几何。
- 可以把另一张地图的积雪、夜色、灯光、材质和远景迁移到正确的几何底图上。主题相似不等于结构相容。
- 若参考图本身偏斜，单说“改成雪地”通常会保留错误透视。提示词必须把可玩区写成“正面、轴对齐、无旋转、无梯形收束、行列边界平行”。
- 左侧建筑要在可玩区之外预留完整体量。不要为了避开草坪而把房子、帐篷或观测站压扁；尤其检查高度、底边是否闭合、入口是否被画布裁切。

## 用 ImageGen 做美术，用代码做校准

1. 先生成整体构图，只锁定大关系：可玩区、左侧景物、右侧开放入口、远景和光源。
2. 构图接近后，用局部编辑修正建筑高度、底边、遮挡和草坪外轮廓；不要每次从头重生整图，避免已经正确的风格与布局漂移。
3. 明确要求画面中不要出现 UI、Cell 网格线、测试标记或玩法特效。调试覆盖层只能临时生成，不能烘进正式背景。
4. 代码或图像工具适合做确定性的裁切、蒙版、局部形变、尺寸和像素校准；不适合替代手绘地图的主体质感。
5. AI 图即使肉眼“很方”，也必须进入 Cell 对齐流程。不要把生成结果当成完成品。

## 按真实 Cell 校准

- 从当前 `Board::InitializeCell()`、`Board::GetCellCenterPosition()`、相关常量及屋顶行高函数推导实际 Cell 中心和边界，不要从旧截图或源图片目测。
- 把 `GameScene` 绘制背景时的 `mStartX`、`mBackgroundY` 等运行时偏移计入换算。需要对齐的是**最终画到世界中的像素**，不是 PNG 内部坐标。
- 用临时网格覆盖层，或在四角、中心与行列交界放置测试植物/标记，检查纹理接缝与逻辑 Cell 是否一致。调试层在验收后移除或保持仅测试可见。
- 若画面只有局部非线性漂移，可分段裁切或局部形变校正；保护左侧景物和远景，不要把整张图粗暴缩放到格子上。
- 草坪存在倾斜、梯形收束或跨列累计漂移时，应退回正确几何底图重新改绘。不要移动 Board 的 Cell 去迎合美术。
- 逻辑网格和视觉偏移始终分离。景物纹理可以有自然起伏，但植物锚点、行列边界和可点击区域不能随之漂移。

## 接入代码与资源

按当前源码核实并闭合以下路径：

1. `Background` 枚举和关卡/模式到背景的唯一映射。
2. `GameScene` 的背景纹理选择与绘制层。
3. 选择页或生存模式需要的缩略图和背景映射。
4. `resources.xml`、`ResourceKeys.h` 与实际纹理键。
5. AutoTest 的背景名、强制背景入口、纹理加载断言、Cell 状态投影和截图。

资源文件只写入 `build/clang-release/resources` 权威目录；其他 preset 通过目录联接共享。被 Git 忽略的新资源在审阅后用 `git add -f` 纳入。`manifest.txt` 中存在文件不代表加载成功，必须用 `GetTexture(key, false)` 或相应强校验确认。

地图的昼夜、行数、泳池、屋顶、蘑菇睡眠、阳光、推车与环境机制资格必须由显式代码契约决定，不能根据背景颜色或贴图内容猜测。若景物会遮住某种实体，应同步收敛其创建、恢复和绘制资格；只把实体藏在背景后面会留下碰撞和触发。

## 图层与遮挡

- 静态地图放在 `LAYER_BACKGROUND`；只作用于背景的天气变体或调色放在背景与战场实体之间。
- 世界天气覆盖层、战场对象和 UI 必须分层；全屏雪幕或暗幕不能污染卡槽、观测仪等 UI。
- 左侧景物不得遮住仍然存在的推车，右侧远景不得伪装成不可通行边界。
- 可玩区边缘可以有积雪和自然纹理，但不应制造错误的行列界线或让玩家误判落点。

## 可见验收

若只改技能文档无需构建；实际地图接入默认使用 `clang-release`：

1. 从 `build/clang-release/` 在主人当前桌面可见运行范围最小的地图 AutoTest。
2. 断言背景枚举、行列数、Cell 尺寸/中心、纹理键和必要的地图资格。
3. 在四角、中心及边缘 Cell 放置对象，截取完整 1100×600 场景；同时检查左侧建筑底部、右侧入口、推车、卡槽和字幕区域。
4. 查看原始尺寸截图，不以缩略图判断对齐。检查行列接缝、累计漂移、建筑是否压扁、底边是否漏出、夜景轮廓是否清楚。
5. 同时检查退出码、`run.log`、状态文件和截图。未改渲染后端时，不机械增加 Vulkan、`-NoInstance`、OpenGL 三路径矩阵。
6. 只有入口、设计原因、特殊例外或可复用经验变化时更新相关说明；已实现几何和数值以源码为准，不重复维护设计、主题记忆和索引中的参数副本。

## 常见失败模式

- **从主题最像的地图直接改**：继承了错误透视。改为从几何正确的地图起步，再迁移主题。
- **提示“草坪正方形”但没有结构约束**：AI 仍会做轻微梯形或斜边。明确正视、轴对齐、无收束，并在实机数值校准。
- **肉眼觉得差不多就交付**：列间误差会累计，植物越靠右越偏。用真实 Cell 中心和全场截图验收。
- **为避让草坪缩小左侧建筑**：建筑高度不足、底部没包住。先扩大其场外构图空间，再局部修正。
- **用代码生成整张手绘背景**：几何稳定但质感僵硬。让生成模型负责主体美术，代码负责测量、蒙版和确定性校准。
- **改 Cell 去配图**：破坏碰撞、植物锚点和既有机制。地图美术服从玩法几何。
- **资源文件存在但取不到键**：补齐 loader/`resources.xml`/键注册，并加运行时加载断言。
- **景物隐藏实体但未禁用实体**：会留下不可见碰撞、攻击或读档复活。资格必须覆盖创建、显式生成与恢复。


## 矿场前景与工具验收

`Scene` 的 `GameObjects` 命令一次绘制全部 GOM 对象，包含选卡面板；把岩壁另注册为较高 Scene 命令会压住面板，数值层级不能插入 GOM 内部。幽晶矿场岩壁在 `GameScene::DrawWorldOverlay` 的现有 pre-overlay 阶段绘制，位于战场之后、UI 对象之前。选卡截图先断言 `chooseCardReady=true`，只等 `CHOOSE_CARD` 会截到滑入前。工具贴图用 `LogicalToWorld`，传给 `GameAPP::DrawText` 的锚点也必须是世界坐标；必须检查镜头平移阶段。
