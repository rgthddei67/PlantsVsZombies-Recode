## 当前源码搜索锚点

| 目的 | 优先搜索 |
|---|---|
| 背景类型 | `enum class Background`、`Background::` |
| 关卡映射 | `GameAPP::GetBackgroundID` 或当前同义入口 |
| 背景绘制 | `GameScene::BuildDrawCommands`、`LAYER_BACKGROUND`、`mStartX`、`mBackgroundY` |
| 平地 Cell | `Board::InitializeCell`、`Board::GetCellCenterPosition`、`CELL_INITALIZE_POS_X/Y`、`CELL_COLLIDER_SIZE_X/Y` |
| 屋顶坐标 | `GetRowCenterYAtX`、屋顶坡度或行高相关查询 |
| 资源注册 | `build/clang-release/resources/resources.xml`、`PlantVsZombies/ResourceKeys.h` |
| 选择页展示 | `GameSelectScene` 内背景/缩略图映射 |
| 测试入口 | `TestDriver.cpp` 内 background 名称、override、resource 与 cell 字段 |

使用 `rg` 搜索当前实现，不依赖文件名永远不变。新增资源后验证“实体文件 → 注册 → 资源键 → 运行时强加载断言”整条链。

## 极夜雪原案例中学到的数值换算

当时的极夜雪原最终采用正视平地几何，运行时 Cell 世界边界为 `x=242..962`、`y=88..588`，9 列每列 80 px、5 行每行 100 px。这个数值只用于说明方法：

1. 先从 Board 当前函数得出世界边界。
2. 再减去背景绘制起点，换算为 PNG 内目标边界。
3. 用实机全场截图和测试对象验证换算。

后续地图不得直接复制这些坐标；相机、背景偏移、地形或 Cell 常量变化时必须重新推导。

极夜雪原最初借用了“雪原”主题参考，但真正解决对齐的是改用第一大关的正视平地构图作为几何基础，再迁移积雪、极夜与暖色帐篷。左下建筑还暴露了另一条经验：避免越界不能靠把建筑压扁，应给场外景物足够的高度和完整底边。

## 最小截图矩阵

一次普通地图改动至少覆盖：

- 无植物的完整背景：看构图、边界和遮挡。
- 四角与中心 Cell 放置对象：看锚点和累计漂移。
- 左侧防线区域：看建筑、推车和第一列。
- 右侧出生区域：看最后一列与僵尸入口。
- 地图专属环境开启态：只在确有环境层时检查背景、世界层与 UI 分层。

截图必须保留完整 1100×600 画面，并以原始尺寸检查。动态对象绝对坐标不适合作为长期稳定断言时，导出同一状态下的 Cell 中心、边界跨度或相对投影。


## 幽晶矿场接入

- `BoardMine.cpp` / `MineGrid`：5×9，沿用平地 Cell；背景1880×720，图片可玩区 `[492,138]..[1212,638]`，绘制偏移(-250,-50)，对应世界 `[242,88]..[962,588]`。
- 岩壁属于逻辑地形，位图仅负责表现；开凿提交后重建距离，循环穷举在 `MineGridTests` 独立目标中执行，不能放入游戏更新。
- 分组布局由 `MineGrid::Initialize(layoutGroup)` 初始化，9-1/9-2 为19块岩壁与第1/3行入口，9-3/9-4 为20块与第0/4行入口。入口、普通/魅惑距离、生成行资格和画面使用同一组地形；读档保留保存的开凿结果，换关重置为该关初始组。定时雾的背景覆盖应延伸到画面边缘，不能复用最右格边界剪掉洞口后的雾。
- 攻击预览按格中心投影，不能把预览色块当作真实碰撞范围。新增植物需核对 `CoversMinePreview` 与原攻击方向/射程。
- 冒烟：`smoke_gloomcrystal_mine`、`smoke_mine_movement`、`smoke_mine_combat`；覆盖 UI / 存档、转弯 / 魅惑、攻击阻挡。
