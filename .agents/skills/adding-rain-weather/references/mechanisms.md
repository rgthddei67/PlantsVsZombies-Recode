# 天气机制专项约束

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

## 不可破坏的契约

- `Board` 不得直接包含或访问具体 `GameScene`，也不得恢复 `mGameScene`。天气玩法状态继续由 `Board` 唯一持有；新增天气 UI 请求应扩展非拥有的 `BoardPresentation`，由 `GameScene` 实现。双方共享的天气枚举放在 `WeatherTypes.h`。
- 新天气维度不得硬塞进 `RainIntensity`。例如夜间泳池雾势使用独立 `FogWeatherIntensity`、阶段计时和预报；它可以在唯一交互点消费现有 `TyphoonStrength/WindDirection` 计算驱散与漂移，但雨势和雾势仍可独立抽取、持久化和测试。
- 温度等并行环境维度若只改变降水表现，不得复制或改写 `RainIntensity`：雨势仍决定玩法倍率和阶段时长，统一的派生查询再选择雨/雪特效与文案。跨过表现阈值时先停旧特效再按当前雨势重建；雪天是否关闭雨声、地面水花和普通闪电必须逐项显式约定。地图禁用台风时，资格查询要同时覆盖 pending 预抽、开始、更新、恢复、测试入口和概率导出，不能只把抽取权重设为零后留下旧档活动台风。
- 并行环境维度若有持续影响玩法的上下限或触发阈值，常驻仪表应独立于会滑入/隐藏的天气预报面板；刻度、液柱比例和测试投影统一读取 `Board` 的阈值 getter，贴图只负责风格化框体，不能在 UI 复制温区常量。
- 地图美术若实体遮挡某些防线装置或行资格，必须把规则收敛到 `Board` 的创建资格，并让普通初始化、显式创建与旧档按 ID 恢复共用；只隐藏绘制会留下碰撞、触发和读档复活。专项断言实际实体数、行集合与快照往返。
- 场景特殊机制的资格默认按 `Background` 判断；关卡号只用于教学解锁、关内曲线或明确的固定关卡事件。当前通用雨势是显式例外：冒险一大关关闭、2-1 起开启，所有由 `SURVIVAL_ENDLESS_DEFINITIONS` 登记的无尽地形均开启。台风资格再统一叠加玩家的全局台风开关与地图环境门禁；无尽模式不再因模式本身禁用台风，雪原无尽仍因 `WINTER_GARDEN` 背景拒绝。生存选关用 `AdventureProgression::HasCompletedArea()` 判断对应大关是否全部通关，未解锁入口不创建。禁止在 `SupportsWeather()`、`SupportsTyphoon()`、选关页与背景映射处维护平行关卡号名单。若固定关卡复用完整迷雾，用 `AdventureProgression::HasLevelSpecificFogMechanics()` 集中登记，并让基础雾、独立雾势、路灯花燃料/照明/索敌和雾火掉落共用同一门禁；当前仅 6-9。
- 地图专属积累器不属于雨势档位：由 `Board` 按地形门禁和当前雨势推进，满值时只锁定一次目标行/路线；可用正式 RNG、确定性规则或动作边沿蒙特卡洛选择，但积累、阶段、倒计时和锁定结果都要入档，绘制不得重 roll。冲刷后若随机保留部分积累，应在锁定事件时预抽并保存 pending 值，结束只兑现，避免活动阶段读档改写下一轮起点。满值后的正向输入若设计为下一轮余量，同一笔跨阈值增量的溢出和整个活动阶段新增量都进入独立、有上限且入档的 pending；它不得暗中强化已经公开的本次效果，结束时一次兑现并清空。若实体能引导锁行，Board 在锁定瞬间通过语义虚查询收集候选；简单规则可选唯一替换者，智能规则可把普通路线与全部实体路线统一推演，但不得扩大一次事件数量。最终行、路线和必要的稳定实体 ID 是唯一事实，候选死亡、换行、破甲或后来出生不得重抽；实体失效只跳过依赖实时资格的自身奖励。实体独享的冲刷倍率应挂在实体虚入口上乘 Board 基础速度，禁止升级成整行光环。昼夜共用同一斜坡时默认共用径流，未来夜间电荷等系统以独立状态叠加，不能因新增机制撤掉地形固有效果。多行目标优先保存 bitmask，并让 UI、世界特效、植物/僵尸结算和 AutoTest 共用同一查询接口。
- 实体存在本身若要持续加快地图积累器，增量仍由 `Board` 在唯一积累函数合成：离散雨档先给基础速率，再叠加集中调参的固定实体增量；明确多只是否叠加及晴天是否生效。资格通过该稀有品种的 `ID → weak_ptr` 专用索引查询，热路径在首个有效候选处返回，不得每帧扫描全体实体。完全由当前天气与有效实体派生的增量不入档；实体的一次性锁定增益仍由实体保存幂等标志。AutoTest 用两只同类证明不叠加、晴天证明增量归零，并以锁定快照往返证明不重复施加实体增益。
- 积累器的一次性放电效果只接在 `WARNING -> DISCHARGING` 等唯一阶段边沿：先复制稳定实体 ID，再按当帧连续环境状态分区，最后调用植物/僵尸通用状态接口。若实体奖励是一次性范围状态，在同一边沿按碰撞箱中心、平方距离、阵营和活动资格冻结受益者；效果发放后由各实体计时，离域或来源失效不得取消。实体生命与状态余时自行入档；恢复已经处于 `DISCHARGING` 的 Board 只恢复演出阶段，绝不重新结算。连续径流等区域场保留 Board 查询，不能伪装成任意固定秒数；实体的离散停机与连续区域源应由统一有效查询合并。
- 一次性放电若允许实体替其他目标承接，Board 仍以同一份排序 ID 快照同时枚举目标与提供者，通过基类语义虚接口查询资格并按距离、稳定 ID 选唯一提供者；目标和提供者的阵营、行、地面资格由实体复核。承接成功后立即跳过目标原伤害/控制，失败才走目标自己的放电入口。禁止在 Board `dynamic_cast` 特定品种、边遍历边增删快照或为每个目标重复随机；专项覆盖自身承接、邻近、并列、距离外、异阵营、提供者中途破甲和双方快照往返。
- 一次性放电若允许植物为多个植物层提供保护并让提供者承受反噬，必须按“冻结全部植物目标→按距离/稳定 ID 选择提供者→让其他受该区域影响的实体消费同一批接地范围→按提供者 ID 归并一次反噬”分阶段结算；禁止分配一个目标就立即扣提供者，也禁止在僵尸等后续目标消费范围前让提供者死亡，否则同次事件会顺序依赖。免除本次离散停机只跳过 `ApplyShutdown`，不得清除或绕过连续径流等区域源的有效暂停。若同一植物范围还压制僵尸承接/过载，植物只声明空间语义，Board 聚合查询，僵尸能力入口分别在承接与直接受击的过载分支消费，不能顺带取消该僵尸的其他抗性或伤甲规则。
- 承载层提供的同格保护只在放电/处决等唯一结算边沿通过 Cell 分层入口 O(1) 查询，不得把“当前受保护”做成逐帧遍历缓存。同行光环若只影响已锁定事件，就在该行固定列上扫描一次，按规格取最大值或求和；非叠加能力取最大值，空承载提供者返回中性值。保护与倍率都由当前植物层组合派生，不另存 active 标志；专项至少覆盖空提供者、多提供者、存读档与提供者被正常外伤摧毁后的即时失效。
- “站在活动区域即持续生效，离开后残留 N 秒”必须把连续区域查询和实体残留计时分开：区域内每帧刷新残留并压掉互斥状态，区域外才递减；只保存残留计时，不复制 Board 行掩码/阶段。放电结算要同时传入当帧是否位于活动坡段，避免把仍湿润但已离坡的目标误按湿坡固定伤害处理。
- 逐格雾 alpha 是由雾势、驱散和路灯花派生的瞬态，不入存档；读档必须等实体恢复完成后直接同步终态，禁止从全透明重新平滑生成而给退出重进留下窥屏窗口。
- `GetRainIntensity()` 是目标档位，切档时立即改变；玩法倍率、暗幕和雨声音量再用两游戏秒平滑到目标。离散触发默认以目标档位为准。
- 关卡/波次派生的固定复合天气要把“是否生效”和“是否已初始化”分开：生效条件可由关卡与波次重算，一次性阵风额度、闪光节奏等未来状态必须保存。读档和每帧强制修复不得返还已消费额度；若设计要求天气随波次骤然降临，应显式完成普通两秒过渡。
- 全屏天气覆盖层只能压世界层。`Scene` 中 `isUI=true` 的贴图由 pre-overlay 接缝在 `DrawWorldOverlay()` 后、UI GameObject 前绘制；卡槽底板等 UI 不得继续混在世界贴图批次，也不要给黑幕写死矩形挖洞。
- 地图专属天气调色若只应改变静态背景，必须注册在 `LAYER_BACKGROUND` 与战场实体之间并消费平滑后的天气 getter；禁止塞进全世界覆盖层而重复染色实体。若用全尺寸变体贴图交叉淡化，必须由原背景按蒙版合成，保证尺寸、网格与非天气区域像素对齐，并补齐“文件/清单 → loader 注册 → 资源键 → AutoTest 加载断言”。昼夜屋顶雨景分别对应 `ROOF` 与 `NIGHT_ROOF`；晴天/晴夜 alpha 恒为 0，下雨时才淡入各自变体，不得用白天灰云直接覆盖夜色。
- 不要修改全局 `DeltaTime`，也不要整体加速 `Zombie::Update()`；只缩放明确属于该能力的计时或结算值。
- 僵尸动画速度统一经 `Zombie::UpdateAnimSpeed()` 收敛：`GetAbilityAnimSpeedMultiplier() × slowFactor × rain`，冻结优先为 0。子类自身整体倍率只覆写该虚函数，状态变化后调用 `UpdateAnimSpeed()`；禁止用 `SetExtraSpeedMultiplier` 绕开它。
- 场地效果若宣称“逐因子强化加速与减速”，对能力、寒冰、雨势和台风等每个非中性倍率分别变换后再相乘；当前鎏金冰道的主人定案为每层让加速倍率乘二（`1.4→2.8`）、减速倍率除二（`0.6→0.3`），中性 `1.0` 不变。手动改 X 的车辆也必须消费同一结果，不能只放大动画。允许重叠时按独立活跃来源逐层变换，并在进入、离开、来源死亡或范围变化时刷新。
- 雨天出生变异不要塞进通用 `CreateZombie()`：该入口也被 AutoTest 显式生成和其他玩法调用。默认在 `TrySummonZombie()` 中对 `selected` 解析为实际类型；`CreateZombieWithID()` 永不重新变异。
- 若图鉴或成就依赖“实际刷出”的概率变异，记录点必须位于正式实际类型成功创建之后，不能放在解析器命中时：超额候选、地形拒绝或创建失败都不算遭遇。永久账号进度存 `PlayerInfo.json`，不要混入 Board 关卡存档；AutoTest 只断言内存标记并源码审查磁盘契约。
- 不要按天气改写持久的 `mSpawnZombieList`。生存模式会保存该列表，预览僵尸也使用它；天气变异应是波次生成时的一次性解析。
- 随机变异只 roll 一次，并把实际类型或结果标志保存。禁止在 `Update()`、绘制、读档或每次技能检查中重 roll。
- 有准确预报的随机环境事件要在预报出现前一次性锁定强度、目标值、各阶段时长和稳定视觉变体；玩法推进、UI、存档和绘制只消费这份 Board 结果。强度可以决定抽样区间，但格子资格等连续效果仍应读取当前实际环境值，不能直接按强度枚举硬编码范围。
- 有时限的整栏天气干扰属于 `Board` 持有的公开可见性窗口，不是删除计划：提交时新增或延长按游戏时间推进、可保存的窗口，暂停冻结且受倍速缩放；雨雪及待生效台风警报、寒潮、雾势分别保留锁定实况与计时，并在窗口内截获后来公开的每一代预报。窗口期间栏目只显示统一故障文案，当前雨雪/台风/寒潮/雾势及其他栏内实况也隐藏；地图上独立于栏目的持续玩法仪表可保留。提交结果要能区分“窗口已补时但当帧无预报”和真正失败。同类来源是否叠加必须明确；当前气象干扰僵尸每次成功提交向剩余窗口追加 30 游戏秒，并在 Board 集中设置 300 游戏秒的当前余时上限，达到上限的来源等待有余量后再施法。该上限不是每波或整局累计次数上限。被干扰的公开大雨不再触发预警弹窗或揭晓失败卡，已经显示的专用大雨/暴雪中央预警、当前天气牌和失败卡也立即撤下，但不得清掉大波、突击令等其他并存提示；正式切档仍消费原 pending 台风。各 disrupted 标志跟对应预报生命周期清零并入关卡档，窗口结束不提前公开尚未揭晓的已截获预报，寒潮继续复用通知依赖植物的既有干扰入口。
- 若改动真实天气转移，必须同步 `BuildPlausibleForecasts()`；公开错误预报只能来自真实可达候选，无候选时强制报准。
- 天气预报揭晓的失败判定要比较玩家实际看到的完整组合：雨势或公开台风等级任一与揭晓实况不同都算失败。大雨同档续期不会消费新抽的 pending 台风，因此实际等级必须取揭晓时正在生效的 Board 台风；失败卡片及其 UI 存档同时保留两边的雨势和台风等级。
- 玩家可选的“会出现台风天气”与开局台风保护都属于 `PlayerInfo` 全局偏好，缺字段必须回到各自产品默认值；台风总开关默认开启并优先于地图、波次和概率，关闭时 `SupportsTyphoon()` 必须统一清理或拒绝 pending、active、概率和测试强制入口。控制台只在总开关开启时显示开局保护项，隐藏时保留其已保存选择。两项说明要明确区分“整局是否允许台风”与“仅开局波次保护”，整行选项都可触发随鼠标移动的 Tooltip；鼠标移出选项或保护项被条件隐藏时说明立即消失。开局保护的实际资格仍由 `Board` 按当前波次派生：普通冒险保护第 1～5 波，无尽只保护第一轮的第 1～5 波。预警期已锁定的“保护性无台风”要以独立标志随关卡档保存，消费时不得累计台风落空保底，否则保护结束波会被反向推成近似必出。
- 实体直接强制雨势不得绕过 Board 私有状态写字段。默认只允许升档，避免中雨命令把自然大雨降级；周期技能默认不续同档以防永久锁雨，一次性阶段技能若允许补足同档余时必须显式传参。是否抽取/保留台风也必须由入口规定，不能意外消费预报期已锁定的台风随机结果。若复用现有 `BeginRain` 已完整保存的状态，不再给实体复制雨势字段或提升 schema。
- 新增可调权重、概率、持续时间和倍率时，集中放在 `Game/Board/` 下对应 `Board*.cpp` 的匿名命名空间，并在声明行末写中文用途/单位注释；基础雨势、预报、台风与暴风雨夜集中在 `BoardWeather.cpp`，独立雾势、逐格 alpha 与路灯花照明形状集中在 `BoardFogWeather.cpp`，屋顶径流/雷荷集中在 `BoardRoofWeather.cpp`，冬日寒潮集中在 `BoardWinterClimate.cpp`，极夜环境导演与雪穴状态集中在 `BoardPolarNight.cpp`。
- 天气维度内的消耗资源不一定服从天气导演：若目标是“关内前宽后紧”，用当前波/总波数建立独立归一化曲线，禁止因后期天气压力升高而反向增加补给。正式出生时先预分配并按波封顶，灰烬群杀只释放既有奖励；AutoTest 至少用两种总波数锁定首尾端点。
- 雾中索敌若允许“可见边界外第一格薄雾”，必须继续消费平滑后的逐格 alpha：目标格不合格时，从目标朝植物检查相邻格是否已可见。禁止按固定雾线列号或路灯花挡位形状另写判定；测试要证明第一格目标本身仍是高 alpha 但可索敌、第二格不可索敌，并覆盖路灯照明边缘。
- 植物等外部能力主动改台风方向时，经 `Board` 的单一接口同时改持续 `mWindDirection` 和仍在进行的 `mActiveGustDirection`，并重置完整方向阶段、刷新方向相关视觉；不得借机重置台风强度、阵风预算/时长、已完成的植物换格或迷雾驱散。专项要在活动阵风尚未结算植物时触发，并同时断言两套方向权威。
- 植物阵风位移继续由 `Board` 的唯一逐格结算点负责；抗风植物用虚接口声明“锚定格位”和直接撞击反馈，禁止按 `PlantType` 写死分支。源格含锚定植物时整个 Cell 的全部活跃植物层组合不动；搬运、出界和弹坑死亡也必须遍历全部层，不能只写死 `under/normal`。只有来袭格直接进入锚定目标格才结算，普通占格形成的后方链不传压。伤害逐格立即生效以允许中途死亡后放行剩余步数，同阵风音画可按锚定植物合并；这类纯派生能力不新增存档字段，但要导出直接阻挡格次供测试。
- 跨多个 Cell 的植物仍是一个实体 ID；阵风只在逻辑锚点结算一次，把完整 footprint 连同各格独立 `under`/附件作为原子事务先清源格、再写目标格，扫描到次级别名必须跳过。雷荷或其他承载层保护若允许单侧保护整株，Board 在结算边沿扫描目标 footprint，支撑物再验证自身格仍引用该目标；不得继续用目标锚点与支撑物列号相等作为“同格”条件。
- Board 所有、随植物格附着的共享对象（如已放置扶梯）必须并入同一个逐格事务：成功搬运时与 Cell 同帧切换逻辑格，绘制消费宿主植物同一份二维追赶偏移；阻挡时留在源格，出界或弹坑死亡继续走既有植物生命周期移除。专项同时断言附件格坐标、滑动中宿主偏移误差为零和最终归零，不能只在落点截图后确认。
- 非水平地图的植物阵风动画必须在源/目标格中心之间插值完整二维视觉锚点，不能只平移 X；本体、影子和测试导出的视觉位置都消费同一锚点，逻辑格仍只在结算点切换。雨滴地面飞溅也必须先按当前 X 查询所属行的连续地面带再取样，禁止用整行固定 Y 范围，否则屋顶坡段会浮空或穿瓦。
- 僵尸阵风漂移必须在冻结/啃食早退前移动真实 Transform，并在同帧重新验证当前啃食目标。禁止只依赖 `onTriggerExit`：跳跃受阻后手动开始的啃食可能从未建立碰撞对；吹离、目标死亡或僵尸转入死亡轨道都必须清目标 ID、平衡 `mEaterCount` 并退出攻击。
- 植物若只在当前冻土等真实格况中获得防御资格，资格直接从 Board 与自身活动态/生命查询派生。一次性版本只保存是否已经消费；存活期间可重复的版本不保存次数字段，解冻时暂停、再冻结后恢复。威胁通过植物基类语义响应取得拦截、散射或后续伤害上限，并保留伤害、动作与音画所有权，禁止按植物类型分支。多个响应是相乘还是取最强上限必须显式约定；上限用 `min(current, cap)`。专项覆盖连续请求、致死边沿、解冻/再冻结、快照恢复与多提供者组合。
