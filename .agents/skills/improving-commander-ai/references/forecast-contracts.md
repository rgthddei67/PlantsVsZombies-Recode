# 能力接入与行为诊断

用于“AI 不懂新技能”“保护不好工人”“只出一个兵”“突发卡顿”等问题。路径相对仓库根目录。普通单位变更仍遵循对应技能；这里约束的是预测与决策边界。

## 先判断缺的是哪一层

- **资格**：单位是否在本关购买池、当前波次已解锁、合法行可生成、资金和名额够用。不要通过调偏好绕开正式规则。
- **画像**：新购单位、活体、已付款未出生单位是否都带入同一套能力；活体必须保留损伤、剩余时间、已用次数、稳定来源和目标 ID。
- **候选覆盖**：单独的支援可能亏损，协同才盈利。大池随机抽到一次不代表充分比较过路线、延迟和搭配；可增加有界的能力组合对照，保留原优案和相同评分，不设置必买数量。
- **预测**：先比较预测与实际时间线、资源账本、伤害／免疫／控制路径，再怀疑训练参数。
- **评分**：检查“行动”相对“不行动”的增量。已有部队本来会取得的收益不能替新购买或技能费用背书；兵种偏好不能掩盖大额净亏损。
- **参数**：上述链路已可信而选择仍差，才用小批实战检验权重或课程调整。不要把所有症状都归因于旧数据。

## 新增单位的最小闭环

沿正式实体／共用 Rules 核对技能触发、目标层、时序、控制、返冰和取消条件，再检查 `BoardColdStorage.cpp` 的画像、`ColdStorageSearch` 的推进及结算。新购、已存活、付费在途三种来源都要覆盖；给新类型加一个偏好分不能补足缺失的能力。无旧偏好的新兵也应能按能力收益参与候选，不要求先训练才能合法使用。技能当前不能触发也不自动等于禁止购买：只服从正式资格，允许比较提前部署、随后开启天气等协同。

先用有／无能力、受保护／暴露、就绪／冷却等与本次变化直接相关的反事实解释收益，再选已有专项核对真实事务；预测可信后才比较权重。验证“具备比较并自主选择的机会”，不写“每波必须带新兵”或固定僵尸组合。实战要落在真正解锁该兵且场地支持的关卡；小卡池缺乏破阵工具不能直接推导为所有关卡都不会经营。

双边清场按实际受影响对象扣掉己方前线、成熟工人和可恢复资产的损失，并评估失去掩护后付费队列的后续收益；不能提前伤害尚未入场的单位。植物收益按目标真实分层／护盾规则判断；返冰是账本收入，不代表杀掉己方一定划算。接近胜利仍可比较增援，但须与原军队自然推进的基线比较，不能因“快赢了”一律停援或让自伤技能毁掉优势。劫持者参考 `smoke_commander_hijacker_exchange`，落种狙击／回溯参考下文的 `smoke_commander_support_pressure`，不把这些例子固化为强制阵容。

## 预测与正式事务分离

`Snapshot` 只携带有界数值及后台自有的只读模型副本，不能借用实体、Animator、Board 或可重载资源指针。局部搜索使用自身 RNG，不消耗正式 `GameRandom`。价格、冷却、阶段和范围尽量来自实体与预测共用的纯数值规则；图形声明不要拖入纯预测测试的依赖。

实际付款、出生、技能锁定和死亡归因仍通过 Board 正式入口。领取后台结果时按现有过期、局势变化、钱包和事务身份门禁复核；失效的耦合计划应重算，不能执行一半失去掩护的后续动作。取消、换关、读档和暂停不重复付款。线程“ready”不代表计划已经提交。

## 易遗漏的能力语义

| 能力 | 必须表达的区别 | 反事实检验 |
|---|---|---|
| 制冰、修复、付费爆发 | 成熟进度、资格丢失、共享钱包、补给／收入兑现时间；硬控与普通减速是否真的影响周期 | 有钱／缺钱、保护／暴露、控制／解控；不得预支未来收入购买 |
| 防具与适应 | 一类防具和二类盾的受伤顺序、穿透／绕盾、整击溢出、真实伤害来源谱系 | 西瓜／混合火力／灰烬；免伤不自动等于免疫减速或小推车 |
| 临时鼓舞／攻击领域 | 同源刷新、异源叠加、真实范围、前摇停步、效果余时及所有权 | 去掉采样时已烘焙的倍率再逐步计算；不把短 buff 当永久属性，不加速无关生产或技能周期 |
| 延迟召唤／投掷 | 按正式所有权区分提交后的生命周期；出生前不能承伤 | 现有在途事件也要入快照；免费召唤有战斗威胁但没有购买资产或死亡返冰 |
| 投篮车 | 有限弹药、射击/装填停步、资源片段剩余时间与已离膛标志、落格当前目标层、叶子伞逻辑格范围；停步仍能碾压 | 来源死前/后离膛、南瓜宿主、邻格伞、空弹药和挡车坚果；活体回溯不补弹药，死亡重建按出生库存，已离膛篮球单独采样且不重复发弹。入口为 `CatapultRules` / `ProjectCatapult`，专项为 `smoke_commander_catapult_forecast` |
| 时间锚 | 每个来源独立计时，目标按邻路威胁排序且不重复套锚；已提交锚须携带死亡目标的数值副本 | 多来源/错峰、来源先死、范围和容量、界碑改点、不可逆清除；回溯不退还灰烬费或重发死亡返冰，制冰工成熟度与生产余时、锅炉付费阶段及修盾余时按有效能力快照恢复，但已产冰与已扣费用不回滚 |
| 付费精准清除 | 单株稳定 ID、瞄准延迟、目标提前消失、同格其他层、机会成本 | 低价值单株不施法；清掉关键输出确实改善破阵／续航时可用；不能只靠目标自身返冰或阳光估值 |
| 玩家应对 | 真实所选卡、资金、共享卡槽冷却、当前合法落点、已承诺爆炸、存储灰烬与不同等待习惯 | 不假定玩家看到第一只就浪费灰烬；不允许对手模型凭空加钱、复制卡槽或读未来操作 |
| 部署狙击 | 新种灰烬也属于落种事件；来源与引爆截止时间要入推演，旧植物不会重新触发射击 | 瞄准/飞行与引爆竞速、装填/控场、前墙和镜面拦截；只对原锁定实体放行即时植物的部署承伤入口 |
| 移动与清场 | 实际网格／碰撞锚点、邻路溅射、范围攻击、小推车及已耗车状态 | 清洁车先结算再判断进屋；只计一次胜利，胜利后不继续累积收入 |

修复会撤回恢复部分的削血得分，避免刷血获利；玩家付费建成且存活的植物属于资产转移，不能把种植花费本身记成被消耗。已生效优惠只延续到真实到期点，后续付款恢复原价。

冷藏站商店时间干扰由 Board 原子取消全部锚（含死者记录），短暂阻止新锚提交，独立钱包/冷却状态入档；不修改钟匠自身循环。预测同时采样地图资格、已生效余时和可用冷却，假想发动必须扣同一玩家冰钱包，并使后台旧快照失效。精英补种同时检查累计余次与活体上限；读档、模仿者和预测都共用正式名额，不能把尚未死亡的旧株忽略后凭空扩军。

不要把真实胜负机制与预测损耗混为一谈。例如普通化灰入口可能按本体判死，而特殊护盾覆写为总生命；按目标真实入口投影，不能因同属“肉盾”而套同一公式。

## 保留战术自由与时域一致性

攒钱、短局进攻、分批、集中和分路都可能合理。区分“有资金和合法兵却因门槛／候选缺失始终不攻”与“当前预测所有投入均亏损”。不要用统一等待超时、必出巨人、固定主攻一路来代替定位。

修改 v1/v2 切换、时域、资本保护或收益定义时，先读当前 `Search`／`SearchFormation` 及相关单测。长时域行动和等待基线必须同窗重算；生产校准窗口与战斗窗口分别看当前代码，不能扩大观察时间却仍与旧分数直接比较。确需调整时单独配对验证，不顺手叠加多项未经区分的改动。

## 有意义的验证入口

- 纯数值边界与反事实：`tests/ColdStorageStrategyTests.cpp`，CMake 目标 `ColdStorageStrategyTests`，CTest `cold-storage-strategy`。
- 付费能力／防具／新技能：`smoke_commander_paid_abilities`、`smoke_commander_defense_abilities`、`smoke_commander_special_skills` 及各自 verifier。
- 狙击压制灰烬与钟匠已提交回溯：`smoke_commander_support_pressure`、`verify_commander_support_pressure.py`；纯逻辑测试另比较多钟匠的自主选择。灰烬落种须先触发瞄准再推进本步弹道，按实际 reanim 帧率读取已有来源剩余时间。
- 正式技能事务：`smoke_cold_storage_skills`；按任务补资格边界，别复制过时的血量或冷却断言。
- 灰烬、存储毁灭、小推车、队列、经营：在 `autotest/scripts/` 按 `commander_stored_doom`、`commander_mowers`、`commander_rolling_queue`、`commander_investment` 等定位现有专项，选受影响的用例。
- 线程／性能：`smoke_commander_background`、`stress_commander_background`、`verify_commander_background.py`。分别报告 `planningMainMaxMs` 和 `planningWorkerMs`；后台耗时不等于卡了一整帧，平均 FPS 也不能证明没有决策尖峰。

先证明预测不污染真实血量、钱包、冷却和技能状态，再跑自由实战。有限步长、有限召唤容量、未来实体身份或未建植物均可能有近似；明确其范围，实测重要偏差，不宣称逐帧精确模拟。

净经济偏好只作按冰价评分尺度约束的先验，分别导出原始与实际贡献。等待暂优时保留未购买的成批探索锚点以发现完整合并案；锚点不代表付款，最终仍过同一资本门禁。成批、分路和错峰对照与配对共享原组合预算，不按角色设必出数量。

气象站天气事务共用 `WeatherStationRules`，雷荷参数共用 `NightRoofChargeRules`。环境倍率需要剥离快照中已烘焙的雨势/过载，再随预测时序更新；雾中移动倍率独立于鎏金增幅。干扰僵尸需完整入场才能引导；劫持者首次锁定加血标记必须随活体快照保留，不能每轮重复加血。雷荷必须同时计入植物停机、僵尸受伤/麻痹、保护与双边处决；黑障对手只用可见信息及过去观察做有限反制推断。

实时后台搜索按墙钟预算在完整候选之间停止，并按游戏倍速缩短预算；单案推演、共同等待基线和交易门禁不能截断。队列重排、短/长时域共用预算；同步离线训练默认不限墙钟，保持配对种子的可重复性。诊断同时看预算、实际耗时、完整提交与丢弃原因，不能用更宽松的过期阈值掩盖长期重算。

路灯范围、挡位耗油和气象站波次边界共用 `Game/Plant/PlanternRules.h`。快照采样当前燃料、挡位、在途预留和活体雾火奖励；推演按到账时刻补油，死亡/耗尽后恢复雾势。气象站购买新兵会推进波次，天气单独付款和等待不推进，跨耗油边界的行动与等待需分别评价。手动灰烬只对可见格精确选点，暗区用盲炸先验；已提交爆炸仍打真实位置，薄雾与浓雾按实际逐格透明度区分。未出生单位的随机雾火、任意时刻反复改挡和未观察动作仍属近似，不能声称精确预知燃料断供。

所有指挥官地图的同时部署容量共用 `ColdStorageDeploymentRules`，按库存与仍存活/在途付费兵力的原成交价派生；不要仅按库存缩放，否则连续付款会让本案自己的名额收缩。已付款队列读档按绝对安全上限恢复，当前资本下降不得截掉旧交易。富余库存直接比较完整编队时，行动与等待仍须同一时域；兵种覆盖必须与整队抽样交替，不能覆盖掉刚产生的大队候选，也不能把容量上限当作必买数量。

反制推演不能假定玩家会把灰烬落点补满或先花掉留作反制的资源。存在未来建设和可落种反制牌时，额外比较暂缓补阵、保留空位与资金的独立应对；仍用真实视野、费用、冷却与资源到账时间。完全不建设的世界不得为已经放弃的建设下补给订单；显式照明响应另允许只补路灯、保留其他空位和资金。补灯与灰烬共用真实钱包和冷却，估值使用该响应实际会选的挡位与格位覆盖，不能始终按新灯默认 I 挡判断。即使单独留位暂未胜出，也有界比较一次补灯与留位的联合应对，避免漏掉协同。与原补阵世界比较完整结果，不逐项拼接最坏伤害；缺阳光、缺冰、未选牌或冷却空窗的真实经营机会必须保留。

气象站玩家可付费解除迷雾。预测对当前选出的完整反制姿态额外比较一次关雾世界，和关雷荷、灰烬、商店共用钱包；使用正式保护期与切换预告，不假定照明耗尽后雾就会永久保护工人。必须同时计算关雾解除敌方减速的代价，仅采用完整结果更利于玩家的合法应对。当前可见雾势不受黑障隐藏，未来预告仍不得越权读取。专项为 `smoke_commander_fog_counter`。

路灯主动应对在已选完整反制姿态上比较关灯、固定 I/II/III 挡，以及随现有燃料在 II/III 挡切换的有界世界，再对优选世界比较付费关雾。动态响应保留低油节省、爆炸雾火到账后升挡的时序，储油门槛以 `ColdStorageSearch.cpp` 为准，不能把固定省油挡下的工人生存期当成永久安全。有雾按该挡位照明，无雾关灯节油；切挡只依赖可见雾势与当前可用燃料，不读取暗区坐标或未来出生时间。切挡按光源实际格位重算共享形状，并结算真实耗油、在途燃料、死亡及波次边界；不存在跨世界借油或全屏照明。保留当前挡位世界作为对照，不穷举全部操作时刻。专项为 "smoke_commander_lamp_response"，还需用密集场景检查后台预算。

完整编队搜索应先评估一个合法、可支付的同步编队，并在前段交错比较任意类型的配对与小批协作，不能把经营协同全部排到单兵变异之后；天气设备不能作为可重复兵种抽满整队后被去重成单按钮。上次已扩展且仍待机时，下次可直接沿用完整搜索，避免反复消耗两套时域基线预算；该提示不强制购买，也不替代资金和亏损门禁。紧预算验证需检查实际比较过的规模与组合，不能只检查结果及时提交。

灰烬落点必须包含可合法腾出普通层的格子，不能只采样当前空位。`Board::CanForecastCounterAt` 仍检查地形、承载层、冰封等资格；推演在普通层真正消失后才开放落种，因此精准清除也可能替玩家打开反制落点。主动铲种作为另一套完整玩家应对比较：牺牲普通层的资产、输出和产能，保留南瓜及承载层，不授予僵尸击杀冰或伤害分；仍共用视野、钱包和卡槽冷却，并保留操作延迟。当前仅投影单格普通层，未展开多格植物的铲除。诊断看 `searchCounterShovels` / `searchCounterShovelAssets`，专项为 `smoke_commander_counter_vacancy` 及其 verifier；测试不能把“这批同步工人会被清掉”误写成“AI 必须一律不买工人”，错峰和小批仍可自由比较。

雷鸣花/防灾工程师入口：`ThunderFlowerRules`、`DisasterEngineerRules` 和 `BoardArea11Units.cpp`。雷鸣花是平射普通伤害，预测分别推进攻击冷却、就绪后索敌轮询和已起播头部吐弹；轮询不吃攻击倍率，目标消失不取消已起播攻击，并保留已发射雷种和扫掠碰撞；来源死亡不取消在途攻击，目标抗性共享且不刷新已有麻痹。工程师对完整灰烬事件一次兑现最近工人的保护，装填从真实可兑现钱包扣费并受硬控暂停；满罐保护不因麻痹关闭。新购、活体、付费队列共用能力画像，不为新兵设置必买偏好。专项为 `smoke_area11_units` 与 `verify_area11_units.py`；正常对战仍使用合法卡牌、资金、冷却和正式后台指挥官。

通用组合按合法类型/价格覆盖配对，并探索非等量数量、整类换路/错峰及候选间合并；不要用某个僵尸编号或能力标签决定搭配。`SearchFormation` 的重复案去重仅限本次同一快照和评分窗口，保留动作次序及精确延迟（同时出生的并列目标可能受提交顺序影响），不得跨世界复用。最终逐路集中对照仍完整评分并导出诊断；`routeEvaluated` 含先前已算案的复用覆盖，实际积分总数看 `evaluated`，非等量混编/重复提案看 `unevenMixEvaluated` / `duplicatesSkipped`。大量工人候选必须保留，灰烬长冷却且存在安全路的经营回归在 `ColdStorageStrategyTests.cpp`，不能把混编优化变成小队数量限制。

付费反制的即时/延迟模型还必须比较保留工具的完整世界：玩家可依靠现有火力，未提交的付费灰烬、手动领域/维修与商店反制不必为无战果诱饵触发；既有事务和自动能力仍兑现，未使用的工具不得产生补给订单需求。等待基线也采用同一选择，不能只对新购物车保留工具。已有路灯需要有界比较高档照明与留灰烬格的联合响应，逐项贪心可能漏掉边路整行清场。诊断看 `searchPaidCounterCasts` / `searchPaidDefensesRetained`，纯数值反事实在 `ColdStorageStrategyTests.cpp`，默认资源接入专项为 `smoke_commander_optional_defense`；该选择不强制采购或禁止某种兵种。

后台实时任务由一条协调/计算线程和一条辅助计算线程合作：辅助线程领取完整候选，协调线程也参与推演，并独占随机抽样、去重、排名和诊断记账；两者共用任务的墙钟截止。`ColdStoragePlanEvaluator` 只能借用任务拥有的只读快照，模型与等待基线不得在候选计算期间修改；进入下一搜索世界、异常退出或销毁快照前须领取/等待所有在途结果。取消时回收两个线程，只有一个完整结果交回 Board；线程创建失败可回退单线程，付款与过期门禁仍在主线程。默认不限时的离线搜索保持同步，实时完成次序可以改变后续探索路径，不要求与离线逐案一致。诊断用 `planningWorkerThreads` / `planningParallelPlans` 确认实际协作，仍分别看主线程耗时、共享预算、实际耗时与丢弃原因。

实时组合探索为完整大队预留通用少量换兵比较，容量/钱包已满时先移除主要成员，保留已有其他伙伴和新引入成员；天气设置独占设备槽位，不能靠修复把新成员从队尾删掉。经营目标允许用生产画像打开分支，按实际产冰及净现金资产保留各路不同规模的探索案，并有界保留构成和工人数不同的未完成方案。`workerProtectionProgress` 只记录完整推演中真正挡灰或回溯恢复的工人生命折价，用来相对等待基线继续深化尚未回本的方案；不写入资源账本、最终评分或存档。普通火力提前杀光工人导致没有使用灰烬，不是保护进展。尚无保护进展时从已有小批案起步，避免廉价单工人吞掉协作入口；有预算和名额时先追加搭档，满额后才腾位。数量/时序按遍历轮次覆盖，不能绑定类型序号，否则某些兵池大小会让同一类型永远只试同一形状。暂时亏损不代表立即付款，也不应让唯一主要成员在换兵时全部消失。所有搭档仍从完整合法类型中自由探索数量和先行/同步/后援时序，不设置工程师、钟匠或肉盾的固定搭配与必买偏好。最终为胜出案预留同技能删成员/无效等待对照，并重新核对技能边际收益与资本门禁；仍共用原墙钟预算。`incomeEvaluated` / `pruningEvaluated` / `refinementEvaluated` 只表示完整候选比较，不代表必须混编或已付款。安全经营的大批工人回归继续保留。

出生基础数值共用 `Game/Zombie/ZombieBirthVitalsRules.h`：实体初始化与新购／已付款队列读取同一份本体、一类防具、二类防具及基础单口伤害。倍率按每层使用实体相同的舍入与饱和规则，生命倍率和 HXY 防具倍率不能被能力投影的旧常量覆盖；活体直接读实际层值，不重复缩放。未知品种不能用默认肉盾血量兜底。阶段加血、飞行附加层和召唤成员仍需各自建模，不合并进出生本体。`smoke_commander_birth_vitals` 及其 verifier 核对全部已实现品种的正式出生、生命倍率和当前合法购买画像；普通夜晚／屋顶／泳池背景本身不会启用该指挥官，不能为测试扩大棋盘资格。

普通舞王动作与伴舞画像见 `DancerRules`、`DancerZombie::GetDanceForecast` 和 `BackupDancerZombie::GetDancingMovementProfile`。读资源的阶段运动与动作时长在主线程采样，后台只持有数值副本；普通出生运动不等于动作结束后的稳定运动。伴舞按独立实体、相邻行和实际阶段补召，不靠虚增舞王血量表示。预测召唤槽位有界且不回收 ID，避免后续召唤被旧时间锚误认；这是预测容量，不是正式召唤上限。现有精英舞王持续召唤还未展开，不能宣称所有特殊能力都已精确模拟。`smoke_commander_dancer_portrait` 及其 verifier 是受控伤害链与付费画像反事实，不是自主实战胜率证据。
小丑／急救员／气球入口为 `JackBoxRules`、`HealerRules`、`BalloonRules` 与 `ColdStorageHealerForecast`。普通小丑保留开盒免伤和灰烬直接移除路径；精英盒已离手后冻结落点并独立计时，但它由来源成员持有，来源被灰烬直接移除会连盒取消，死亡动画、控场与掉头不能混同实际移除。清理取消事务须先于钟匠复活，回溯不能重建旧盒。正式随机出生和未来择点采用期望/有界贪心近似，活体读取实际阶段余时；不嵌套实体自己的 Monte Carlo。

治疗按存活、尚有头、真实圆形距离、独立冷却/前摇和稳定单疗预留兑现；三层分别封顶，已脱落护甲不重造，气球额外层不能治疗。急救员没有本地治疗能力回溯覆写，活体回血回溯不倒放其施法冷却或永久禁疗；死亡重建才恢复出生状态。未来施法使用正式确定性回退，未展开自身主动等待搜索。治回可生产工人的真实生命只作为通用探索进展，不能直接加冰或最终评分。

气球额外层随正式生命倍率缩放，与本体分开；飞行、破球动画、地面移动按不同索敌/啃食/控场资格推进，溅射候选也要先过滤飞行目标。小推车用实际二维碰撞而非一律免疫。吹风草保留方向、前摇可被杀、合法空格、共享卡槽冷却与真实钱包，前方吹走持续到离场，向房屋吹按正式有限距离；磁力菇移除尚存金属层并同步最大可恢复层，普通小丑拆盒失去爆炸。未来落点/几何和随机阶段仍为有限近似，不要求完整复刻动画；跳跳、绝缘、干扰沿用现有近似，撑杆越障、搭梯与报纸破盾转态等尚未完整展开，不能宣称所有特殊能力已模拟。纯数值边界在 `ColdStorageHealerForecastTests` / `ColdStorageJackBalloonForecastTests`，实机专项为 `smoke_commander_jack_healer_balloon` 及其 verifier；受控夹具不代表自主实战表现。

攻城中间态由 `AssaultFrontier` 在资本拒绝前有界保留，按实际削血、路线、规模与合法类型构成继续尝试伙伴和先行/同步/后援时序；纯护工中间态仍走经营分支。`assaultEvaluated` 只统计真正完整评估的扩展，不表示已付款。探索共享原候选/墙钟预算，不能把保留中间态变成固定组合或必攻。最终资本门禁接受现金亏损与更大的对方实际资产损失交换，仍比较同窗等待基线、幸存资产和剩余风险；虚构现金、单纯纸面削血以及没有回报的大额送死不得绕过检查。玩家手动坚果修复也会响应有弹药的远程投篮威胁，仍共用真实冰、修复冷却与停机约束。

矿工入口为 `DiggerRules` 与 `DiggerZombie::GetDiggerForecast`。地下、出土、眩晕及双向步行使用独立阶段；出土门槛按对象原点而非碰撞中心。地下不能挡普通弹丸、触发小车或假装进屋，持镐折返按右侧接触顺序啃后排；地面资格随阶段变化。樱桃/毁灭/辣椒可打地下且正灰烬直接死亡，土豆/窝瓜须先过滤地面资格，磁吸走合法阶段丢镐状态机。阶段计时只消费有效行动秒，不烘焙雨风/鼓舞；两方向中性步行速度分别重组能力、雨风与金冰，地下只重组位移场及鼓舞。活体时间回溯不倒放矿工阶段；死亡复建从地下有镐出生。随机速度/连续出土边界、已采样琥珀/突击令/破甲狂潮仍有近似，精英矿工额外爆破未展开。纯数值契约见 `ColdStorageDiggerForecastTests` 和 `ColdStorageAssaultExplorationTests`，真实雷鸣花时序专项为 `smoke_commander_thunder_timing`。

富裕库存的现金边际价值由 `CapitalUtilityScale` 从实际钱包和两次当前合法完整大队所需资金派生；设备不计入兵价，不借未兑现的产冰。`AccountForIce` 对收入、支出、残存投资使用同一现金价值，击杀的战术成分、真实对方资产损耗与风险仍独立评分。贫穷期保留原净冰价；现金效用递减只改变计划比较，不改变单位数值、账本、资本风险额度或付款/解锁规则。等待、候选、队列重排与技能反事实必须使用同窗条件权重，不跨版本时域拼接评分。反事实在 `RunColdStorageCapitalUtilityTests`。
