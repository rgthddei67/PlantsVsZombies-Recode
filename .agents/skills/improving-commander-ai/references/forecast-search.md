## 候选覆盖与去重

完整编队搜索应先评估一个合法、可支付的同步编队，并在前段交错比较任意类型的配对与小批协作，不能把经营协同全部排到单兵变异之后；天气设备不能作为可重复兵种抽满整队后被去重成单按钮。上次已扩展且仍待机时，下次可直接沿用完整搜索，避免反复消耗两套时域基线预算；该提示不强制购买，也不替代资金和亏损门禁。紧预算验证需检查实际比较过的规模与组合，不能只检查结果及时提交。

通用组合按合法类型/价格覆盖配对，并探索非等量数量、整类换路/错峰及候选间合并；不要用某个僵尸编号或能力标签决定搭配。`SearchFormation` 的重复案去重仅限本次同一快照和评分窗口，保留动作次序及精确延迟（同时出生的并列目标可能受提交顺序影响），不得跨世界复用。最终逐路集中对照仍完整评分并导出诊断；`routeEvaluated` 含先前已算案的复用覆盖，实际积分总数看 `evaluated`，非等量混编/重复提案看 `unevenMixEvaluated` / `duplicatesSkipped`。大量工人候选必须保留，灰烬长冷却且存在安全路的经营回归在 `ColdStorageStrategyTests.cpp`，不能把混编优化变成小队数量限制。

富余实时搜索直接采样多类型、非等量、少量多路和错峰的完整案，类型全部来自合法选项，继续保留单类型安全经营。实时首案不再主要局限于1–3类/单类型同步大队；实际单案最大新购兵种数由 `widestComposition` / `searchWidestComposition` 导出，设备及既有军团不计。基线成本计入全局截止，但阶段只分剩余时间；同快照/同动作的初始姿态与完整等待结果可在本次搜索复用，保留首次进屋时刻，不跨技能意图或60/120秒阶段拼接。富余阶段提前重评攻城提案、多目标狙击与完整任意跟进，不要求支付或选满目标。

## 经营与攻城探索

净经济偏好只作按冰价评分尺度约束的先验，分别导出原始与实际贡献。等待暂优时保留未购买的成批探索锚点以发现完整合并案；锚点不代表付款，最终仍过同一资本门禁。成批、分路和错峰对照与配对共享原组合预算，不按角色设必出数量。

实时组合探索为完整大队预留通用少量换兵比较，容量/钱包已满时先移除主要成员，保留已有其他伙伴和新引入成员；天气设置独占设备槽位，不能靠修复把新成员从队尾删掉。经营目标允许用生产画像打开分支，按实际产冰及净现金资产保留各路不同规模的探索案，并有界保留构成和工人数不同的未完成方案。`workerProtectionProgress` 只记录完整推演中真正挡灰或回溯恢复的工人生命折价，用来相对等待基线继续深化尚未回本的方案；不写入资源账本、最终评分或存档。普通火力提前杀光工人导致没有使用灰烬，不是保护进展。尚无保护进展时从已有小批案起步，避免廉价单工人吞掉协作入口；有预算和名额时先追加搭档，满额后才腾位。数量/时序按遍历轮次覆盖，不能绑定类型序号，否则某些兵池大小会让同一类型永远只试同一形状。暂时亏损不代表立即付款，也不应让唯一主要成员在换兵时全部消失。所有搭档仍从完整合法类型中自由探索数量和先行/同步/后援时序，不设置工程师、钟匠或肉盾的固定搭配与必买偏好。最终为胜出案预留同技能删成员/无效等待对照，并重新核对技能边际收益与资本门禁；仍共用原墙钟预算。`incomeEvaluated` / `pruningEvaluated` / `refinementEvaluated` 只表示完整候选比较，不代表必须混编或已付款。安全经营的大批工人回归继续保留。

攻城中间态由 `AssaultFrontier` 在资本拒绝前有界保留，按实际削血、路线、规模与合法类型构成继续尝试伙伴和先行/同步/后援时序；纯护工中间态仍走经营分支。`assaultEvaluated` 只统计真正完整评估的扩展，不表示已付款。探索共享原候选/墙钟预算，不能把保留中间态变成固定组合或必攻。最终资本门禁接受现金亏损与更大的对方实际资产损失交换，仍比较同窗等待基线、幸存资产和剩余风险；虚构现金、单纯纸面削血以及没有回报的大额送死不得绕过检查。玩家手动坚果修复也会响应有弹药的远程投篮威胁，仍共用真实冰、修复冷却与停机约束。

## 护卫与分阶段候选

护卫覆盖候选由 `BuildPressureCoverFormations` 生成：按当前合法角色、移速、停火位置和活体护卫范围比较连续护卫、延后后排和直接增援，不修改单位移动，不给覆盖面积赠送收益。完整案仍经过原预算与反制世界；`BuildPhasedPlanningMenu` 可把护卫保留在当前购物车、工人/迫击手留作未付款后队。后队到时必须重新采样评价，缺钱/失效不创造部分单位；迫击手无额外来源槽，只在本世界整笔付款后激活自身装填、弹丸和伤害。换关/读档仍清瞬态意图，已付队列沿原存档恢复，新的搜索根据活体重建候选。

## 经验编队

经验编队入口为 `ColdStorageSearch::BuildExperiencedFormations`（`ColdStorageFormationSeeds.h/.cpp`）。它从当前合法能力画像生成旧版护卫先行、工人跟进及新的保护/攻坚完整案，只提供搜索起点，不沿用旧启发式评分或直接付款。经验案与自由组合交错，进入同一精英、经营和攻城前沿；后续仍可自由删换成员、改路线与时序。完整配方超过现金或名额时整案拒绝，不能先截掉工人或保护者再称协同有效。纯数值 `experiencedFormations=false` 或 AutoTest 根字段 `commanderExperiencedFormations=false` 只用于消融候选来源，正式默认混合搜索；诊断用 `searchExperiencedEvaluated/Selected` 区分实际比较与直接选中原案，不把自由变异后的方案误记成固定编队。回归需同时保留就绪灰烬下的真实经营、已有复杂自由协作以及亏损时可等待的契约。

抗灰经验由 `ColdStorageFormationSeeds` 按 `shieldedAshCap` 独立保留护卫，部署狙击也单独选角色，不能用总血量把二类盾的单次灰烬封顶挤掉。双路接梯、错峰护工和投篮组合只生成全额可支付提案；钟匠需真实提交锚，热狙只处理新落种，门盾不替邻居挡溅射。限时经验首案按同Planner轮次轮转，仍与自由搜索共享预算。`experiencedAshEvaluated/Selected` 仅计实际完成的双路抗灰支援经验/直接采用原案，剪枝替换后清选择标签；被取消的旧后台工作不冒充真实采购。对应反事实见 `ColdStorageCannonExperienceTests`。

抗灰轻装经验补充两路门盾画像与梯子/快兵或投篮的完整核心，最多六案，仍共用96候选上限及真实钱包。它不检查固定炮数，不要求额外钟匠/热狙，并保留完整炮击、补炮与待机反事实；生成和选中不能混为实战破阵。生成与费用/炮击回归见 `ColdStorageLightAshExperienceTests`。

## 墙钟预算与后台线程

实时后台搜索按墙钟预算在完整候选之间停止，并按游戏倍速缩短预算；单案推演、共同等待基线和交易门禁不能截断。队列重排、短/长时域共用预算；同步离线训练默认不限墙钟，保持配对种子的可重复性。诊断同时看预算、实际耗时、完整提交与丢弃原因，不能用更宽松的过期阈值掩盖长期重算。

后台实时任务由一条协调/计算线程和一条辅助计算线程合作：辅助线程领取完整候选，协调线程也参与推演，并独占随机抽样、去重、排名和诊断记账；两者共用任务的墙钟截止。`ColdStoragePlanEvaluator` 只能借用任务拥有的只读快照，模型与等待基线不得在候选计算期间修改；进入下一搜索世界、异常退出或销毁快照前须领取/等待所有在途结果。取消时回收两个线程，只有一个完整结果交回 Board；线程创建失败可回退单线程，付款与过期门禁仍在主线程。默认不限时的离线搜索保持同步，实时完成次序可以改变后续探索路径，不要求与离线逐案一致。诊断用 `planningWorkerThreads` / `planningParallelPlans` 确认实际协作，仍分别看主线程耗时、共享预算、实际耗时与丢弃原因。

## 跨轮提案

`Planner` 可以跨决策保存有界的 `Proposal` 探索起点，只含类型、路线、设备设置和延迟，不含价格、评分、收入、实体ID或借用指针。每次按当前选项重映射、修复钱包/容量并完整评价；失去必要类型则舍弃整案。`Cancel`/销毁/换图/读档清空；它不属于购物车或存档。后台交付先回收线程再取提案，不能把旧提案的预期收益直接提交为真实交易。 实时经营探索在回本前也须轮转不同构成，不能让最佳挡灰或裸工人 fallback 提前返回而遮断第三、第四层协作；不限时搜索保留完整探索节奏。构成深度使用2/3/4/至少5类的有限保留桶，不按四类截断。实时末段固定一份动作副本扫描一轮合法搭档后再轮换起点，避免起点与搭档锁相漏算；各阶段仍分享原候选与墙钟预算，不产生购买义务或额外收益。

## 进攻时序与覆盖证据

完整进攻时序入口为 `ColdStorageAssaultTiming.h/.cpp` 的 `ColdStorageSearch::BuildAssaultSchedules`：对已合法完整动作只改变出生延迟，保留成员、路线、费用与设备零延迟；技能首次落地、独立在途炮弹、已经存在的装填空窗与下一炮候选时点分开。未提交炮的 `ready+windup` 已含飞行，不再加 `flightSeconds`；事件超出当前延迟窗口时不得截早并声称已经安全。分段只是一份需要完整评价的候选，不承诺诱炮成功；当前实现仍沿用整案付款队列，并非观测后才付款的多阶段控制器。免费可重复炮的即时应对不套用付费灰烬的最低冰价门槛，避免低价单兵被预测成可白打炮阵；仍参与完整长期留火应对，已有弹与其他就绪炮照常结算。

时序、原构成、跨轮提案与经营探索必须都有实际评估入口，避免外层/采样器同余编号锁住规模或覆盖掉提案槽。技能粗案允许少量未胜目标共享原余量深化；联合提案有界合并、重新定价，不携带目标ID或旧收益。`searchAssaultTiming`/对战 `assaultTiming` 记录实际完整积分及联合拒绝原因，保留数量按最终合并后的构成计；生成、去重或已过期的候选不能当作完成覆盖。数值契约见 `ColdStorageAssaultTimingTests`；短墙钟覆盖只作实测诊断，固定候选逻辑断言不得依赖CI运行速度。

## 观察后的增援

实际观察后的未付款增援入口为 `ColdStorageAssaultIntent` 与 `Planner::{RememberAssault,ObserveAssault,CompleteAssaultReview}`。只有实际小队或精准技能付款成功才建立短期观察，至多保存两份本轮完整评过的类型/路线构成；它们没有旧价格、收益、资金预留或购买义务。公开炮体相位、离膛和独立弹身份、精准提示结束触发新快照，不能把一炮开火当成全炮冷却。增援在原预算早期槽重映射，缺类型/全额不足/缩容时整案拒绝；原建议延迟不重放，当前即时增援、等待与普通自由搜索仍用原完整反制和资本门禁比较。没有轮到评价的截止不能消费事件；明确拒绝或完整比较才确认捕获代，旧结果不清新事件。有效期不因等待或重评续期，Cancel/读档/关闭策略清瞬态，不影响原付费队列与账本。`assaultObservation` 与 `searchAssaultTiming.continuation*` 区分真实事件、实际评价、无效案和新采购；删改原案后不得沿用直接采用标记。纯数值契约在 `ColdStorageAssaultIntentTests` / `ColdStorageAssaultContinuationTests`，实机生命周期须启用 `backgroundCommander`。这是观察后重新采购闭环，尚未为独立亏损的诱饵估计条件后续策略价值；不能把后队独立收益补到先手分数，公平等待还需获得同样的未来购买机会。
