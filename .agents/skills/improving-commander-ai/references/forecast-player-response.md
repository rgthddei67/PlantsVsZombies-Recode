## 建设、留位与铲种

反制推演不能假定玩家会把灰烬落点补满或先花掉留作反制的资源。存在未来建设和可落种反制牌时，额外比较暂缓补阵、保留空位与资金的独立应对；仍用真实视野、费用、冷却与资源到账时间。完全不建设的世界不得为已经放弃的建设下补给订单；显式照明响应另允许只补路灯、保留其他空位和资金。补灯与灰烬共用真实钱包和冷却，估值使用该响应实际会选的挡位与格位覆盖，不能始终按新灯默认 I 挡判断。 留位应对的订冰也须预留一张当前就绪、来源与落点合法且阳光够用的灰烬阳光；仍可用余钱下较小订单，施法后按共享冷却解除预留，不为冷却或不可支付的卡牌虚构资金锁定。即使单独留位暂未胜出，也有界比较一次补灯与留位的联合应对，避免漏掉协同。与原补阵世界比较完整结果，不逐项拼接最坏伤害；缺阳光、缺冰、未选牌或冷却空窗的真实经营机会必须保留。

灰烬落点必须包含可合法腾出普通层的格子，不能只采样当前空位。`Board::CanForecastCounterAt` 仍检查地形、承载层、冰封等资格；推演在普通层真正消失后才开放落种，因此精准清除也可能替玩家打开反制落点。主动铲种作为另一套完整玩家应对比较：牺牲普通层的资产、输出和产能，保留南瓜及承载层，不授予僵尸击杀冰或伤害分；仍共用视野、钱包和卡槽冷却，并保留操作延迟。当前仅投影单格普通层，未展开多格植物的铲除。 同格死亡替换需忽略原株自己的同时唯一名额：曙光莲与路灯花活着时仍保留该格的未来替换画像，正式第二株门禁保持生效；其他活体占用与累计种植额度不豁免。诊断看 `searchCounterShovels` / `searchCounterShovelAssets`，专项为 `smoke_commander_counter_vacancy` 及其 verifier；测试不能把“这批同步工人会被清掉”误写成“AI 必须一律不买工人”，错峰和小批仍可自由比较。

经营留位与开炮时机是独立选择：存在免费可重复炮时也须比较“保留周转空位＋即时炮击”的完整世界，不能把留位一律绑定长期留火。无伤害、无付费反制的廉价兵若仍获大量对方资产压力分，应核对等待与行动分别选择的建设/兑换/订冰账本；不能把玩家模型不必要补满格子造成的周转损失当作已证明的进攻效果。`compare_commander_search` 显式案的 `playerEconomy` 提供对应资金及留位诊断。

## 留存反制与商店

付费反制的即时/延迟模型还必须比较保留工具的完整世界：玩家可依靠现有火力，未提交的付费灰烬、手动领域/维修与商店反制不必为无战果诱饵触发；既有事务和自动能力仍兑现，未使用的工具不得产生补给订单需求。等待基线也采用同一选择，不能只对新购物车保留工具。已有路灯需要有界比较高档照明与留灰烬格的联合响应，逐项贪心可能漏掉边路整行清场。诊断看 `searchPaidCounterCasts` / `searchPaidDefensesRetained`，纯数值反事实在 `ColdStorageStrategyTests.cpp`，默认资源接入专项为 `smoke_commander_optional_defense`；该选择不强制采购或禁止某种兵种。

冷藏站商店时间干扰由 Board 原子取消全部锚（含死者记录），短暂阻止新锚提交，独立钱包/冷却状态入档；不修改钟匠自身循环。预测同时采样地图资格、已生效余时和可用冷却，假想发动必须扣同一玩家冰钱包，并使后台旧快照失效。精英补种同时检查累计余次与活体上限；读档、模仿者和预测都共用正式名额，不能把尚未死亡的旧株忽略后凭空扩军。

## 精准清除与解锁

精准清除允许以真实有利资产交换先削弱仍会攻击的来源，不要求一击同时进屋；选靶优先级按同窗内的周期全场释放次数估算，最终回报仍必须完整推演。无害高价植物、未击中目标和未兑现跟进不能冒充破阵。实时选靶保留部分原阶段时间用于胜出目标的完整编队重搜，仍比较只施法、只买兵、联合行动及等待。通用大队跟进仍与技能共用一个钱包/截止，不指定兵种模板。反事实在 `RunColdStorageSiegePreparationTests`。

多目标精准清除保留旧首目标字段并附加稳定ID列表；正式上限、每株费用与共同瞄准/冷却读取 ColdStorageSkillRules。搜索交错比较不同目标数与跨行组合，名单只是候选，不要求选满；已付款的 pending 全名单参与等待基线，不再次收费。各反制世界、删兵、结果采用和不施法对照必须同步复制/清空全部目标。任一目标消失不补靶、不影响同批其他目标。保存版本升级以防旧EXE静默丢掉额外已付款打击，旧单目标局面只补空附加列表。

距正式狙击解锁仅一波时，`precisionUnlockAfterPurchase` 允许同钱包比较“真实付费派兵→正式复查及后台计算后开始瞄准→付费清除”的未来反事实。空案、纯设备、缺钱或技能后缩容超额不成立；不禁止等待、不指定兵种、不提前改正式资格。结果将未付款意图导出到 `forecastPrecision*` 并清空当下施法目标；预测费用在特征中预留，主线程当前只支付真实购物车，下一轮按实际局面重新选靶。该预留会保守低估等待期间可用资金。未来意图仅诊断，不入存档或作为已付款承诺；用 `smoke_commander_precision_unlock` 及其 verifier 核对实际兵费、未来费未预扣、解锁后重新搜索与实际收费。

## 玉米炮与在途弹

玉米炮使用 `Counter::plantID/consumesPlant/flightSeconds` 区分可重复来源与一次性灰烬。本体余时是到爆炸的总时间，采样时扣除 `CobCannon::GetSimulationShotWindup()` 后再推进前摇，不能重复加延迟；前摇可受击，离膛后按独立弹丸保留已锁定落点。已发射快照不重新收费、不消耗炮体，死亡只停止尚未离膛和未来装填。`CobForecastAimPoints` 必须包含格中心以外的可见场景边缘；玩家能在那里提前炮击，漏掉它会把密集鼓舞冲锋误判成抢先突破。选靶按同一来源去重备选爆点，重复火力纳入先削弱输出的资格；专项是 `smoke_commander_cob_cannon` 与对应 verifier。10-6 正常开局陪练入口为 `train_cold_storage.episode_commands` 的 `cob`，无支援、真实双玉米升级及前排高坚果；满卡槽携带毁灭/咖啡、樱桃、辣椒与对空，灰烬只按真实可见威胁和费用提交。其他命名战术夹具保持独立。

## 玉米炮升级重建

玉米炮升级重建入口为 `Board::{CanForecastKernelAfterVacancyAt,CanForecastCobUpgradeAt}`、快照 `Construction::cob` 和 `ColdStorageSearch::SelectCobRecipe`。逐笔购买两株真实玉米投手，再支付升级牌；共享玩家钱包、同种卡槽冷却与当前承载层身份，不能借用后续到账。未变身模仿者、重叠底材及外壳/overlay 阻挡不能升级。双格炮活着时同时占两格，死亡后才可补材；主动铲种仍不铲多格炮，但死炮格后来补出的单格植物可按当前身份让位。空场预备只恢复本快照已有炮位，近身危险选择只读可见单位。底材消费不发击杀冰或战损分，新炮只转移底材剩余资产一次；既有炮的历史底材成本仍不追溯虚构。新炮独立负 ID 与反制 source 共用各落点装填，遵守真实首次充能、起手取消和已离膛弹独立规则，旧狙击目标不会命中新身份。暂缓建设/留钱仍是另一完整玩家世界。诊断 `cobRebuildForecast` 的升级/新炮发射是重叠预测中的统计，不能当成实战建炮数；`compare_commander` 的 `cobRebuild:false` 只作只读反事实，`compareConstructionResponse:true` 可分别查看默认建设世界与被选出的最坏完整应对。纯数值回归在 `ColdStorageCobConstructionTests`，真实存档须另外核对采样不变性、三笔费用和实际陪练。
