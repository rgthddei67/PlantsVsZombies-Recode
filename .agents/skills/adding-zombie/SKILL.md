# 给 PvZ 新增僵尸

**最高原则：不确定的事立刻问主人，不要自行推断。** 已知必问项：①**帧事件帧号**（死亡 Die 帧、啃咬 EatTarget 帧——主人看动画预览有准确答案）②断肢/断头**隐藏哪些轨道、是否换残肢材质、粒子用哪张图**（各 reanim 差异大）③数值/行为偏离原版时。**帧号口径（主人 2026-07-14 定死）：`AddFrameEvent` 真实帧号 = 预览帧号 − 1；主人报的帧号默认已 −1 过，直接用不许再减**；只有自己读预览工具时才手动 −1。

**所有玩家可感知的歧义或分支都必须逐项问主人。** 包括但不限于例外对象、伤害/能力来源归属、基础/紫卡/运行时变种是否视为同类、伤害与附带状态是否一起豁免、范围/溅射口径、动作提交边沿、存读档终态和首次教学/复习投放。主人批准一个具体例子只批准该例，禁止按常识、实现便利或相邻品种自行外推；先提出当前最小决策问题并记录明确答案，未定分支保持未实现或中性，不能边做边替主人补规格。

**帧号即便主人给了也必须实测触发**——"末-1 帧"陷阱：帧事件靠播放头**越过**帧号触发，死亡动画实际停帧因 reanim 而异（伴舞 anim_death 65~101，帧 100 永不触发、99 才行；舞王 146 却正常）。**症状指纹：僵尸血 0 卡在 anim_death 不消失，10 秒后 run.log 出现 `WATCHDOG force-die`**。见到即帧号问题，回报主人调小。

## 原版参考边界

- C# 参考实现用于确定玩家可感知的功能契约：状态机与触发顺序、时长和数值、目标规则、断肢/死亡结果、音效及资源表现；没有主人批准时不得自行改变这些行为。
- C# 不是本项目的类图或字段模板。实现前逐项核对当前僵尸继承体系、Board/实体所有权、碰撞回调、Animator 与根运动、绘制层、资源轨道、魅惑/死亡生命周期和存读档，再复用现有最窄入口；禁止复制平行状态或绕过公共系统。
- 玩法对象架构固定为继承式：新增僵尸继续选择 `Zombie` 或最窄既有派生基类，并用窄虚接口表达品种差异；不得为僵尸能力恢复通用 `Component` 基类/类型表、把品种状态拆成任意组件组合，或为形式统一复制基类生命周期。空间数据由宿主 `CreateTransform()` 创建并通过 `GetTransform()` 访问。Collider、Shadow 与 Clickable 是宿主显式独占的具名附件：分别通过 `CreateCollider()` / `GetCollider()` / `RemoveCollider()`、`CreateShadow()` / `GetShadow()` / `RemoveShadow()`、`CreateClickable()` / `GetClickable()` / `RemoveClickable()` 管理，禁止恢复 `AddComponent/GetComponent/RemoveComponent<T>` 或缓存可独立失效的附件裸指针。三个类的 `Component` 后缀只是过渡命名，不代表组件系统。`CreateClickable()` 保证 Collider 已就绪；`RemoveCollider()` 会同步注销 Clickable，运行时替换 Collider 则保持 Clickable 注册有效。
- 架构、坐标或资源差异必须做适配，并用状态投影、音效计数和默认可见截图证明功能等价。原版资源版本与当前 reanim 不一致时，以玩家结果忠实为目标，具体轨道方案按当前资产确认；需要改变行为时再询问主人。

## 视觉识别底线

- 机制或身份特征明显的新僵尸不得只靠全身换色表达。至少提供一个能改变低分辨率轮廓的独立装备/部件，以及与机制阶段同步的动作、破损或脱落反馈；巡航、能力前摇、破层、死亡与图鉴中都应让玩家快速辨认。染色只能作为辅助色彩语言，不能成为唯一识别手段。
- 动作优先复用语义相符的原版僵尸时间轴与核心身体分件，再把 AI 母图拆成头盔、工具、背包等有限装备或命名 follower；除非新体型确实需要且已完整拆件校准，否则不要用大型合成图替换整具身体。这样既保留原版断肢、啃食和死亡动作，也让独立装备承担身份轮廓。
- 独立部件必须按实际握持、背负或安装关系选择稳定语义锚点和绘制层级。背负设备要在最终低分辨率合成中与肩背、腰线形成明确重叠，不能只因挂到 `Zombie_body` 就接受落地或并排站立的观感。主人指出附件漂移、过大或遮挡错误时，要在最终实机合成中校准尺寸、锚点、父轨及前后遮挡；轻微机械颤动不得继承手臂等大幅摆动轨。手持件若直接跟手掌会脱手，优先挂到稳定的上游前臂轨，并在最终合成中让手掌与设备握持处保持重叠；自身状态反馈优先换图或小幅局部变换，禁止用大幅逐帧缩放制造“抖动”。机械往复 reanim 还要检查循环末帧到首帧的角度/位移差，不得只检查片段内部平滑。默认实例化与 `-NoInstance` 各用同步截图验收，不能只看高分辨率源图或单张贴图。
- 延迟回溯、倒计时等 Board 独立事务若需要持续标记移动目标，僵尸只负责提交边沿，Board 按稳定 ID 在目标当前视觉原点周期续发短寿命复合粒子；表现层可把钟面与多根指针拆为同中心透明层并赋予不同逆向角速度，但不得新增会改变事务时序的实体动画或在粒子里复制倒计时真相。恢复仍只发生在 Board 的既有结算边沿，施法者死亡与存读档语义不得因视觉增强改变。

## 坐标换算铁律

**C# 原版逻辑场景是 800×600，本项目是 `SCENE_WIDTH=1100`、`SCENE_HEIGHT=600`。原版任何绝对 X/Y、碰撞框偏移、绘制偏移、粒子触发点和屏幕边界都只能当语义参考，禁止直接抄入代码。**

- 场景绝对坐标改由 `SCENE_WIDTH/SCENE_HEIGHT`、Board 网格与当前背景几何重新派生；不要把 800 宽地图的右边界、出生点或阈值原样搬来。
- 原版按世界 X 分段的速度/状态阈值写成“当前地图坐标基准 + 原版相对距离”；平地可从 `CELL_INITALIZE_POS_X` 派生。屋顶连续坡面由 `Board::GetRoofSlopeEndX/GetRowCenterYAtX` 唯一拥有，当前交界 X 从 `CELL_INITALIZE_POS_X + 5 * CELL_COLLIDER_SIZE_X` 派生，禁止品种复制斜坡公式。
- 僵尸局部坐标先求“原值相对 C# 绘制原点”的差，再锚到本项目稳定视觉原点 `Transform + mVisualOffset`；物理框、攻击框和粒子通常不得跟受伤抖动等临时绘制偏移移动。
- 黄油等需要跟随活动部件的状态贴图统一走 `Zombie` 配置的 reanim follower：基类虚接口默认返回 `anim_head1`，异形/车辆只覆写自己的语义父轨道；必须在派生 `SetupZombie()` 完成后再配置，并让命中、清除、死亡、魅惑和读档只切 follower 可见性。资源确实没有该轨道时保留稳定锚点后绘兜底，禁止创建空轨道掩盖注册问题。异常体型用独立虚倍率调尺寸，默认保持 `1.0`，禁止为放大贴图改语义轨道或全局默认尺寸。冰晶等稳定车体/地面效果继续使用 `Transform + mVisualOffset` 局部常量；默认实例路径的后绘贴图必须用 `DrawTextureInstanced` 与 reanim 本体进入同一有序实例流，`-NoInstance` 才保留 `DrawTexture`。不能假定 C++ 调用在后就一定显示在前：对象数跨过并行阈值后，同一 blend 段会先 replay batch、再 replay instance，受击 glow 的 Add 分段还可能让错误只在“不发光”时出现。专项用至少 200 个可绘制对象稳定命中并行路径，分别截取无 glow、glow 中、glow 结束及 `-NoInstance` 对照。
- follower 层级按品种语义选择：普通僵尸默认把已经算好完整父轨仿射变换的 follower draw record 延迟到整个 Animator 的轨道和子附件之后，使黄油稳定处于头发、眼镜等最高层；巨人这类需要武器、下巴或前臂跨层遮挡的品种覆写为父轨之后立即提交。延迟记录必须留在 `Animator`/`Graphics` 的同序队列内：默认 Vulkan 使用 bindless `InstanceRecord`，`-NoInstance` 与 OpenGL 兼容后端使用同序矩阵 batch（OpenGL 4.3 可由 SSBO 在 GPU 变换，3.3 在 CPU 展开）；禁止在 `Zombie::Draw` 外部另发 `Graphics::DrawTexture` 或强制 flush。专项同时覆盖普通头发遮挡、异形专属头轨、极端动作遮挡、存读档、默认实例化与 `-NoInstance`，并审计所有已注册僵尸的语义轨道是否成功配置。
- **胸甲也可以是一类防具**：`HelmType` 表达的是防具结算顺序和独立生命池，不要求视觉位于头部。胸甲等必须压住整套本体的装备可跟随 `Zombie_body`，并用 `drawAfterAllTracks=true` 延迟到本体全部轨道之后；不要仅把子 Animator 附到身体轨道，因为父轨后续的手臂/头部仍会盖住它。裂纹贴图只从同一 `mHelmHealth` 派生，不得为每张贴图增加隐藏生命段；破甲、磁吸、死亡和读档都要同步 follower 显隐，默认实例化与 `-NoInstance` 各看同步截图。
- **正向修复后全部破损外观必须可逆**：治疗只能增加当前仍大于 0 的生命池，不能重建已掉落、被磁吸或已部署的装备；结算后通过基类虚语义入口重建本体与装备表现，默认调用 `CheckHelmImage` / `CheckShieldImage`，拥有本体伤势换图的品种再覆写并收敛到同一重建函数。身体、头盔与护盾检查都必须完全由当前耐久重新派生完整/轻损/重损阶段；恢复完整态要显式清除 Animator 轨道 override（`SetTrackImage(..., nullptr)`），不能保留只允许向下破损的一次性分支。专项同时断言耐久增加、本体/一类/二类三层各自夹紧上限、跨阈值后的实际贴图键，并以同步截图验收。
- **同一语义轨道并存多种状态挂件**：`ReanimTrackExtra` 以命名 vector 保存多个 follower 槽；黄油、防具等各用稳定唯一槽名，只更新自己的贴图和可见性，不得互相覆盖或退回对象外 `DrawTexture`。静态 follower 默认继承宿主 Animator 的状态 overlay，使减速、冻结等覆盖色覆盖装备；属于当前承伤层外观的装备还必须显式传 `inheritGlowEffect=true`，让父轨 additive glow 同步覆盖装备。黄油等状态贴花显式同时关闭 `inheritOverlayEffect` 与 `inheritGlowEffect`，保持自身原色且不随本体受击闪白。实例与 `-NoInstance` 都按“base → overlay → glow”提交；专项在同一画面先施加覆盖色、再命中装备，断言装备 follower 发光而状态贴花不发光，并截图核对 additive glow 最终确实落在 follower 上。只有需要独立播放头、clip 或帧事件的附件才使用子 Animator。
- 用户目验若指出整只载具统一偏高/偏低，且碰撞框、攻击框、发射点、死亡特效都已从 `Transform + mVisualOffset` 派生，只调权威 gamedata 的整车 offset，禁止给每个消费者再补一份 Y。改后同时复查车轮地面线、投射物起点与独立残骸；只有其中单项仍偏时才调该项的局部常量。
- 僵尸装备发射同行直射物时，瞄准线、枪口粒子和弹体出生必须共享同一真实炮口世界锚点；不能为了命中逻辑行而把出生 Y 直接设为目标格 Y。炮口与目标高度不同时，让弹体视觉沿明确轨迹从炮口收束到终点，碰撞仍按锁定逻辑行判定，并保存足够的终点/轨迹状态供在途读档恢复。AutoTest 同时截图炮口起点与在途轨迹，并断言途中植物仍可正常拦截。
- 网格位置与画面偏移继续分离；屋顶出生、读档重建、出土裁剪及任意当前点地面线必须使用 `GetZombieCollisionY/GetZombieSpawnY(row, worldX)`。水平移动仍由品种的 `ZombieMove` 决定，基类在阵风后和 `ZombieMove` 后统一把 Transform Y 收敛到坡面，普通、飞行、地下品种不得各自维护 Y 公式。
- 验证先执行同步 `screenshot`，再用 `animatedObjectsByTag.Zombie` 的 `renderProbeReady/worldBounds/visualToRenderCenterD*Int/nearestZombie` 验证本项目最终绘制几何相对自身 collider、同排植物或攻击目标的关系；每阶段只保留一个目标僵尸以稳定数组索引。
- 修改出生 offset、受伤偏移、附件、翻转或整身变换时，在默认实例路径跑同一静止用例并比较整数 `worldBounds`；运动对象瞬时绝对 X/Y 只供诊断，不作稳定断言。
- 战场主体按 `row N 植物 → row N 僵尸/扶梯 → row N+1 植物` 交错绘制；同排僵尸仍在植物之上，下一行植物遮挡上一行越界身体。大蒜改道、蹦极选格、首领换行等运行期 `mRow` 提交必须走基类行提交/排序键刷新入口，不能只改字段；小推车与子弹层保持原顺序。专项同时断言语义 `renderLayer` 未变、实际 `renderOrder` 行带正确，并以默认/`-NoInstance` 屋顶跨行截图验收。

## 第 0 步：勘察（动手前全部做完）

1. **读 reanim**：`build/clang-release/resources/reanim/<Name>.reanim`，Grep `<name>` 提取全部 track，并 Grep `<i>` 列出每个实际图片键；`anim_*` 是剪辑轨（`<f>0/-1</f>` 定活跃帧区间），其余是部件轨。重点记下：头部组（`anim_head1`=头、`anim_head2`=下巴、`anim_hair`，可能有 tongue/earing 等挂件）、外臂三段（`*_outerarm_upper/lower/hand`，注意前缀可能不统一）、有无残肢轨（`_bone`/`upper2`）、`_ground` 轨（位移速度来源），以及 `rise2～6` 这类把帽子、脸和衣服烘在一起的阶段合成图。独立部件换色不会影响合成图，必须按实际 `<i>` 引用逐张盘点。
2. **读 C# 参考并主动盘点音效**：`D:\PVZ\PlantsVsZombies.NET-master\Lawn_Shared\Lawn\Zombie\Zombie.cs` grep 僵尸名，读 UpdateZombieXxx 状态机 + SetupReanimForLostArm/LostHead + 数值，先记录必须忠实的玩家行为，再按本项目当前所有权、更新、碰撞、动画、资源和存档契约实现；同时收集相关路径的全部 `PlayFoley` / `PlaySample`，不要等主人听出缺声才补。沿 `FoleyType → Sexy.TodLib/Foley/TodFoley.cs → Resources.SOUND_*` 得到精确资源键，以资源键去掉 `SOUND_` 后的小写名到 `D:\PVZ\中文年度加强版完整版\Test\sounds\` 查同名 `.ogg`。找到后复制到唯一权威 `build/clang-release/resources/sounds/` 合理子目录，并同步 `resources.xml` 与 `ResourceKeys.h`；找不到才问主人，禁止用相近声音静默替代。构建后检查 `manifest.txt` 和启动日志无 missing sound，并用可见行为路径及 `GetSoundPlayRequestCount` 投影验证触发次数（含读档不得重响）。出生/登场声若只属于“新刷新”，必须从 `Board::CreateZombie` 的正式新建路径调用品种钩子，禁止塞进 `SetupZombie()`（预览与 `CreateZombieWithID` 读档也会经过 Setup）。**警惕版本错位**：C# 是后期资源（舞王=disco 版有 `_upper_bone` 残肢轨；主人给的 MJ 版没有）——玩家可感知的状态机保持原版，断肢轨道和素材方案按手头 reanim 实际能力适配。
3. **盘点已就位基建**（常常提前有了，别重复加）：`ZombieType.h` 枚举（**多半在 `NUM_ZOMBIE_TYPES` 哨兵之后，要移进去才可出怪**）、`TestDriver.cpp` kZombieNames、`GameScene.cpp` kDevZombieTable、`AnimationTypes.h`、resources.xml 的 `<Reanimation name>`、粒子贴图。缺哪补哪。**reanim 文件进入 manifest 不等于已注册**：新角色必须同时把文件放入权威 `resources/reanim/` 并在 `resources.xml` 写 `<Reanimation name="...">`；漏后者会让 `AnimatedObject` 得到空 Animator，僵尸构造阶段访问轨道时直接 Access Violation。AutoTest 在首次直造前用 `ResourceManager::HasReanimation` 断言注册键。不要给 `Zombie`/`AnimatedObject` 基类加宽泛空 Animator 早退来“止崩”，`Start()`/`SetupZombie()` 仍会访问它，且坏注册会被掩盖。每个可直造的新类型必须在同一改动同时加入 `TestDriver.cpp` 的 `kZombieNames` 与 `GameScene.cpp` 的 `kDevZombieTable`；提交前比较两表的新类型集合，不能用 `spawn_zombie` 专项通过替代开发者面板登记。开发者面板会把所选僵尸的**枚举名字符串**写入 `PlayerInfo.json`；禁止改存表下标或枚举整数，因为新类型移入哨兵前会让旧数值漂移。新增表项继续用 `DEVZ(ZOMBIE_X)`；需要自动回归时，让 `smoke_develop` 实际选到该类型并断言召唤及跨场景重建仍保持，不能只循环到早期旧类型。
4. **若任务含冒险出怪表**：完整阅读 [references/adventure-spawnlist-pacing.md](references/adventure-spawnlist-pacing.md)，先画整大关的首次登场/复习/综合表，再改 JSON；禁止只盯被抱怨的单关局部挪怪。
5. **若僵尸会部署脱离建造者后持续存在、独立承伤或拦截弹道的世界对象**：完整阅读 [references/persistent-built-world-object.md](references/persistent-built-world-object.md)，先定所有权、原子提交、碰撞优先级与双方存档边界，再写状态机。

## 实现清单

1. **类**：`Game/Zombie/<Name>.h/.cpp`，抄最像的现有僵尸（护盾换图=PaperZombie；状态机+覆写碰撞=Polevaulter；手臂显隐对称钩子=DoorZombie；召唤/编队=DancerZombie+BackupDancerZombie）。HP/速度硬编码在 `SetupZombie()`（不在 gamedata.json）。
2. **SetupZombie 先判定“复用父类”还是“完全接管”**：
   - **同一套 reanim/轨道/事件时序的换皮或数值变体**，优先调用最近父类的 `SetupZombie()`，再覆盖 HP、攻击和速度差额；这样直接复用已经验证过的 Die/EatTarget 事件，禁止重复 `AddFrameEvent`。父类已经乘过移速时，用“目标倍率 / 父类倍率”补差（粉色橄榄球 1.85/1.7 实证），不要再乘完整目标倍率。
   - **新 reanim、事件时序不同或状态机需要替换父类初始化**，才不调基类并自己接管三件事：帧事件注册（Die 一次性 + EatTarget `repeating=true`，帧号=全时间线绝对帧，只在所属剪辑段播放时经过）、走路起播、`mIsPreview` 分支（预览只 PlayTrack 不注册事件）。`AddFrameEvent` 回调走一个指针大小的内联存储，只允许无捕获或 `[this]` 这类可无异常复制、平凡析构的小回调；额外上下文放宿主字段并只捕获 `this`，禁止扩大捕获后改回每事件 `std::function`/堆分配。任何新增帧号仍必须先问主人。
   - **预览运动不能假定会进入品种实战更新**：`Zombie::Update()` 对 `mIsPreview` 只推进 `AnimatedObject`，不会调用 `ZombieUpdate/ZombieMove`。若上下跳、附件或阶段姿态由品种状态机而非 Animator 自身产生，覆写 `Update()`，先调 `Zombie::Update()`，再只为非 UI 大图推进无碰撞、无位移、无音效的展示状态；图鉴网格设置 `mIsUI + PauseAnimation()` 时必须继续静止。AutoTest 分别在选卡与图鉴详情导出相对高度/阶段整数投影，不断言运动对象绝对 X/Y。
   - **预览的无 `Board` 不是动作失败**：品种 `Update()` 的终止/耗尽判定若把 `mBoard == nullptr` 视为异常，必须先为 `mIsPreview` 早退到纯展示更新；否则首帧会把预览初始 `anim_idle` 改成实战 `anim_walk`，还会重新启动已暂停的图鉴网格 Animator。专项至少在一帧以上后同时断言网格保持暂停、详情保持指定轨道，并覆盖默认与 `-NoInstance`。
   - **僵尸自身整体动画倍率只有一个出口**：覆写 `GetAbilityAnimSpeedMultiplier()`，固定品种值直接返回常量，阶段能力从已保存状态派生，出生随机值存派生类字段并由 `SaveExtraData/LoadExtraData` 持久化。状态变化后调用 `UpdateAnimSpeed()`；禁止子类直调 `Animator::SetExtraSpeedMultiplier()` 或再造一份通用基础倍率字段。`mSpeed` 只表示额外水平位移，`PlayTrack(..., clipSpeed)` 只表示当前轨道绝对速度。
   - **Board 权威倒计时必须与专属一次性动作同长时**，在该阶段通过基类的固定 extra 倍率虚入口收敛动画速度，让它先于冻结、黄油、麻痹、减速与天气倍率生效；退出阶段再 `UpdateAnimSpeed()` 恢复普通组合。只绕过动画推进，移动和啃食仍由状态机独立禁止。不要只把轨道 clip 调成目标 FPS，否则大雨或减速会让一秒动作提前结束或播不完。AutoTest 在有控制状态和非 1.0 天气倍率下同时断言倒计时、轨道与 `animExtraSpeedPct`。
   - **带 `_ground` 的根运动僵尸禁止把目标世界速度直接写进 `mSpeed`**：`GetTrackVelocity()` 已包含逐帧根位移与 `EffectiveSpeed()`，`ZombieMove()` 随后才乘 `mSpeed × delta`；因此 `mSpeed` 应承担资源 FPS 的时间基准换算，品种快慢主要用与 C# `mVelX` 对齐的 clip 速度同步改变步频和位移。直接把 42/54px/s 填给 `mSpeed` 会让身体滑行。对外提供投手、倭瓜或数值推演使用的未来水平速度时，必须对当前活动片段的 `_ground` 逐帧位移取平均，再组合能力、减速、天气、风力和场地倍率；禁止把当前单帧速度外推整段时间，否则非匀速步态会在不同帧随机前后偏移。AutoTest 至少断言 `effectiveAnimSpeed`，并从池外稳定起点检查进入泳池前仍保留可见步行时长；有固定飞行时间攻击时，再跨多个步态相位锁定相对提前量。
   - **非魅惑状态也会反向移动的品种必须集中方向权威**：在 `Zombie` 提供 `IsMovingRight()` 虚入口，让基类位移、台风顺逆风、目标提前量和房屋失败线都查询它；子类只按当前 phase/阵营覆写一次。禁止仅在子类 `ZombieMove()` 里改正负号，否则会出现“视觉向右但仍触发进家”或阵风/索敌预测反向。AutoTest 同时断言方向、位移趋势与 `CanTriggerGameOver()`，并在房屋附近验证反向阶段不触发失败。
   - **跨轨道换态先核对视觉坐标系，不能只看逻辑位移**：从同一身体部件轨读取旧轨末帧与新轨首帧锚点，再叠加各阶段 `mVisualOffset`/视觉补偿，世界提交位移要抵消总差；海豚 `anim_dolphinjump→anim_swim/anim_ride` 当前实测分别需 104/106 px，原版 94 只复制逻辑位移会在落地时倒退。若换态同帧撤销视觉补偿，禁止继续 blend 旧姿态（海豚 `anim_ride→anim_walkdolphin` 上岸须零混合），否则旧姿态会被新坐标绘制成短暂垂挂。C# 的 `mUsesClipping` 也不等于通用水线裁剪：海豚入水只在 0.56～0.65 与 0.75～结束使用较低的局部底线，中间关闭；在本项目用派生类裁剪钩子复刻并截图校准，默认实现必须保持其他水中僵尸原样，禁止通过隐藏海豚部件轨或裁整只僵尸冒充。
   - **内嵌 reanim 部件切换为独立实体时也要接续视觉锚点**：在隐藏旧部件前取得双方同一语义轨道的实际渲染世界原点（含各自 `mVisualOffset`、Transform scale、`SetFlipX` 支点和最终 render scale），新实体完成轨道、阵营与镜像配置后再补偿差值；原版逻辑出生量可保留作创建基准，但不能代替两套资源原点换算。只校正主人指出的轴，抛物线高度等由独立玩法合同继续拥有。AutoTest 应在既有切换事件前推进正式路径，以同一状态下的相对锚点整数投影覆盖正向/魅惑镜像，并配合默认与 `-NoInstance` 同步截图；不要断言运动对象的绝对世界坐标。
   - **把父类资源选择改成虚入口时必须双向回归**：派生类换色通过后，仍要触发父类的受损帽、残肢、掉落粒子和读档终态；新增虚入口可能把父类原先未被断言的错误键暴露出来。AutoTest 分别导出父类与派生类的实际资源键加载状态，不能只证明精英路径。
3. **枚举移动 + 空工厂窗口**：新类型必须**追加在全部既有已实现类型之后、`NUM_ZOMBIE_TYPES` 哨兵之前**；禁止插进旧类型中间，否则存档里的整数僵尸 ID 会错位。把枚举移到哨兵前的**同一提交**必须补齐权威 `gamedata.json` 条目（缺字段拒启动 exit -6）；若工厂注册在后续提交，**weight 先填 0**（哨兵前+非零权重+无工厂=生存随机抽中即空指针），注册后再解封。
4. **注册**：`GameDataManager.cpp` `#include` + `RegisterZombie(type, "ZOMBIE_X", ANIM_X, "ReanimName", &MakeZombie<T>)`——animName 必须与 resources.xml 的 `<Reanimation name>` 一致。
5. **gamedata.json**：只改 `build/clang-release/resources/gamedata.json`，`{weight, appearWave, survivalRound, offset, scale}` 五字段缺一不可；只能被召唤的僵尸 `weight: 0`（永不被抽中，AutoTest spawn_zombie 仍可直造）。注意 weight 一物两用=抽中权重+生存点数成本。
6. **粒子**：照抄 `ZombieHeadOff.xml` 改 `<Name>`+`<Image>`（图键=贴图文件名的标准派生键，如 `ZombieDancerHead.png`→`PARTICLE_ZOMBIEDANCERHEAD`），放权威 `build/clang-release/resources/particles/config/`，其他 preset 自动共享。新粒子专用 PNG 还必须登记进 `resources.xml` 的 `<ParticleTextures>`；只有文件和 manifest 不会加载出 `PARTICLE_*` 键。XML 标签全参考/foot-guns 见 **adding-particle skill**（勿再读 ParticleSystem 源码）。
7. **换色变体资源**：优先用仓库内 PowerShell + `System.Drawing` 脚本按 HSV/亮度映射目标材质，保留原 Alpha、阴影、高光、描边和非目标部件；不要对整张图平涂或只靠 overlay。脚本是可复现源，只向 clang-release 权威资源生成一次。先把 reanim 全部 `<i>` 引用建立源→目标表，尤其逐张处理阶段合成图；空间/低饱和度遮罩必须在原分辨率与原图并排检查，防止把眼白、灯泡、牙齿等一起染色，**视觉检查通过后**才把最终 SHA-256 写回脚本并复跑锁定。批量替换 reanim 键必须按完整 token 或最长名称优先，禁止让短前缀误命中共享长键（如 `..._BASKET` 把未换色的 `..._BASKETBALL` 一并改名）；生成后列出全部新 `IMAGE_REANIM_*` 引用并检查启动日志无缺图 WARN。换色后还要沿死亡/受击入口检查粒子 XML 的每个车辆或身体部件 `<Image>`：本体 reanim 换色不会自动替换粒子里写死的普通资源键。**仅存在于 `image/reanim/` 但未被 reanim XML 引用的受损帽、残肢等运行时换图，manifest 驱动的启动扫描会生成文件标准键 `IMAGE_<UPPERCASE_STEM>`，不是 `IMAGE_REANIM_*`；后者只由 reanim loader 为时间线实际引用的图片建立。** 用 `GetTexture(key, false)` 导出加载断言，同时覆盖正常换图和读档重建。同一 reanim 只替换头部等分阶段部件时，把材质选择收敛到父类按伤势阶段查询的虚入口，并让 Setup、实时受伤、`ZombieItemUpdate()`/Load 共用；健康、轻伤、重伤逐档断言，避免初始换色在重伤换图或读档后退回父类颜色。派生换色品种的断肢应由父类虚入口同时选择“本体残留材质”和“飞出粒子效果”，并让 `ZombieItemUpdate()` 复用同一材质入口，避免受伤或读档时短暂变回普通配色。
   - **新增标志性部件不能退化成平涂矩形或儿童画轮廓**：先在 4× 工作分辨率沿既有材质语言补壳体厚度、倒角、铆钉、玻璃高光、内部层次、线缆与磨损，再高质量缩回最终贴图；细节取舍以游戏内约 40～100 px 合成尺度仍能辨认的轮廓、明暗层级和一两个身份锚点为准，不能只验高分辨率母图。生成脚本保留 Alpha、描边与阴影，并用夜间背景同步截图检查最终合成。
8. **⚠️ build/ 下资源提交必须 `git add -f`**——被 .gitignore 静默挡下，`git commit` 照样"成功"但文件没进去。提交后 `git show --stat` 核对文件数。
9. **图鉴**：在权威 `build/clang-release/resources/info.txt` 同时添加 `[ZOMBIE_X]` 与 `[ZOMBIE_X_DESCRIPTION]`。`ZombieAlmanacScene` 按 `mAdventureLevel - 1` 之前已通关关卡的 `spawnlists.json` 并集解锁条目，并按首次遭遇顺序排列；当前正在玩的关卡不得提前泄露。召唤型 `weight: 0` 子单位（如伴舞）不能为了图鉴解锁写进随机池，而应由图鉴的“必然派生遭遇”映射随其召唤者解锁；固定 BOSS/关卡槽位同样不应伪造随机池权重，而要在对应关卡通关边沿按确定性遭遇映射加入。概率变异不能由 spawnlist 推断；若要求实际遇见后永久解锁，把独立遭遇标记存入 `PlayerInfo.json`，且只在正式波次的实际类型成功创建后记录，不能在 roll 命中、通用 `CreateZombie()`、读档或预览路径记录。缺 info key 不会构建失败，只会留下有图无标题/正文的空白条目；因此静态检查每个可解锁枚举名的两枚 key 均存在、非空且唯一。AutoTest 用 `set_adventure_level` 配合 UI 场景状态字段 `zombieAlmanacEntries` / `zombieAlmanacSelected`，同时断言当前关排除、下一关解锁并截图；AutoTest 会短路真实 PlayerInfo 磁盘写入，遭遇持久化须用内存字段断言加保存/加载源码审查。

## 冒险出怪编排

修改 `spawnlists.json` 时完整遵循 [references/adventure-spawnlist-pacing.md](references/adventure-spawnlist-pacing.md)。核心不是“把新僵尸塞进一个可生成关卡”，而是围绕玩家在**关卡开始时**已有的植物，给重点敌人安排独立教学、无同场复习和最终综合，并用精简池保证重点敌人的实际抽中率与选卡预览可读性。

- **未定 BOSS 只登记关卡槽位**：在 `AdventureProgression` 用 `BossSlot::RESERVED` 标记关卡性质，背景映射继续独立决定；禁止为了“先占位”把现有 `ZOMBIE_BOSS`、其他普通僵尸或伪造枚举写进出怪表。等主人明确身份、机制与投放时，再把槽位升级为具体契约并补正式生成、存档和 AutoTest。
- **常驻 BOSS 血条属于场景表现，不复制战斗状态**：`GameScene` 每帧从 Board 当前有效实体派生可见性、当前/最大生命与阶段阈值；阶段阈值由 BOSS 暴露语义 getter，禁止 UI 再写一套魔数。热路径查找不得创建临时僵尸向量，可增加无分配的 `EntityRegistry` 语义查询或缓存实体 ID，并排除预览、垂死和已死亡对象。血条本身无需入档，实体恢复后自然重建；AutoTest 至少锁定出场前隐藏、正式最终波出场、满血与跨阶段比例/标线、快照往返、致死隐藏，并用同步截图校准是否遮挡最下路与底部关卡信息。
- **稀有僵尸的锁定信息属于派生场景表现**：威胁线、目标名或阶段提示只在 Board 仍能解析出有效锁定实体时绘制；未锁定状态连占位文案和对应面板高度都移除，禁止常驻“未锁定”泄露未来机制或遮挡战场。展示每帧消费 Board 语义 getter，不复制锁定 ID、生命或存档字段；专项用锁定前后状态投影和同步截图同时确认文字与底板高度。

## 断肢 / 断头（每个 reanim 单独定案，先问主人）

- 覆写 `ArmDrop()/HeadDrop()`（不调基类——基类隐藏的是普通僵尸轨道名）+ 基类阈值自动触发（臂≤2/3、头≤1/3，由 `mNeedDropArm/Head` 门控）。
- 无残肢轨道的 reanim：藏 `outerarm_lower`+`outerarm_hand`、保 `outerarm_upper` 当残端、**不换材质**（disco 伴舞式）；有 `_bone`/`UPPER2` 的才做显示残肢/换图。
- 同一语义部件可能按动作烘焙成多套独立轨道（雪橇队员的 `outerarm_lower/hand` 与 `outerarm_lowereating/handeating` 实证）；逐片段审计走路、啃食和其他稳态使用的全部部件轨，把隐藏与残端换图收敛到同一 helper，并在 `OnStartEating`/`PlayWalkAnimation` 切轨后按当前断肢状态重放，禁止只隐藏当前最常见的一套轨道。
- 断头隐藏头部组全体**含挂件**（hair/earing/tongue…逐 reanim 数）。
- 主人指定头部挂件“随头一起飞”时，把头与挂件预合成为一张专属粒子贴图并只发一颗粒子；`HeadDrop()` 在隐藏头部组前读取头轨世界锚点，再同步隐藏挂件轨。不要用两颗独立随机粒子冒充固定连接，否则旋转和弹道会立刻错位。
- **`ZombieItemUpdate()` 与 Arm/HeadDrop 的轨道操作严格一致**（读档重建残肢的唯一路径，漏一轨=读档后幽灵部件）。

## 僵尸专属心智清单

- **走路权威**：reanim 无 `anim_walk2` 必须覆写 `PlayWalkAnimation`（啃完回走/读档全经它）；啃食视觉残留用 `OnStartEating/OnStopEating` 对称钩子；永不覆写 `ResumeWalkAfterEat`。
- **逻辑库存与美术槽位必须分离**：弹药、装备或召唤次数可高于 reanim 烘焙的可见槽位数；高库存阶段保持全部槽位显示，只在剩余量进入可见槽位范围后逐个隐藏，禁止复制轨道冒充更多库存。逻辑上限统一供 Setup 默认值、成员默认值和 Load 钳位使用；调高后同步断言初值、首个扣减、存档往返、进入可见阈值和耗尽总伤害。
- **啃食层级必须复刻 C# `CanTargetPlant(Chew)`，不能无条件认物理顶层**：`EatingOrder` 的上层只有在自身仍可成为目标时才遮挡下层；倭瓜 `NotOnGround()`、被吊起、压扁或其他 `CanBeEaten=false` 上层都应让同格花盆/睡莲继续成为候选。碰撞回调收到支撑层时，先验证上层的啃食资格再迁移目标；当前目标校验也必须判断“最高有效层”，不能只比较 `GetTopPlantAt` 指针。否则会每帧先判目标失效并恢复走路、随后又从支撑层碰撞重播啃食，表现为动画冻结在同一帧但 X 持续移动。
- **巨人锤击必须逐层派发植物自有反应**：命中帧先快照 `overlay/pumpkin/normal/under`，再对仍活动的每层调用 `Plant::ResolveGargantuarSmash()`；禁止在巨人类按植物类型判断。基类默认压扁，正在引爆的樱桃/辣椒/清醒毁灭菇由植物立即走正式爆炸，清醒寒冰菇立即走正式冻结结算并跳过剩余动画；索敌后的倭瓜忽略锤击但保持完整自身动画，睡眠毁灭菇与寒冰菇仍压扁。任一层的忽略或即时结算都不得阻止花盆等其他快照层接收锤击。随机动画倍率下不要靠固定秒数命中；AutoTest 用只推进到既有第 93 帧事件前的夹具，仍让目标快照、植物反应和命中音画走正式路径，并回归读档后的普通压扁与魅惑中断。
- **明确命中整格的逐格威胁必须结算全部植物层**：通过 Board 的整格访问入口先快照 `overlay/pumpkin/normal/under`，再让每个仍活动层通过植物语义伤害入口消费同一份本格伤害；通用整格效果可复用 `ForEachActivePlantInCell` 传入动作，带拦截和传播语义的威胁仍应保留窄专用入口，禁止退化成 `GetTopPlantAt` 或“普通层不存在才取顶层”。基础伤害由威胁拥有，植物只返回后续传播语义；接口必须明确多个响应是倍率相乘还是取最强上限，后者用 `min(current, cap)`，不能默认连乘成指数减伤。只在逐格结算伤害时统一取整，禁止在植物侧复制基础伤害或提前整数除法。锚定等传播响应在伤害前选定，使致死当前命中仍能生效，但它改变的传播值只从后续格生效，不能让当前格其他层提前减伤。专项同时断言多提供者组合、响应整数投影和真实后续格扣血，避免只改一侧后假绿。咖啡豆等通常免疫地面伤害的覆盖层若被规格明确纳入，用按冲击类别的窄虚入口声明例外，攻击者侧不得判断植物类型。
- **入水/出水反馈只绑定真实介质边沿**：通用僵尸以决定 `mInPool` 的同一对探针中点和水面裁剪底线作为水花世界锚点；C# `PoolSplash` 是一次性 `Splash.reanim` + `PlantingPool` 水滴两层，必须分别创建并按入水/出水选择 Foley。首次生成在水中、预览与读档恢复只静默同步介质，禁止伪造跨界声画；海豚等自管入水动作在 C# 进度节点调用共用水花视觉，动作结束提交 `mInPool` 时显式静默，避免末端重复一次。AutoTest 一负一正断言节点前计数 0、节点后两层各 1，并在快照重载后确认计数和声音请求都不再增加。
- **飞行/落地是命中层状态机，不只是视觉偏移**：由僵尸虚接口按当前 phase 声明空中层、地面层或过渡期不可命中，植物索敌与子弹碰撞都查询该接口；高低弹丸的层标记必须随对象池 `Reset()` 归零并入存档。飞行期同时禁用啃食、地面水池状态、冻结/黄油和断肢阈值，落地后再统一补结算；水道气球被击破按原版直接 `Die()`，不能先进入落地动画。飞行额外生命应在基类发光反馈后、普通防具/本体前由虚钩子消费，并参与全局生命倍率。专项至少覆盖空/地弹互斥、爆裂过渡、陆地落地、水道直接消失与存读档。
- **新增完全定身状态要审计全部派生 `Update()`**：基类在 `Zombie::Update()` 内早退只能停住基类移动/啃食，派生类在调用返回后仍可能继续倒计时、投掷或开盒。通用短控优先复用 `ApplyParalysis/IsParalyzed`，重复施加取更长余时、写入基类保护字段并统一收敛到 `IsImmobilized()`；永久免疫由 `CanBeParalyzed` 声明，地面危害的飞行/地下命中资格另走 `CanBeAffectedByGroundHazards`，伤害与控制免疫不得混成一个类型表。grep 所有覆写 `Update()` 的品种并在尚未离手的能力门禁前复用 `IsImmobilized` 或明确的 `IsParalyzed`；已经独立离手的攻击应在门禁前继续推进。中立环境麻痹可跨魅惑保留，死亡/掉头转死亡轨和派生直接死亡入口必须先清状态，损坏档不得给永久免疫品种恢复麻痹。专项至少锁定一个带派生倒计时的可定身品种，比较状态生效前后计时不再减少，并覆盖魅惑、死亡、免疫阶段与存读档。
- **受击白光必须按实际承伤层驱动**：禁止在 `TakeDamage` 分层前统一整身 `SetGlowingTimer`。原版本体/头盔/飞行额外生命共用本体计时器，报纸/铁门/梯子等二类护盾使用独立计时器和盾轨高亮；普通正面弹只伤盾就只闪盾，穿透或破盾溢出确实伤到后层才同时闪。所有 `Bullet` 的直接伤害统一走 `Zombie::TakeProjectileDamage`，按命中时 `velocityX` 与 `IsMovingRight()` 判断命中面：子弹与面向同向即从背后追上，完全绕过二类护盾并只闪后层；`velocityX=0` 保持正面口径。禁止按子弹类型或运动模式建**方向性**绕盾白名单，追踪弹须持续写回真实速度。弹丸自身能力若主动请求绕盾，必须通过同一入口的显式参数表达，并由目标侧 `BlocksProjectileShieldBypass` 虚接口按当前防具状态否决；方向背击优先保持原物理语义，目标否决不得顺带封死背击。`penetrateShield` 会让盾与后层同时承伤，不能用来冒充完全绕盾。围绕 `TakeExtraProtectionDamage`、`TakeShieldDamage`、`TakeHelmDamage`、`TakeBodyDamage` 的虚调用比较扣血前后值，避免派生覆写漏报；盾轨覆盖必须同时接入实例化与 `-NoInstance` 绘制路径。AutoTest 用 `hitFlashMask` 锁逻辑层、`renderedHitGlowMask` 锁实际轨道层，并同步截图检查铁门/报纸的正向、反向、主动绕盾、目标否决与静止弹。
- **灰烬致死若要求直接消失，不能只改 `CanBeCharred()`**：覆写 `TakePlantAshDamage()`，按词条缩放后的最终伤害与“本体 + 当前额外生命层”判断是否确实致死；致死直接 `Die()`，非致死继续 `TakeDamage(..., PLANT_ASH)`。同时覆写 `Charred()` 收口其他兼容调用，避免落地态仍生成烧焦残影。带额外生命层时不要简单放开飞行态 `CanBeCharred()`，因为通用调用方多只比较 `mBodyHealth`，会把本应剩血的目标误删。AutoTest 至少分别覆盖额外层仍在与落地后两态，并断言实体、`charredZombieCount` 和特殊爆裂音效。
- **高生命首领不能只提高 `mBodyHealth`**：逐项审计绕过数值耐久的统一入口。土豆雷会向 `TakePlantAshDamage(INT32_MAX)` 传直杀值，若需限制单次灰烬，应在该虚入口先压回基础上限再调用基类，以保留植物词条缩放。大嘴花的 `TakePlantInstantKill()` 只返回是否确实吞下；拒吞时由大嘴花把默认 20 点交给 `AdjustRejectedChomperBiteDamage()`，再走正式 `PLANT` 伤害链。未来拒吞品种默认不覆写调整入口；只有已有明确特殊数值的品种才覆写，不能让每个普通拒吞目标各自复制 20。巨人、红眼巨人和屋脊督军均拒吞并使用默认 20；持杆跳跳因高度咬不到，按装备状态将拒吞伤害调整为 0，失去弹跳器后恢复基类吞食。另按设计覆写 `CanBeCharmed()`、`ResistsTangleKelpDrowning()` 与 `CanBeKilledByMower()`；小推车免疫只跳过处决，车辆仍须正常启动、消耗并驶离。专项必须用真实植物/车辆覆盖每条入口，并以普通僵尸对照锁定默认直杀行为，同时回归已有特殊拒吞伤害。
- **静态贴图装备不要小题大做成子 Animator**：没有独立播放头、clip 或帧事件，只需跟随父轨仿射变换的帽子、甲片、铃舌等，使用 `Animator` 的命名 track follower。每个调用方提供稳定且唯一的槽名，并显式设置贴图、层级策略和可见性；同一父轨的多个 follower 保存在向量中，按插入顺序绘制，更新或移除一个槽不得覆盖其他槽。装备默认保留 `inheritOverlayEffect=true`，状态贴花才显式关闭。特别审计 `SetupZombie()` 之后基类 `Zombie::Start()` 还会配置黄油等 follower：专项必须从自然生成起检查装备已出现，再覆盖同轨多槽共存、状态覆盖、换损伤贴图、隐藏/脱落、快照重建，以及默认实例和 `-NoInstance` 两条路径。
- **同 reanim 独立附件**：螺旋桨等确实需要自己的播放头、clip 或帧事件的部件才实例化第二个 Animator、只播放附件 clip，再挂到主 Animator 的稳定锚点；附件 clip 必须清除主轨下发的 clip 速度覆写，但保留冻结/减速 extra 倍率。一个 Animator 的全部轨道共享同一播放头，生成或手写小 reanim 时每条轨道必须拥有相同总 `<t>` 数；短 marker 轨在切到后段 clip 后会被同一帧号越界索引，实例和慢路径都可能在 `Animator::DrawInternal*` 崩溃。生成器应在运行前解析并断言全轨等长，不能用渲染空指针早退掩盖坏资源。父锚点隐藏不会自动阻止附件绘制；仅把子 Animator 的 Alpha 设为 0 也不等于完全不可绘，父级受击 additive glow 仍可能留下幽灵轮廓。装备永久脱落且没有恢复路径时应 `DetachAnimator` 并释放强引用，AutoTest 同时断言子 Animator 已销毁并检查破甲瞬间截图；临时隐藏才显式同步全部绘制层与播放态。附件帧、播放态和宿主 phase 一起入档。
- **不移动阶段**：覆写 `ZombieMove` 按状态早退（PaperZombie gasp / 舞王 SNAPPING+HOLD 同款）。
- **入场后才施法的僵尸**：在进入停步前摇的入口检查 Board 最右列右缘（格中心加半格宽），使用逻辑位置，不用画面宽度或视觉偏移。准备计时到期但仍在场外时继续走路，不能先进入禁止移动的阶段再等待入场。专项同时覆盖边界外到期、场外快照往返及场内正常发动；旧能力测试中的场外静止施法夹具须移入场内。
- **特殊动作若优先于啃食，必须原子抢占双方状态**：进入动作前用基类窄 helper 同帧清 `mIsEating`、植物/僵尸目标 ID、目标植物 `mEaterCount` 并调用 `OnStopEating()`，但不要在 helper 内自动起播走路；调用者随后提交 phase 和指定动作轨。动作期间 `StartEat` 与 `ZombieMove` 都按 phase 早退，不能只让移动停住后继续由碰撞回调开吃。专项先让目标实际处于 `anim_eat`，再发布动作资格，下一帧同时断言目标 ID 为空、`eaterCount=0`、动作轨和原地 phase。
- **一次性动作不能只靠完成分支解锁**：放梯、投掷、开盒等阶段若让 `ZombieMove` 早退，必须在断头、死亡、魅惑等使动作失效的边沿原子清理目标/计时并恢复可移动稳态；魅惑后的派生撤销统一覆写 `OnMindControlled()`，该钩子在阵营、碰撞掩码和视觉提交完成后调用。死亡入口要让品种更新对 `mIsDying/mIsDead` 早退，避免旧动作重新覆盖死亡轨；`LoadExtraData` 也要自愈“终止状态 + 未完成动作”或动作 phase 与当前轨道不匹配的旧档组合。否则品种更新会因终止状态早退，移动又因动作阶段早退，形成双重死锁。
- **允许外部工具打断的动作由动作拥有者定义提交边界**：只在真正未提交的 phase 通过 `GetInterruptibleSpecialActionRemaining()` 返回非负余时，其他阶段返回负数；`InterruptUncommittedSpecialAction()` 必须在一个入口中撤销半成品对象、清计时/目标、恢复动画，并明确本次能力是可从完整前摇重试还是永久消费。已经离手的弹丸、地裂、公开干扰、完成墙体等独立结果不进入接口。外部植物或工具只按余时和稳定 ID 选唯一目标，禁止知道派生 phase；专项分别覆盖外部中断、自然终止、完成提交与读档修复，防止“状态已回退但半成品残留”或反向回滚已提交结果。
- **共享循环音效要有物种级所有权**：`AudioSystem` 的循环 key 是全局共享资源，一只实例直接 `StopLoopingSound` 会误停仍存活的同类。为品种维护静态引用计数，每实例用布尔值保证只申领/释放一次；只在正式出生钩子和 RUNNING 读档恢复时申领，在开盒/换态、掉头、死亡和析构时释放，计数归零才真正停止。Load 不得重播 boing/surprise/explosion 等一次性声音。AutoTest 至少断言循环实际播放状态与一次性请求计数；允许同品种并存时再造两只，验证一只退态后循环仍由另一只保持。
- **编队齐舞/同步动作**：动画速度必须 `SetAnimationSpeed(固定值)` 锁死——基类 `Start()` 给每僵尸随机 1.1~1.4，不锁必散拍。全队同步时钟用现成的 `Board::mBoardFrame`+`GetDanceBeatFrame()`（0~22 拍，12 逻辑步/拍，入存档），按拍映射轨道、缓存上次段位防每帧重播。
- **单个正式候选扩成多实体编队**：随机池、`weight`、首次登场和每波上限只登记可抽中的领队身份；唯一正式 resolver 接纳一次候选并扣一次编队预算后，领队等拿到稳定实体 ID 再创建随员，随员不得再次经过候选解析或重复计上限。`CreateZombieWithID` 只恢复存档逐只列出的成员，禁止自动补齐队伍。选卡/图鉴的候选语义仍是 1；若宣传画面需要展示完整编队，可显式创建 N 个无稳定 ID、无碰撞、无玩法注册的展示实体，并由对应预览容器逐一持有和销毁，绝不能复用正式随员生成入口。Board 预览每个展示实体的 `mZombieNumber++` 必须与一次基础 `Zombie::Die()` 严格平衡；整队死亡不得依赖已登记的 `memberIDs[0]` 才回收领队，否则单体预览或正式首帧死亡会留下幽灵计数。图鉴 `board=nullptr` 不参与计数，但切换条目也必须销毁整组展示对象。每名正式成员都保存 `role/slot/leaderID/memberIDs/phase`；运行时按稳定 ID 解引用，缺领队或缺槽位时跳过缺员并降级到可独立行动的安全 phase，禁止读档、阵亡或孤儿修复时复活/补召。专项至少锁定“一次候选=N 个正式实体、同波第二次候选被拒、预览候选=1 但展示槽位齐全、预览销毁后 `zombieCount==zombieNumber==0`、完整编队与缺员快照往返”；最终波零实体旧档还应验证计数归零并出现奖杯。
- **编队出界回收必须使用当前阶段的位置权威**：乘车、推车或其他附着编队若把后排成员的逻辑原点放在领队右侧，通用逐实体右边界会在自然出生区先 `Die()` 后排，再经队伍死亡联动误删整队。附着/落地阶段通过基类窄虚入口统一按领队 X 判断；损坏引用先走安全脱队，独立步行后恢复每名实体自己的出界回收。AutoTest 用正式自然出生 X，等待超过边界轮询周期后仍断言完整成员数和附着 phase，不能只等两帧。
- **累计释放上限必须绑定正式提交结果**：仅成功提交独立召唤事务才消费一次，前摇中断和无合法落点不得扣次数；封顶后停止进入前摇但保留普通移动与啃食。次数同时审计实体存档与钟匠窄能力快照；是否随时间锚回溯须按主人明确口径实现，不能默认为不可逆或漏存后复建归零。专项覆盖中断不扣、封顶往返，以及存活和死亡目标的时间锚恢复。
- **召唤僵尸**：`mBoard->CreateZombie(type, row, x)`（y 恒由 row 派生）；关联用 EntityRegistry 整型 ID（死亡自动失效）；**槽位有效性 = `GetZombie(id)` 非空 且 `IsMindControlled()` 与本体一致**——只判空则被魅惑的随从永远占位、补召失灵；行越界/永久不可用的槽要豁免，否则无限重触发召唤动作。持续补召必须把“最多维持数量”和“补召间隔”集中为匿名 namespace 可调常量，并明确计时使用哪种 delta：精英舞王实证为冻结暂停、减速按 scaled delta 拖慢，天气动画倍率不得重复加速召唤逻辑。
- **大规模血量文字不得重回动态整串纹理抖动**：受伤本体与防具行继续使用共享字形图集，并在 worker 录制期按原对象顺序写入实例；若压力场景需要优化满血共同路径，只能为 `current == max` 的稳定文本取得 pinned 共享纹理，动态数值必须立即回退字形路径，禁止把每个历史血量永久缓存。整行纹理上传前要裁掉四周全透明像素并保存原 surface 偏移，绘制时补回原点；默认 Vulkan 可在当前位置写一条 `InstanceRecord`，`-NoInstance`、OpenGL 和裁剪路径保留同序 batch。不能假设“实例更少必然更快”：未裁整行会增加透明片元，把一行拆成多张纹理也可能因采样局部性变差而退化，候选必须在同一存档比较 GPU 时间、fragment invocation 与稳定对象数。真实关卡存档的 AutoTest 必须显式用只读 `-AutoTestLoadSave`；小推车等事件会快速改变僵尸数时，只比较数量仍稳定的早期 60 帧窗口，并用 `smoke_zombie_hp_glyph` 的默认、`-NoInstance`、OpenGL 截图复核字距、基线、护具行和层序。
- **逐帧稀有品种查询禁止扫描全体僵尸**：血条、天气来源、地形光环等功能若每帧只关心一种或极少数品种，不得调用 `GetAllZombieIDs()` 后过滤，也不得在 `mZombies` 上写通用按类型全扫。优先在 `EntityRegistry` 维护该品种的 `ID → weak_ptr` 专用索引：普通生成和 `AddZombieWithID` 读档恢复两个入口都登记，同 ID 被其他类型覆盖时撤销，沿既有清理节奏删除过期弱引用；查询时只遍历稀有候选，并即时复核 `IsPreview/IsActive/IsDying/health` 等易变状态。需要“最小实体 ID”稳定语义时使用有序索引；需要同帧安全批量遍历时仿照黄色冰道生成 `shared_ptr` 快照；真正由 Board 唯一拥有的单例可保存实体 ID 并在读档后重建。只有查询集合本来就覆盖大量普通僵尸或按行移动频繁时，才用每帧惰性重建的行桶。交付时必须告诉主人所选索引、复杂度和所有维护入口，避免功能正确但压力场景退化。
- **专用品种索引是附加镜像，不是所有权迁移**：`TrackXxx` 只把同一个实例登记成 `weak_ptr`，不得从 `mZombies` 擦除或移动主 `shared_ptr`；全体遍历、`ForEachZombieInRow`、存档和碰撞仍以主表为全集。AutoTest 同时比较专用索引计数与按行遍历计数，防止优化悄悄改变可见实体集合。
- **按行裸指针桶必须在生命周期边沿立即失效**：`EntityRegistry::mZombiesByRow` 只为热路径缓存非拥有 `Zombie*`，唯一真相源仍是 `mZombies` 弱索引。运行期换行必须走 `Zombie::CommitRow()`，最终 `Die()` 必须在 GOM 延迟销毁前调用 `InvalidateZombieRowIndex()`；不能只依赖 Board 稍后的 `CleanupExpired()` 每帧兜底，因为下一帧 GOM 会先释放对象、较早更新的射手就可能虚调用悬空地址。`ForEachZombieInRow` 回调前还要复核 active/dying，以覆盖同帧前一个回调改变后续候选状态。`smoke_zombie_row_index_lifetime` 固定“先构建行桶、同帧杀两只、下一帧射手查询”的 UAF 窗口；换行专项沿用同一先查询后变更结构，防止堆布局变化把错误偶然隐藏。
- **历史范围召唤池必须逐项显式列举**：规格写“某大关以前所有僵尸”时，禁止遍历 `[0, NUM_ZOMBIE_TYPES)` 或复用会继续扩张的注册表；把当时允许的基础、精英和必然派生子单位逐项列入固定数组，并用 AutoTest 分别锁定允许的边界类型与下一大关/首领/特殊禁入类型。实际抽取再按目标行调用 `Board::CanSpawnZombieInRow` 过滤，历史白名单包含泳池形态不等于能把它生成到屋顶。未来新增枚举不得无意进入旧首领召唤池。
- **残血召唤压迫必须同时提高质量**：只缩短间隔或增加数量仍可能连续抽到低威胁杂兵。把历史白名单显式拆成标准/高威胁子池，由当前生命等权威阶段状态派生高威胁概率，不另存易漂移字段；若最终阶段规格要求硬压制，就让概率达到 100%，而不是保留随机放水。AutoTest 导出当前概率，并分别锁定满血、中段和最终阶段；最终阶段至少连续两批断言“高威胁数=实际生成数”，避免单批固定 Seed 假绿。
- **啃食中仍施法的派生品种只补一次早退逻辑**：`Zombie::Update()` 在通用状态、目标校验和地形同步后会因 `mIsEating` 早退。若规格要求啃食时继续召唤/施法，派生 `Update()` 先记录 `wasEating`、调用基类，再仅在 `wasEating && mIsEating` 且活动、未死亡、未定身、未被水草束缚/大蒜暂停时以同一减速时间基准补调一次 `ZombieUpdate`；若基类本帧已停止啃食，它已经走过正常派生更新，禁止再次调用。施法不得抢占 `anim_eat`，专项同时断言啃食轨道、伤害帧、施法次数与快照往返。
- **跳跃阻拦要拆分职责、动画时序和受伤对象**：阻拦植物通过虚接口声明“能挡哪类跳跃”并拥有 Bonk/粒子反馈；接触回调只锁定当前格顶层目标并起播跳跃，必须到 C#/规格给出的动画进度节点才查询一次，禁止一碰植物就提前阻拦。起跳入口必须完整复刻 C#/规格的资格，尤其不能让已经掉头、正在死亡或已失活的僵尸新提交跳跃；无头流血计时不会因跳跃暂停，漏掉 `mHasHead` 会表现成“刚落地就消失”。跳跃一旦合法提交，之后受致命伤应让死亡轨接管而不是回滚动作；落地回调也要拒绝覆盖 `mIsDying/mIsDead/!mIsActive`。阻拦查询不能复用啃食顶层：须按格内层级逐层询问能力，让非阻拦南瓜继续向内找到高坚果；品种跳距超过基类时还要按起跳碰撞框到完整落地碰撞框的扫掠区，沿移动方向选择最先遇到的阻拦者，不能只复查起跳目标 ID，否则会越过后方高坚果。仅按进度检查不需要新增 `AddFrameEvent`；起跳 X、目标 ID、是否已检查和额外根位移须入档，读档恢复原动画帧继续判定，不能直接落地绕过阻拦。跳跃计时必须明确使用真实 delta 还是寒冰后的 scaled delta；若某半程按独立倍率加速，额外根位移必须消费同一时间基准和倍率，且不得把已缩放的 delta 再乘 Animator extra 倍率造成重复减速。被挡时先撤回品种已补的额外位移，再把碰撞框落到实际阻拦者迎敌面，恢复碰撞/阴影、弃杆或落地、切稳态并开始啃食，最后把实际阻拦植物传给派生钩子结算召唤或撞击。**规格写“给 A N 点伤害”先确认 A 是植物还是跳跃者，禁止把碰撞伤害凭感觉记到自身**；常规僵尸对植物伤害走 `Plant::TakeDamage(N, DamageSource::ZOMBIE)` 以统一消费僵尸增伤与植物韧性，只有主人明确要求最终固定扣血才另设不缩放入口。若要求被挡后仍召唤，先创建召唤物再伤害目标。AutoTest 必须同时断言节点前 `JUMPING/anim_jump`、无 Bonk/粒子/扣血，节点后才出现阻拦终态和派生效果，并覆盖“阻拦体外套非阻拦壳”“长跳初始普通植物后还有阻拦体”“接触前掉头不得起跳”和“跳跃中致命伤保持死亡轨”。
- **手动开吃不能依赖碰撞退出收尾**：跳跃受阻等状态机可能把僵尸停在植物碰撞箱外的小间隙后直接调用 `StartEat`，这对对象从未进入 `CollisionSystem::currentCollisions`，外力吹离时不会产生 `onTriggerExit`。基类必须逐帧复核已保存的植物目标仍存活、仍是同格顶层且碰撞箱间距仍在允许咬合范围；失效时原子清目标 ID、平衡 `mEaterCount`、调用 `OnStopEating` 并经 `PlayWalkAnimation` 恢复。进入死亡轨道前也要先清啃食状态，`EatTarget` 对垂死者硬早退。AutoTest 同时断言吹离、目标死亡、啃食者死亡三条路径的 `isEating=false`、目标 ID 为空和 `eaterCount=0`。
- **魅惑交互**：`StartMindControlled` 非虚，派生类通过 `OnMindControlled()` 接收阵营已经提交完成的单次回调；正在抑制移动的动作在这里原子撤销，禁止继续用 `ZombieUpdate` 边沿布尔量复制钩子语义。魅惑领队后新召唤单位补调 `StartMindControlled()` 继承阵营；若召唤物配置接口会先魅惑再切飞行态，先调用该入口再提交不可魅惑 phase。魅惑者互啃敌方是引擎既有行为，编队混战减员属正常。
- **投掷召唤物的离手事件必须先成功创建、后消费库存**：持有标志是背部/手中子单位显隐与能否再次投掷的唯一权威；创建失败保持库存和轨道，创建成功后再配置阵营、飞行参数与剩余减速，并最后清标志。巨人等投手保存动作 phase、是否已经越过离手帧、投掷距离和唯一持有标志；召唤物保存飞行/落地 phase、高度、水平/竖直速度与方向。读档分别覆盖离手前、离手后但动作未完和动作完成，禁止从现场是否存在召唤物反推库存。原版离手动作若是 `PlayOnceAndHold`，必须用一次性播放并在剪辑末帧停住；`PlayTrack` 会强制 `PLAY_REPEAT`，当物理飞行长于剪辑时回绕首帧会造成空中回弹。旧档缺 `animPlayState` 而按循环恢复时，应保留当前帧只修播放状态，禁止重新起播。按世界 X 分界且只允许在一侧起手时，触发距离必须保留相对分界线的符号，禁止取绝对值后让单位越线越远反而重新满足条件；AutoTest 在分界线两侧各放一只半血静止投手，分别锁定允许起手与持续禁投。只抬高离手高度会延长重力飞行并带偏水平落点；若规格只要求视觉起点上抬，应先用旧高度和旧初速解出原落地时刻，再按新高度反算竖直初速，保持飞行总时长、水平速度和落点不变。若还明确要求水平距离乘倍率且水平速度不变，必须把“倍率后的落点仍位于哪些地图格”写成合同，再把原落地时长乘同一倍率作为新目标时长并结合新高度反算竖直初速；禁止无落点断言地盲乘完整飞行时长，因为屋顶的额外距离修正可能掩盖草地越过第一格的错误。AutoTest 用网格相对投影锁定落地列，并覆盖至少一个无屋顶修正的地图；屋顶与非屋顶公式分叉时两者都要覆盖。
- **不掉头的僵尸不要复用普通无头死亡阈值**：关闭 `mNeedDropHead/mNeedDropArm` 后，按品种规格在本体真正归零时启动死亡轨；生命仍大于 0 时继续完整行动。任何强制处决入口都应先清空统一可计生命，再交给品种自己的本体伤害/死亡入口接管动作中断、碰撞体和死亡轨；禁止对这类品种无条件调用普通 `ArmDrop/HeadDrop`，否则会混入错误断肢贴图。受伤换图若只由当前生命比例决定，读档直接重建材质，不额外保存易矛盾的伤势阶段字段。专项用处决后专属死亡轨、保留头臂标志和同步截图锁定品种表现。
- **魅惑范围伤害按阵营对称过滤**：僵尸自身发起的爆炸或范围伤害若应攻击敌方，统一用 `target->IsMindControlled() != source->IsMindControlled()` 判敌，禁止只在来源已魅惑时跳过魅惑目标，否则未魅惑来源会误伤普通僵尸。AutoTest 的未魅惑与魅惑两侧都同时放普通僵尸、魅惑僵尸和植物，先证明敌方目标实际受击，再断言同阵营与植物是否按设计保留。
- **僵尸临时持有植物必须建立双向关系和三层绘制契约**：植物保存持有者实体 ID、抓取/离地状态与视觉偏移；抓取起禁用行为、承伤、啃食资格、碰撞和显式阴影附件，离地后跳过植物常规 `Draw()`，由僵尸在“后层身体 → `Plant::DrawAsBungeeCargo` → 前臂专用 Animator”顺序提交，不能只调对象 draw order 期待跨对象夹层。僵尸保存目标格与植物 ID，`LoadExtraData()`/`ZombieItemUpdate()` 在实体恢复后重建关系、前臂显隐和双层影子；抓取未离地时僵尸死亡应释放植物并恢复原状态，已经离地则按能力规格结算植物。AutoTest 必须覆盖抓取中禁用、离地截图、双方快照往返、两阶段死亡和退出清理。
- **离体但仍由僵尸持有的延迟攻击要按投出瞬间锁定**：保存飞行起终点、已飞时间、目标行、下一次倒计时和投出时阵营；飞行更新必须放在冻结、掉头和死亡动画的新攻击门禁之前，使已经离手的攻击继续结算。投出时隐藏手持轨、落地后恢复，`LoadExtraData()` 与 `ZombieItemUpdate()` 都按飞行状态重建显隐；若设计要求投掷者被立即回收后仍保留攻击，则不能继续把投射物只存在僵尸对象内，必须改成独立实体。
- **范围攻击的贪心落点要按实际结算集合评分**：先从合法行/格或实体建立候选落点，再用与最终伤害完全相同的活动状态、阵营过滤、圆/碰撞框相交和组合植物拦截规则累计每个爆点覆盖目标的价值；位置倍率、经济产出预期等权重施加到每个受影响目标，而不是只看被瞄准单体或硬切目标优先级。新增南瓜等外壳或邻格保护后，先以原几何找出命中层，再通过 Board 唯一解析入口按逻辑范围选择保护者；重叠范围须稳定选择最近者并打破并列，命中外壳只选自己以阻断连锁，最后按保护者实体 ID 归并为每次攻击一次承伤。无保护者才保持原逐层伤害；不要只遍历全植物直接扣血，也不要让普通版本误接精英专属拦截。贪心与蒙特卡洛/轻量推演须保存层类型，并复用相同保护范围、选择和归并规则。无合法目标时不空投且用有界短间隔重试，最高分并列可随机择一。专项覆盖陆地、水路 under+normal+壳、多命中归并、重叠保护、无保护旧行为、倍率伤害和明确豁免的普通版本。
- **可复用的短视未来选点由 `Board` 采集、纯数值模块推演**：`Board` 是唯一读取 GameObject/当前卡槽/正式 `CanPlantAt` 的边界，快照记录当前敌方僵尸的真实行、X、移速、本体/头盔/护盾生命与攻击力，以及玩家实际已选卡、冷却、费用和 gamedata 植物画像；已有交互不能只存 `isEating` 等布尔量，必须用实体 ID 带入当前啃食目标等精确关系，否则简化几何会把正式状态误判成尚未接触。推演器不得按僵尸类型写 `switch`，只用能力维度固定预算推进；需要让时域外的未完成交互参与决策时，可在终点用剩余生命、合并后的交互速率和有界权重结算一次廉价终局分，而不是延长完整逐步模拟。候选与无攻击基线共用 rollout seed，并使用局部 RNG，禁止消费 `GameRandom`；诊断状态应单独导出终局分差，便于确认决策来自协同而非噪声。总开关放 `GameAPP` 且旧档默认开启，关闭或推演失败必须保留原确定性/贪心策略；AutoTest 同时锁定开启时的 rollout/候选/僵尸/卡槽数量、关闭时确实走回退，并用一例“协同改变目标”和一例“更高即时收益仍胜出”约束终局权重。
- **普通支撑植物不得挤占详细植物预算**：由植物 gamedata 的 `simulation.supportOnly` 声明普通花盆/睡莲；Board 按稳定实体 ID 把它们写入独立、每格至多一项的支撑数组，完整保留 ID、生命、战略价值、碰撞框与啃食资格。详细植物维持 128 株容量，支撑层按棋盘格硬限 64；避雷花盆等带特殊推演能力的 under 植物保持完整画像。纯数值推演中的范围伤害、蹦极单株移除、当前锁定啃食和终局阻挡价值都必须同时消费两类数组，并以 `pumpkin > normal > under` 而非实体创建顺序解析同格重新索敌；不能用“under 全部忽略”的快捷分支。当前模型不表达“未来先种支撑、再种宿主”的两步占格，因此 `supportOnly` 卡牌不进入未来种植候选。
- **蒙特卡洛的单株移除必须按实体而非爆炸半径表达**：候选携带目标植物 ID，纯数值推演在时间线起点只删除该实体；`Board` 负责按正式组合植物优先级为每格选出实际会被带走的一层，并过滤已被其他实例预订的 ID/格。多个候选最高分并列时用局部 seeded RNG 随机，不得消费正式 `GameRandom`。若总开关关闭，必须走该品种原版选择算法（例如蹦极的“有植物格 10000、空格 1”加权随机），禁止把现有贪心回退误当所有品种的统一原版行为；专项以同一 Seed 分别锁定开启/关闭的模式、目标与 rollout 数。
- **控制免疫使用基类能力维度，不按品种散落判断**：临时免疫通过 `ZombieControlEffect` 位、独立计时与 `GrantControlImmunity()` 发放；派生类的固有免控只覆写永久 mask。所有入口分别守卫 `SLOW/FROZEN/BUTTER/PARALYSIS`，发放时只清除 mask 覆盖的既有状态，计时按游戏时间推进并进入僵尸存档；装备触发后授予的免控属于本体，除非规格明确，否则装备掉落不得提前取消。一次性范围发放在能力结算边沿按稳定 ID 快照，用碰撞箱中心和平方距离复核半径、阵营及活动资格；每个目标独立领取计时，随后离域、来源掉装或死亡不得反向取消。对应蒙特卡洛必须使用预计结算时的位置、相同半径和阵营过滤比较群体收益，不能继续只强化来源自身。寒冰菇的固定伤害、冻结和减速尾巴是三项独立语义：只免冻结时仍受伤且仍减速；黄油弹也应先结算命中伤害，再由 `ApplyButter()` 决定是否定身。`CanBeChilled()` 仍是减速状态、蓝色覆色和减速音效的共同前置总闸；寒冰子弹必须先检查它再播放 `SOUND_COOLDOWNZOMBIE`，避免“没减速却有音效”。蒙特卡洛快照必须同时带入临时余时和永久 mask 的有效结果。AutoTest 覆盖清除既有控制、未免疫类型保留、范围内外与阵营边界、伤害与控制拆分、装备掉落、离域、计时存读档和到期恢复，并用普通僵尸作对照。
- **车辆/精英变体的特殊受击**：让车辆基类拥有虚事件（如 `HandleCaltropHit`），植物只命中并派发；普通车辆在默认实现里处理植物消耗、音画和死亡，精英车辆覆写生存规则，避免植物侧 `dynamic_cast` 到每个精英类型。若特殊死亡播放的是 wheelie/bounce 等非通用 `anim_death` 轨道，不要设置会被基类死亡轨看门狗消费的通用 dying 标志；用独立状态+计时器守卫 `ZombieMove`、碾压和继续承伤，存档保存状态/剩余时间，Load 和 `ZombieItemUpdate` 重新应用停驶、碰撞禁用及材质终态。
- **无 `anim_*` 剪辑标记的专属残骸要播放完整默认时间线**：把残骸做成独立 `AnimatedObject`，`SetFrameRangeToDefault()` 后从 0 帧 `PLAY_ONCE`，在主人给定的全时间线帧注册自身回收事件；禁止 `PlayTrack` 一个资源里不存在的 `anim_crumble`，也不要让残骸寿命延迟原僵尸本体死亡。专项分别断言本体同帧消失、残骸只剩一份、指定帧后残骸归零，并确认灰烬入口不叠普通爆炸。
- **特定植物攻击抗性**：由 `Zombie` 基类提供语义窄的虚修正点，特殊品种按当前防具/状态覆写；子弹只向目标查询，禁止在子弹侧堆类型表或 `dynamic_cast`。若攻击先按倍速累计“每帧总基础伤害”、再拆成多个 `TakeDamage(1)`，目标修正必须发生在累计之前，普通 `AdjustIncomingDamage` 单击上限无法把整帧压低。防具限定抗性在防具掉落后必须返回输入原值，专项同时锁定有/无防具两态。
- **按植物谱系适应或免疫时必须携带显式来源身份**：`DamageSource` 和共享 `BulletType` 都不足以表达原发射植物；复用 `PlantDamageOrigin`，弹丸从 `Board::CreatePlantBullet` 在发射边沿锁定 `FromPlant(mPlantType)`，直伤/范围伤/持续伤在能力提交边沿显式传同一值，真正灰烬才传 `Ash()`。目标只通过 `BlocksPlantDamage` / `TryAdaptHelmetToPlantDamage` 等窄接口消费，禁止从弹型、贴图、粒子或内部 `DamageSource::PLANT_ASH` 猜玩家语义。火炬树桩等运行时转换只改变当前弹型与命中语义，来源仍属于原发射植物；来源必须随在途存档恢复，并在对象池 `Reset()` 归零。基础/紫卡谱系、跨植物类别、状态是否保留仍按主人逐项定案；专项至少覆盖转换前后来源不变、在途快照、池槽复用，以及数值免疫后状态的独立结果。
- **防具伤害倍率与溢出必须使用同一原始伤害口径**：若湿润等状态只放大一类防具承伤，覆写来源感知的防具入口，并返回“未被防具消费的原始伤害”，不能把倍率后的负生命直接溢出本体。固定环境伤害若规格要求只碎甲，则把输入截断到当前防具生命并禁止溢出；专项至少覆盖差一血破甲、本体不受固定伤、普通植物破甲后按原始余量进本体和小数余量存档。
- **独立破层值由目标当前层消费且禁止溢出**：盐蚀、破冰等不属于普通直击伤害的数值由 `Zombie` 语义窄虚入口接收，默认目标 no-op；拥有冰制护甲/墙体的品种只扣当前冰层并在零处截断，余量不得换算成本体伤害，弹丸侧也不得维护品种表。普通直击仍走原伤害链，两者在 AutoTest 分别导出并断言。主动干扰寒潮预报的品种只在正式动作提交边沿调用 Board 的单一干扰入口，由 Board 通知植物并保存本轮失效态；僵尸不扫描植物、不清空空中弹，也不复制预报计时。
- **可被植物剥离的装备由僵尸拥有契约**：在 `Zombie` 提供成对的资格查询与原子剥离虚接口，返回当前损伤阶段贴图、装备轨道世界起点和目标偏移，再由品种切到正式无装备 phase/显隐/速度/循环声终态；植物侧禁止识别具体僵尸类型。剥离不得调用会喷掉落粒子或触发范围伤害的派生 `HelmDrop/ShieldDrop`，应只复用无副作用的基类层清理并显式重建品种终态。精英或核心能力变体用资格覆写免疫，不在植物侧加黑名单。C# `MagnetItem.mDestOffset` 是未缩放贴图左上角；若植物侧保存的是绘制中心，必须用每张贴图的缩放后半宽/半高换算，不能让所有装备共用固定补偿。AutoTest 覆盖普通/免疫对照、损伤贴图、装备显隐、能力取消、循环声、离体物与双方存档往返。
- **剥离反噬随 `MagneticItem` 一起原子返回**：装备若会伤害提取植物，在返回结构中用默认 0 的通用字段表达；磁力菇必须先提交吸取状态和离体物，再直接扣自身本体生命。这样即使反噬致死，目标装备也不会复原；直接扣血是否绕过南瓜/词条由规格明确，不能把反噬伪装成僵尸攻击。专项覆盖第一次精确扣血、充能/离体物存档和下一次吸取致死时第二件装备仍被卸除。
- **僵尸部署且供全体共享的格对象必须归 Board 所有**：扶梯、路障式通路等对象用轻量 `GameObject` 表现、`GameObjectManager` 持所有权、Board 持 weak_ptr 并提供唯一格查询/添加/移除接口；绘制锚点从当前 `GetCellCenterPosition/GetCellHeight` 换算，不照抄 C# 800×600 绝对点。共享移动瞬态（攀爬/下落高度、已用列）放在 `Zombie` 基类并入档，特殊移动品种通过现有阶段能力门禁拒绝；撑杆/海豚等自管接触回调必须在起跳判定前先查共享通路。C# 单目标轮询改成多碰撞回调时，停止啃食/能力前必须确认当前动作目标与本次回调对象同实体或同格；已爬过的相邻旧通路只能跳过自身宿主，禁止取消下一格目标并每帧重播走路。对象自身用 Board 可选数组入档，旧档缺字段为空；植物死亡/压扁、行级清除和磁吸等外部生命周期统一调用 Board 接口，禁止各方直接持对象裸指针。原版 `KillAllZombiesInRadius` 对僵尸按像素圆命中，却按爆心所在格的方形 `rowRange` 清扶梯：樱桃/玉米炮为 ±1 格，毁灭菇为 ±3 格；该外部结算必须复用 Board 入口，并分别断言范围内非宿主格清除与范围外保留，避免植物自身死亡清宿主格造成假绿。若格对象附着在可被台风搬运的植物组合上，必须在 Board 逐格事务中与 Cell 同帧换格，并直接消费宿主植物的二维视觉追赶偏移；阻挡留源格，出界/弹坑沿死亡链移除。AutoTest 用显式格对象夹具分别锁定普通单位、特殊起跳单位、相邻两格碰撞重叠期内的目标状态/动画、移除中下落、外部吸取、台风中段零偏移误差和双方快照往返。
- **能力驱动的装备换色必须保留损伤阶段并覆盖全部视觉终态**：父类提供按当前能力/阶段选择材质、已部署样式和掉落效果的窄虚入口；能力切换只重放现有 `damage0/1/2` 映射，禁止重置护盾生命或破损档位。携带轨道、已放置 Board 对象、磁吸离体物、破盾粒子和读档重建必须消费同一状态；Load 在能力字段恢复后再次应用材质入口。AutoTest 先断言初始样式，再分别锁定完整态与二段破损态切换、非命中分支不换色、部署/磁吸/掉落颜色以及双方快照往返。
- **车辆的场地范围与攻击范围必须分离**：多行铺路、速度场或其他地面覆盖由独立入口决定，植物碾压只通过 `CanCrushRow` 等攻击入口决定；禁止从铺路范围推导碾压范围。AutoTest 在同一列的本行和相邻行同时放植物，分别断言压扁状态，再独立断言各行场地状态，防止调整一项时误改另一项。
- **场外地面效果不能夹成边缘占格**：冰道世界左缘转列号时保留 `mColumns` 作为未覆盖棋盘的哨兵，不能把上界夹到 `mColumns - 1`。寿命已激活不等于已覆盖格子；普通与黄色冰道用 `extend_ice_trail` 固定左缘，通过正式 `assert_can_plant` 覆盖场外、采样边界两侧与存读档，避免移动时点影响边界断言。
- **手动位移车辆的速度合成**：车辆若不用基类走路位移，仍必须让动画与真实 X 位移消费同一组能力、寒冰、雨势、台风倍率；禁止只改 `Animator` 速度。场地增益必须逐因子变换再相乘，不能放大最终乘积；当前鎏金冰道契约为每层把加速倍率乘二（`1.4→2.8`）、减速倍率除二（`0.6→0.3`），中性 `1.0` 不变。重叠场地按仍存活且实际覆盖目标的独立来源逐层变换；进入、离开、来源死亡和范围缩短都要刷新，不能只缓存一个布尔值。若品种能力有最终上限，先保留原始能力因子供统一变换，再在品种覆写的有效能力入口钳位，避免为逆变换叠层而产生无法表达的边界。
- **稀有品种来源的热路径查询**：若每个目标每帧只需查询少量特殊僵尸来源，不要借通用行索引扫描整行后对每个候选 `dynamic_cast`。在 `EntityRegistry` 的所有新增/恢复入口维护按实体 ID 的品种专用弱索引，每帧首查生成强引用快照并在 `CleanupExpired` 释放；快照只缩小候选集，回调仍须复核同帧死亡/失活、当前行与精确几何覆盖。移动区间或多独立来源的最终层数仍应即时计算，不能缓存成布尔值或静态计数。
- **稀有的每实例状态优先冷热分离，但必须按真实总量验收**：先用目标工具链的 record layout 与代表性数量确认常驻字段确实显著，再把大数组、容器、回调或仅少数品种启用的附件移到首次生效才分配的侧车；高频资格查询需要的稳定 ID/小标志继续内联，不能为了缩 `sizeof` 让热路径多一次指针追逐。活跃元素用显式计数和紧凑前缀推进，未生效热路径必须 O(1) 早退。侧车不得变成任意组件系统，宿主仍独占状态与生命周期；Save/Load 保持原 JSON 字段与中性默认，只在读到有效状态时分配。到期、魅惑、死亡和孤儿恢复按各状态正式生命周期释放；若侧车持有计划复用的附件，可保留休眠分配，但必须隐藏/停用并计入真实总量。报告内存时同时列对象 `sizeof`、常见侧车、附件与分配开销，禁止只报缩小后的热对象或仅凭布局宣称 FPS 提升；专项至少覆盖未生效、满层刷新、到期或休眠、正式快照往返和倍速等价。
- **虚受伤入口可以同步结束宿主生命周期**：调用 `TakeDamage`、`TakeProjectileDamage` 或分层受伤虚函数后，不能假定 `this` 仍活动、可选侧车仍存在。投篮车等派生品种会在本体归零时直接 `Die()`，而死亡会立即释放毒素等侧车；调用方若还要更新层数、余量或附件，必须先重查 `IsActive()` 与对应拥有指针。专项用一种立即死亡车辆把生命压到下一次批量伤害可致死，再断言实体与副作用各结算一次且进程不崩溃。
- **可关闭的蒙特卡洛主动决策只放在动作边沿**：由 `Board` 一次采集实体、装备层、卡槽、已提交但未结算动作和确定的全局事件，纯数值模块用共同随机数比较全部合法候选与“不执行本次动作”基线，局部 RNG 禁止消费正式 `GameRandom`。候选若是“立即停机、延迟销毁”，必须从 t=0 禁用目标能力并按真实间隔/目标专属次数推进伤害，不能复用蹦极的立即移除近似；已经离膛或越过提交边沿的效果作为来源无关事件继续结算，尚未提交的能力则随来源停机取消。高操作玩家可控的范围能力应集中声明冷却、伤害和几何，由推演按命中数优先、有效收益次之与稳定 ID 选择默认落点，禁止在决策僵尸侧识别植物类型。详细实体数必须有共享硬上限；无上限范围效果把样本外对象折算成有界汇总量，不能改变正式结算数量。不同决策族可以共享实体硬上限，但 rollout 预算必须按各自时域、步数与候选规模使用独立可调常量；禁止为了调高短时域能力的精度而经同一个全局常量同步放大其他长时域推演。候选数会随防线密度增长的决策还要用“候选数 × rollout 数”总评估量封顶，候选少时保留完整样本数，避免错峰后单次推演仍在满防线形成尖峰。等待候选用有限延迟副本表达，累计等待和重试计时入档，达到上限后只比较立即动作；同收益严格偏好立即执行，等待必须靠真实未来收益胜出。总开关关闭、阵营模型不适用或推演失败时，原子回退该品种原有确定性/随机规则。性能验收不能只看60帧平均 FPS：用同步放开全部施法者的确定性压力夹具，并把快照与 rollout 分段计时，同时记录报告窗口调用次数和单次最大耗时；否则动作边沿尖峰会被 VSync 等待和窗口均值掩盖。多名施法者的同步峰值仍超预算时，在 `Board` 按稳定实体 ID 与固定逻辑步间隔发放推演名额，间隔至少覆盖一次渲染帧允许追赶的最大固定步数，未领取者保持动作就绪后续再试；禁止改按渲染帧发放而让逻辑时序随机器性能漂移。AutoTest 同时导出决策模式、动作、rollout/候选/样本计数，覆盖开关两路、等待读档、同步压力和共享上限；纯数值单测另锁定关键事件对收益的改变。
- **天气条件变异**：同时使用 `adding-rain-weather`。`spawnlists.json` 与波次点数预算只放基础类型，正式生成路径在扣点前经唯一 resolver 决定实际变异类型；`CreateZombie`/`spawn_zombie` 保持直造确定性。每波上限只在推进新波时清零，不能被天气切换重置；已生成数必须入存档，`weight: 0` 的变异体不得独立进入随机池。
- **无尽候选池的品种排除必须只收窄候选池资格**：把明确禁入类型放进 `BuildSurvivalSpawnList()` 和冻结池读档共用的统一资格查询，使选卡预览、正式波次与旧档恢复共用同一 `mSpawnZombieList`；不得把排除扩大到冒险 `spawnlists.json`、开发者直造、AutoTest `spawn_zombie`、已存在僵尸实体的读档恢复或其他显式召唤来源。专项导出“候选资格”和“本轮实际池中是否存在”两层状态，并用同类普通版本作允许对照，避免固定 Seed 恰好没抽中而假绿。
- **普通基础类型的每波上限也走唯一正式 resolver**：把上限计数放 `Board::ResolveWaveZombieType` 等正式波次解析入口，超额返回失败哨兵且不消费候选预算；`CreateZombie`/`spawn_zombie` 保持直造确定性。计数只在 `SummonNextWave()` 与明确的新生存轮边界清零并进入存档，不能按教学关例外，除非规格明说。若还规定场上同时上限，resolver 必须同时统计未死亡敌对实体与已提交的延迟出生事务；魅惑、死亡或事务结算后释放同时名额，但不得返还本波累计名额。专项应在自然出怪表不含该类型的关卡直测解析器，分别锁定每波、同时、换波与快照语义，避免换波后自然抽中同类干扰“已清零”的断言。
- **成功能力后的跨波刷新冷却必须覆盖完整波次**：由 `Board` 同时保存“当前波是否封锁”和“未来仍需封锁的完整波数”；能力只有在正式结算边沿成功提交时才同时封锁本波余下候选并写入未来波数，提前击杀、取消或无效结算不得启动。`SummonNextWave()` 必须在本波任何候选解析前把一份未来冷却转为当前波封锁，再由唯一正式 resolver 返回失败哨兵且不扣预算；不能只保存一个在换波时递减的数字，否则最后一个冷却波生成完成后，同波稍后的正式候选会提前解封。两字段都入档，旧档用中性值；生存换轮默认不清零，明确教学保证才在 resolver 处窄豁免。`CreateZombie`、预览、直造测试和读档恢复保持确定性且不消费冷却。AutoTest 覆盖成功边沿、本波余下候选、后续每个完整波、最早恢复波、取消路径、快照往返与轮次边界。
- **僵尸主动改变天气**：同时使用 `adding-rain-weather`。僵尸只保存并推进自身施法节奏、次数或生命跨段，实际雨势升档必须调用 Board 的语义窄入口；入口显式规定不支持地图/锁定天气 no-op、强天气是否允许降级、同档是否续期及是否附带台风。固定周期触发应在本次动作确实完成后记数，生命阈值触发要排除同次致死并只在跨边沿调用；Board 现有雨势/过渡/余时已经入档时禁止在实体复制。专项覆盖不支持地图、弱转强、已有更强天气、同档续期、后续受击/施法不刷新和双方快照往返。
- **地图积累器联动**：同时使用 `adding-rain-weather`。由 `Board` 在满值边沿一次性收集普通路线与实体能力候选；简单替换规则可按位置与稳定 ID 选唯一候选，智能路线则让全部候选在同一组共同随机 rollout 中比较，但都只能锁定既有一次事件，不能扩大目标数量。实体用语义虚接口声明“类型身份、当前资格、视觉锚点”，`EntityRegistry` 用有序弱索引避免热路径扫描普通僵尸。Board 保存最终路线、行及必要的稳定实体 ID；WARNING 中死亡、换行、破甲、后来出生和跨波残留均不得重抽，锁定实体失效时按既定路线结算、只跳过依赖实时资格的自身增益。蒙特卡洛开启时不得先消费正式 RNG，关闭或推演失败才走规格指定的稳定回退。若能力只强化该僵尸自身位移，在 `Zombie` 提供实例倍率虚入口并乘 Board 基础速度，禁止升级成整行光环。AutoTest 覆盖候选数、锁定存读档、失效不重抽、正式回退及普通/能力路线的效果差异。
- **外部区域压制僵尸的天气承接能力**：区域所有者声明位置语义，Board 提供只读聚合查询，僵尸在自己的承接资格和直接受击后续状态入口分别消费；禁止让植物或 Board 修改僵尸私有计时器，也不要把“拒绝承接/拒绝过载”误扩大成免除本次胸甲伤害、麻痹或品种其他抗性。若承接与自身直击会走不同函数，两处都必须显式审计；专项至少同时放一只被保护目标，证明区域内提供者不承接、目标恢复原伤害/控制，而提供者自身仍按原直接伤甲但不进入被压制状态。
- **地形限定刷新必须放正式选行入口**：只允许陆地或水路刷新的品种统一登记到 `Board::IsSpawnRowCompatible` / `CanZombieTypeSpawnInPool`，让 `SelectSpawnRow` 在加权前把非法行权重清零；零条合法行必须返回失败哨兵并由波次调用方跳过候选，禁止兜底成 `row 0` 后仍创建。地图解禁时同步复核品种自己的坐标基准、场地效果和出生 Y，不能只删兼容性门禁。`CreateZombie` / AutoTest `spawn_zombie` 继续保留直造确定性；专项先用 `assert_zombie_spawn_row` 锁定边界行，再以固定 Seed 走 `SummonNextWave()` 并断言正式实体实际覆盖多条合法行。
- **地图出生改道只能接在正式波次创建边界**：雪穴等入口在候选类型、预算和行已经提交后，只允许延迟并改变这一只的出生 X；不得重抽类型、行或返还预算。预警期间入口被封时回退右侧出生，已创建实体不追溯。内部召唤、预览、开发者直造和 `CreateZombieWithID` 读档恢复不经过改道。延迟事务保存实际类型、行、原波次、锁定入口与余时，读档仍在同一提交边沿决定入口是否有效；出生奖励和正式遭遇记录只在真正创建成功后分配。待出生队列非空时禁止按残血提前出波；兑现边沿必须同步刷新血量，不能等周期采样。提前出波血量阈值由 `FinalizeWaveSpawnThreshold()` 在本波全部候选兑现后锁定，不能用预警期间缺少实体的血量计算；过期波次事务不得重算当前波阈值。专项开启自然出波，覆盖五路全改道、部分改道、倍速、预警读档与封穴回退，并证明未受伤不连跳、达到残血阈值仍正常推进。
- **新增无尽地形只登记模式，不复制出怪池或冒险脚本**：关卡号、背景、显示名和解锁大关统一加入 `SURVIVAL_ENDLESS_DEFINITIONS`，让选关、`mIsSurvival`、背景与独立存档自动消费；僵尸继续走 `CanZombieTypeEnterSurvivalPool()` 和 gamedata `survivalRound`，除非规格明确要求地形专属白名单。背景特有的 Board 环境可以复用，但必须用 `mIsSurvival` 隔离原冒险区域的教学保证、固定关序和收官波脚本。AutoTest 至少锁定“区域末关尚未通关 / 进度越过末关”两侧的入口数量，并验证真实进入、背景环境、代表性僵尸轮次资格和快照往返。
- **提交后延迟出生或回溯必须由 Board 持有独立事务**：施法者只保存未提交 phase/倒计时；提交边沿把锁定类型、稳定实体 ID、行/X、核心生命/防具/控制状态和余时复制到 Board，之后施法者死亡不得删除事务。回溯普通死亡时用原稳定 ID 重建，存活目标只恢复数值和可选位置，不逐帧倒放 Animator；但 `HeadDrop` / `ArmDrop` 已经写入 Animator 的隐藏与换图覆盖不会随 `mHasHead` / `mHasArm` 自动反转，必须在目标拥有的窄恢复钩子里静默重建普通及异形骨架分件，不重放掉落粒子、声音或动作相位。本来没有断肢表现的品种保持空语义，禁止为了省分件映射而销毁全部存活目标再用同 ID 创建，否则会让仍引用旧对象的啃食、附件、碰撞与 Board 事务失效。目标若已进入 `mIsDying` 但尚未正式 `Die()`，它仍占一份 `mZombieNumber`：先构造不登记、不增计数的替身，让旧壳在注册表仍指向自身时走派生清理并以“计数所有权移交”模式静默退役，再把同一稳定 ID 登记给替身；旧壳不得发死亡光环/奖励、扣计数或触发胜利检查，禁止制造 `+1/-1` 的瞬态双计数。一次候选扩成多实体的编队不得进入这种单体回溯；新锚采集和旧档锚结算都要排除，避免复建孤立成员或破坏队伍计数。魅惑、吞食和小推车等不可逆移除，以及磁力剥离的不恢复装备，由对应正式入口给事务打窄标记，禁止 Board 反查攻击者类型。若规格要求回溯品种能力，用基类窄快照接口保存“品种自解释 phase + 剩余时间”，同类型目标恢复时覆盖本地能力并同步安全动作；若锚后取得的新状态也必须能撤销，捕获端必须把“尚未拥有能力/免疫”的中性状态同样返回为有效快照。`phase` 是目标品种解释的不透明编码，事务读档只能按该字段实际编码域校验，禁止用某个施法品种的 `0..N` 小枚举全局截断；恢复顺序在核心生命与防具之后，并原子修复派生状态、防具和 follower 表现。准备/重试/前摇/普通循环冷却可以退款，已提交/禁用态按规格恢复。循环能力应在旧枚举末尾追加冷却阶段而不改写既有编号，并让实体读档、Board 事务读档及能力快照共同夹紧到最长合法余时；旧永久提交态语义改变时提升 schema，把实体和有效锚快照一起迁移为完整冷却。锚定期间已经提交的裂隙、时间锚等 Board 外部事务始终保留，既不撤销也不重放；来源在建立自身事务的提交边沿必须排除局部能力快照，防止自我刷新，结算时也必须跳过该来源的旧 submitted 兼容恢复，否则会在锚结算边沿重新灌满冷却；其他来源仍可记录并恢复它。旧档缺窄快照时仅对非来源目标保持旧 submitted 兼容语义，禁止猜测历史阶段。边界保护若拒绝目标位置，存活者留在当前位置，复活者落到该行安全出生侧。待出生/待回溯事务是否阻止奖杯必须按关卡规格显式决定；选择沿用当前实体结算时，奖杯边沿清空所有未兑现事务。专项覆盖施法者死亡、事务中途存读档、存活/死亡恢复（含逻辑头手与实际轨道可见性）、垂死壳移交前后 `mZombieNumber` 不变、复合编队排除、位置拒绝、磁力剥离、三类不可逆死亡、能力阶段/余时恢复、来源不自刷、同类连锁、外部事务不回滚、旧档兼容和奖杯清理。
- **回溯完成后还必须对齐啮食表现**：品种局部阶段恢复可以为非前摇态选择 walk/idle，但它不拥有存活对象保留的 `mIsEating` 和目标 ID。Board 必须在核心数值与全部局部阶段恢复后，调用目标拥有的对齐入口：有效关系重播该品种的 eat/开吃表现，失效植物关系走原子收尾并平衡 `mEaterCount`。禁止只改轨道后等碰撞“重新开吃”，因为主循环会被 `mIsEating` 早退永久卡住。专项覆盖回溯前后 `isEating/track`、目标 `mEaterCount` 以及位置已失效时的收尾。
- **地下状态与地面能力使用目标拥有的窄接口**：普通自动索敌/弹丸资格、地面危害资格和强制出地是三件独立语义，不能只用 `CanBeTargetedByProjectile(false)` 同时代表。地面植物先按 `CanBeAffectedByGroundHazards()` 与 collider 判定实际命中并结算自身伤害，再调用目标的 `ForceSurfaceFromGroundHazard()`；目标自己决定当前阶段是否接受、是否取消自然冲击及是否写入重试时间。接口默认 no-op，调用方不得识别具体僵尸类型或直接改私有 phase。AutoTest 同时覆盖地下弹丸不可锁定、地面命中可触发、强制出地不结算自然冲击，以及满血/已达触发线时不同的重试边界。
- **连续坡面由 Board 统一拥有，品种移动只提交水平语义**：屋顶出生、预览、正式行走、阵风横移和读档恢复都以保存的 `row + x` 经 `Board::GetZombieSpawnY`/基类坡面同步重建 Y；气球、矿工等品种不得复制坡度或各自累计 Y。需要地面裁剪、影子或附件落点时查询当前 X 的行地面线。不要给通用 `Transform` 自动套坡面，否则飞行物、UI、独立动画与其他地图都会被误改；专项同时覆盖坡段/平台、预览、读档和至少一个非普通移动品种。
- **击杀掉落资源先在正式出生时预分配并按波封顶**：死亡、灰烬群杀和其他 `Die()` 路径只领取出生时锁定的奖励，禁止按本次死亡数量临时 roll，否则范围灰烬会把经济成倍放大。若设计要求关内前宽后紧，用当前波/总波数建立独立归一化曲线，同时收紧携带概率、单团价值和单波预算；跨波累计器只补偿未命中，预算命中硬闸后不再累加。AutoTest 用正式 `SummonNextWave()` 和至少两种总波数断言首尾参数及最终波实际上限。
- **全场稀有能力禁止靠每帧全表扫描维持锁定**：在 `EntityRegistry` 维护该品种的 `ID → weak_ptr` 稀疏索引，覆盖普通 Add、带 ID 读档重建和周期清理；只在能力阈值边沿遍历候选一次，Board 保存稳定实体 ID，后续锁定 Update/Draw 都做 O(1) 查询。若玩法另明确要求“场上存在任意该品种”持续改变积累速率，热路径也只能扫描这份稀疏索引并在首个有效候选处提前返回，禁止改扫全体僵尸或每帧创建候选向量。全场结算先快照全部目标再批量应用，先清除施法者锁定 ID，避免容器遍历顺序、死亡回调或同类连锁改变本帧结果。一次性锁定加当前/最大生命时保存 `boostApplied` 标志；Board 读档 finalize 重放锁定展示必须幂等，旧档缺标志可在这次 finalize 补应用一次，新档不得重复回血。AutoTest 同时覆盖并存择优/并列、持续增量多只不叠加、晴天归零、取消不转移、锁定生命存读档不重复和结算同帧快照。
- **小推车特殊交互**：若能力只应吞掉“其他行”小推车，当前碰撞车必须先走原版 `Trigger()`，Board 副作用按当前 mower ID 排除它，最后仍按 `CanBeKilledByMower()` 决定是否结算 `INT32_MAX`；不要在全场清理分支提前 return，否则精英会绕过本行最后防线直接进家。AutoTest 把吞车/免疫验证放在新场景，前序编队/动画长等待可能让移动僵尸提前撞到别行 mower，造成断言对象漂移。
- **出土/升起**：垂直位移用 `mVisualOffset.y`（存基准值，按计时线性还原）；地面遮挡用现成 `SetClipRect(0,0,SCENE_WIDTH, groundY+margin)`，**底边取 `Board::GetZombieSpawnY(row, currentX)` 当前 X 的行地面线**（换地图与连续坡面自适应），完成后 `ClearClipRect`；升起期不移动不啃食（覆写 StartEat 早退）。出土未完成前通过 `GetShadow()->SetVisible(false)` 隐藏显式阴影附件，并隐藏 reanim 自带 `_ground` 轨道，完整站起后才恢复两者；`ZombieItemUpdate()`/Load 必须重建双层显隐，防 Animator 恢复后 `_ground` 黑影提前出现。AutoTest 导出两者的可见状态并在出土中段、完成节点和读档后分别断言。死亡演出资格不得直接复用“是否已可索敌/啃食”的交互资格：只要升起阶段已经把本体画到地面以上，断头流血或致死伤害就应进入死亡轨，地下移动阶段才可无演出回收；专项用冻结中的无头目标锁定 `isDying + anim_death`、硬控解除和帧事件最终回收。默认让动画继续播放；若主人明确要求静态出土，**只能 `Animator::Pause()` 播放头，不得把 base/extra 速度层写成 0**——后续 `PlayTrack(anim_death)` 会自动恢复 playing，RISING 读档在 `RestoreAnimState` 后须重新 Pause，并必须专项实测升起中死亡不会卡帧。

## 存读档心智清单

- **出生防具倍率只在创建边沿应用**：`Board::CreateZombie` 在各派生 `SetupZombie` 完成后调用 `ApplyHealthMultiplier`；全身倍率与额外防具倍率先合并，再同时缩放当前/最大生命并统一取整，额外保护层也须通过虚钩子覆盖。`CreateZombieWithID` 直接恢复已缩放的保存值；派生读档或时间锚修复不得把最大防具生命写回固定出生常量。模式开关若仅对新局生效，由 Board 锁定并存档，阳光奖励只在新局初始化叠加，续局及生存换轮不得重复发放。专项覆盖治疗夹紧、残甲连续读档、关闭菜单开关后旧局续接与新局恢复默认。

普通 AutoTest 仍会短路玩家 `saves/`，但可用 `save_level_snapshot` → 主动改局面 →
`reload_level_snapshot` 在脚本输出目录内验证“正式序列化 → 销毁旧 `GameScene` →
新场景正式反序列化”。这能覆盖实体与 Animator 的进程内往返；中央存档路径、跨进程
退出重进和迁移行为仍需按任务风险另行验证。禁止临时关闭 `GameAPP::mAutoTestMode`
绕过保护。

- 状态机枚举/计时器/关联 ID → `SaveExtraData/LoadExtraData`；Load 首行 `if (mIsEating) return;` 再动动画。
- 新字段能用中性默认值表示旧档时保持兼容；结构或语义变化无法只靠默认值表达时，提升 `SaveSchema::kCurrentLevelVersion`，增加连续迁移和 `SaveSchemaTests`。JSON 必须先升级成功，再恢复 `Board` 与实体。

## 验证（缺一不可）

1. 所有僵尸任务的编译、F5、范围最小 AutoTest 和最终相关回归都默认直接使用 `clang-release`，保持 0 warning；新 .cpp 未被编译时先执行 `cmake --preset clang-release` reconfigure。同一份当前源码已用该产物完成相关验证时，不再重复编译 Debug 或重跑同一轮 AutoTest。只有主人明确要求 Debug CRT/Debug 语义，或 Release 问题确实需要辅助诊断时，才显式切换 `clang-debug`。
   验证矩阵按实际改动面分流：新僵尸、新附件、新粒子或普通资源本身只要求默认 `clang-release` 可见专项与相关资源/截图断言，不机械加跑 `-NoInstance` 或 OpenGL。只有实际改到渲染后端、后端兼容路径或跨后端提交实现时，才补默认 Vulkan + `-NoInstance` + 强制 OpenGL 回归。本条覆盖本 skill 前文各专项沿用的旧“默认双路径截图”表述：未改渲染后端时，那些专项只跑默认路径。
2. **AutoTest 冒烟**：`autotest/scripts/smoke_<name>.json`。默认按 [AutoTest 验证](../../../docs/agent-guide/AUTOTEST.md) 的“当前桌面可见启动”方案运行：从 `build/<preset>/` 工作目录，用提升权限的 `Start-Process -WindowStyle Normal -PassThru` 启动并等待退出；普通沙箱 shell 即使写了 `WindowStyle Normal` 也可能落在隔离会话，主人桌面完全看不到。首次直造前断言 `HasReanimation`，运行时帽子/残肢/粒子贴图用 `GetTexture(key,false)` 导出加载状态；Release WARN 不保证写进 `run.log`，manifest 也不能替代这些断言。状态断言用 `zombies.N.type/hasArm/armVisible/hasHead/track/mindControlled`；几何断言用 `animatedObjectsByTag.Zombie.N` 的最终世界包围盒及相对 collider 投影，禁止把 C# 绝对坐标写成期望值。**exit 0 ≠ 通过**：逐张 Read 同步截图（断肢前后、编队站位、出土中段——换色变体必须截取真正使用 `rise*` 合成图的中段；注意升起初期整体在地面线下被裁掉是正确的，截图要卡升起 60% 时点）。
3. **死亡消失必须专门测**（末-1 帧陷阱专项）：豌豆打死→dump 确认该 type 消失+run.log 无 WATCHDOG。炸弹类走 Die() 直杀路径，**测不到**死亡帧事件。若品种有出生随机动画倍率，等待上限必须按倍率范围下限计算并在 WATCHDOG 前留裕量，禁止沿用平均速度或旧固定秒数导致慢实例假失败。
4. 时序：`wait_seconds` 是游戏秒；关卡 20 秒起第一波普通僵尸会混入 dump。精确断言碰撞目标或僵尸数量的隔离专项应在进入 `GAME` 后立即 `set_spawn_paused=true`；只有测试自然波本身时才保留生成，不能把首波当固定对照数。
5. 站位/影子不对 → 本体调 gamedata offset（免编译）、影子通过 `GetShadow()` 调 `ShadowComponent` 参数。
6. 父类测试钩子或状态投影使用 `dynamic_cast` 时会同时命中派生精英；先判断具体派生类，或以 `mZombieType` 排除变体，避免普通品种计数和命令误操作精英。
7. Release Fatal Error / Access Violation 先保留崩溃报告与最小脚本，并用同次构建的 EXE/PDB 符号化；若仍不足以定位，给最小复现补充针对性的状态投影、日志或断言，能在 `clang-debug` 复现时可辅助诊断。优先检查资源注册/键和首个空对象来源；修复后重跑 Release 的新类型脚本和父类回归，禁止只交付 Debug 结果。

## 矿道运动兼容

植物主动瞬移前必须通过僵尸自有 `ReleaseRelocatedPlant(plantID)` 解除旧啃食，复用 `StopEatingInvalidPlantTarget` 平衡植物 `mEaterCount`、清目标并恢复走路。不能只移动植物或仅清其计数，否则待提交啃食帧仍可能追伤原 ID；落点接触由正常碰撞重新开吃。专项同时验证旧关系立即终止、随后数秒无远程扣血，以及搬入新僵尸接触区后正常受咬。

幽晶矿场把普通 `ZombieMove` 的既有根运动距离交给 `Board::AdvanceMineZombie`，不能再额外平移一次。`mMineTargetCell` 是已承诺的相邻节点，开凿/读档/魅惑后先完成当前边，再在节点选择新方向；实际 Y 越过行中线时通过 `CommitMineRow` 同步行桶与排序。普通敌人用左/上/下有向下降距离；魅惑单位沿四邻接通路返回右侧入口，以免左侧安全区或死胡同困住单位。新品种的跳跃、钻地、入场等特殊运动不得推定已经兼容此公共步行入口。用独立地形穷举验证防环，再以可见专项验证竖向啃食与中途读档，不能用纯图测试替代实体运动验收。

矿道中的撑杆起跳要按实际 Y 是否到达行基线判断，不能只比较已经越过中线的 mRow；enter 被拒绝后，stay 必须在持续接触且到行时重试，起跳同时撤销原水平目标节点，落地从新位置规划。解除僵尸能力的地图特判时，同时审计 Board 提交、更新和存档恢复入口；裂隙候选须排除岩壁与未连通地面，时间锚回位须一起保存和恢复连续换行偏移及已承诺节点，禁止把旧节点接到回溯后的新位置。
