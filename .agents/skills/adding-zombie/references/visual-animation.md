# 坐标、装备与断肢动画

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

## 视觉识别底线

- 机制或身份特征明显的新僵尸不得只靠全身换色表达。至少提供一个能改变低分辨率轮廓的独立装备/部件，以及与机制阶段同步的动作、破损或脱落反馈；巡航、能力前摇、破层、死亡与图鉴中都应让玩家快速辨认。染色只能作为辅助色彩语言，不能成为唯一识别手段。
- 动作优先复用语义相符的原版僵尸时间轴与核心身体分件，再把 AI 母图拆成头盔、工具、背包等有限装备或命名 follower；除非新体型确实需要且已完整拆件校准，否则不要用大型合成图替换整具身体。这样既保留原版断肢、啃食和死亡动作，也让独立装备承担身份轮廓。
- 独立部件必须按实际握持、背负或安装关系选择稳定语义锚点和绘制层级。背负设备要在最终低分辨率合成中与肩背、腰线形成明确重叠，不能只因挂到 `Zombie_body` 就接受落地或并排站立的观感。主人指出附件漂移、过大或遮挡错误时，要在最终实机合成中校准尺寸、锚点、父轨及前后遮挡；轻微机械颤动不得继承手臂等大幅摆动轨。手持件若直接跟手掌会脱手，优先挂到稳定的上游前臂轨，并在最终合成中让手掌与设备握持处保持重叠；自身状态反馈优先换图或小幅局部变换，禁止用大幅逐帧缩放制造“抖动”。机械往复 reanim 还要检查循环末帧到首帧的角度/位移差，不得只检查片段内部平滑。按项目 AutoTest 矩阵选择路径，用同步截图验收，不能只看高分辨率源图或单张贴图。
- 延迟回溯、倒计时等 Board 独立事务若需要持续标记移动目标，僵尸只负责提交边沿，Board 按稳定 ID 在目标当前视觉原点周期续发短寿命复合粒子；表现层可把钟面与多根指针拆为同中心透明层并赋予不同逆向角速度，但不得新增会改变事务时序的实体动画或在粒子里复制倒计时真相。恢复仍只发生在 Board 的既有结算边沿，施法者死亡与存读档语义不得因视觉增强改变。

## 坐标换算铁律

**C# 原版逻辑场景是 800×600，本项目是 `SCENE_WIDTH=1100`、`SCENE_HEIGHT=600`。原版任何绝对 X/Y、碰撞框偏移、绘制偏移、粒子触发点和屏幕边界都只能当语义参考，禁止直接抄入代码。**

- 场景绝对坐标改由 `SCENE_WIDTH/SCENE_HEIGHT`、Board 网格与当前背景几何重新派生；不要把 800 宽地图的右边界、出生点或阈值原样搬来。
- 原版按世界 X 分段的速度/状态阈值写成“当前地图坐标基准 + 原版相对距离”；平地可从 `CELL_INITALIZE_POS_X` 派生。屋顶连续坡面由 `Board::GetRoofSlopeEndX/GetRowCenterYAtX` 唯一拥有，当前交界 X 从 `CELL_INITALIZE_POS_X + 5 * CELL_COLLIDER_SIZE_X` 派生，禁止品种复制斜坡公式。
- 僵尸局部坐标先求“原值相对 C# 绘制原点”的差，再锚到本项目稳定视觉原点 `Transform + mVisualOffset`；物理框、攻击框和粒子通常不得跟受伤抖动等临时绘制偏移移动。
- 黄油等需要跟随活动部件的状态贴图统一走 `Zombie` 配置的 reanim follower：基类虚接口默认返回 `anim_head1`，异形/车辆只覆写自己的语义父轨道；必须在派生 `SetupZombie()` 完成后再配置，并让命中、清除、死亡、魅惑和读档只切 follower 可见性。资源确实没有该轨道时保留稳定锚点后绘兜底，禁止创建空轨道掩盖注册问题。异常体型用独立虚倍率调尺寸，默认保持 `1.0`，禁止为放大贴图改语义轨道或全局默认尺寸。冰晶等稳定车体/地面效果继续使用 `Transform + mVisualOffset` 局部常量；默认实例路径的后绘贴图必须用 `DrawTextureInstanced` 与 reanim 本体进入同一有序实例流，`-NoInstance` 才保留 `DrawTexture`。不能假定 C++ 调用在后就一定显示在前：对象数跨过并行阈值后，同一 blend 段会先 replay batch、再 replay instance，受击 glow 的 Add 分段还可能让错误只在“不发光”时出现。专项用至少 200 个可绘制对象稳定命中并行路径，分别截取无 glow、glow 中、glow 结束及 `-NoInstance` 对照。
- follower 层级按品种语义选择：普通僵尸默认把已经算好完整父轨仿射变换的 follower draw record 延迟到整个 Animator 的轨道和子附件之后，使黄油稳定处于头发、眼镜等最高层；巨人这类需要武器、下巴或前臂跨层遮挡的品种覆写为父轨之后立即提交。延迟记录必须留在 `Animator`/`Graphics` 的同序队列内：默认 Vulkan 使用 bindless `InstanceRecord`，`-NoInstance` 与 OpenGL 兼容后端使用同序矩阵 batch（OpenGL 4.3 可由 SSBO 在 GPU 变换，3.3 在 CPU 展开）；禁止在 `Zombie::Draw` 外部另发 `Graphics::DrawTexture` 或强制 flush。修改通用 follower 层级实现时覆盖普通头发遮挡、异形专属头轨、极端动作遮挡、存读档与已注册僵尸的语义轨道；只改品种附件时仅验证受影响品种，渲染路径按项目 AutoTest 矩阵选择。
### 胸甲也可以是一类防具

`HelmType` 表达的是防具结算顺序和独立生命池，不要求视觉位于头部。胸甲等必须压住整套本体的装备可跟随 `Zombie_body`，并用 `drawAfterAllTracks=true` 延迟到本体全部轨道之后；不要仅把子 Animator 附到身体轨道，因为父轨后续的手臂/头部仍会盖住它。裂纹贴图只从同一 `mHelmHealth` 派生，不得为每张贴图增加隐藏生命段；破甲、磁吸、死亡和读档都要同步 follower 显隐，按项目 AutoTest 矩阵检查同步截图。
### 正向修复后全部破损外观必须可逆

治疗只能增加当前仍大于 0 的生命池，不能重建已掉落、被磁吸或已部署的装备；结算后通过基类虚语义入口重建本体与装备表现，默认调用 `CheckHelmImage` / `CheckShieldImage`，拥有本体伤势换图的品种再覆写并收敛到同一重建函数。身体、头盔与护盾检查都必须完全由当前耐久重新派生完整/轻损/重损阶段；恢复完整态要显式清除 Animator 轨道 override（`SetTrackImage(..., nullptr)`），不能保留只允许向下破损的一次性分支。专项同时断言耐久增加、本体/一类/二类三层各自夹紧上限、跨阈值后的实际贴图键，并以同步截图验收。
### 同一语义轨道并存多种状态挂件

`ReanimTrackExtra` 以命名 vector 保存多个 follower 槽；黄油、防具等各用稳定唯一槽名，只更新自己的贴图和可见性，不得互相覆盖或退回对象外 `DrawTexture`。静态 follower 默认继承宿主 Animator 的状态 overlay，使减速、冻结等覆盖色覆盖装备；属于当前承伤层外观的装备还必须显式传 `inheritGlowEffect=true`，让父轨 additive glow 同步覆盖装备。黄油等状态贴花显式同时关闭 `inheritOverlayEffect` 与 `inheritGlowEffect`，保持自身原色且不随本体受击闪白。实例与 `-NoInstance` 都按“base → overlay → glow”提交；专项在同一画面先施加覆盖色、再命中装备，断言装备 follower 发光而状态贴花不发光，并截图核对 additive glow 最终确实落在 follower 上。只有需要独立播放头、clip 或帧事件的附件才使用子 Animator。
- 用户目验若指出整只载具统一偏高/偏低，且碰撞框、攻击框、发射点、死亡特效都已从 `Transform + mVisualOffset` 派生，只调权威 gamedata 的整车 offset，禁止给每个消费者再补一份 Y。改后同时复查车轮地面线、投射物起点与独立残骸；只有其中单项仍偏时才调该项的局部常量。
- 僵尸装备发射同行直射物时，瞄准线、枪口粒子和弹体出生必须共享同一真实炮口世界锚点；不能为了命中逻辑行而把出生 Y 直接设为目标格 Y。炮口与目标高度不同时，让弹体视觉沿明确轨迹从炮口收束到终点，碰撞仍按锁定逻辑行判定，并保存足够的终点/轨迹状态供在途读档恢复。AutoTest 同时截图炮口起点与在途轨迹，并断言途中植物仍可正常拦截。
- 网格位置与画面偏移继续分离；屋顶出生、读档重建、出土裁剪及任意当前点地面线必须使用 `GetZombieCollisionY/GetZombieSpawnY(row, worldX)`。水平移动仍由品种的 `ZombieMove` 决定，基类在阵风后和 `ZombieMove` 后统一把 Transform Y 收敛到坡面，普通、飞行、地下品种不得各自维护 Y 公式。
- 验证先执行同步 `screenshot`，再用 `animatedObjectsByTag.Zombie` 的 `renderProbeReady/worldBounds/visualToRenderCenterD*Int/nearestZombie` 验证本项目最终绘制几何相对自身 collider、同排植物或攻击目标的关系；每阶段只保留一个目标僵尸以稳定数组索引。
- 修改出生 offset、受伤偏移、附件、翻转或整身变换时，在默认实例路径跑同一静止用例并比较整数 `worldBounds`；运动对象瞬时绝对 X/Y 只供诊断，不作稳定断言。
- 战场主体按 `row N 植物 → row N 僵尸/扶梯 → row N+1 植物` 交错绘制；同排僵尸仍在植物之上，下一行植物遮挡上一行越界身体。大蒜改道、蹦极选格、首领换行等运行期 `mRow` 提交必须走基类行提交/排序键刷新入口，不能只改字段；小推车与子弹层保持原顺序。专项同时断言语义 `renderLayer` 未变、实际 `renderOrder` 行带正确，并以默认/`-NoInstance` 屋顶跨行截图验收。

## 断肢 / 断头（按实际 reanim 校准）

- 覆写 `ArmDrop()/HeadDrop()`（不调基类——基类隐藏的是普通僵尸轨道名）+ 基类阈值自动触发（臂≤2/3、头≤1/3，由 `mNeedDropArm/Head` 门控）。
- 无残肢轨道的 reanim：藏 `outerarm_lower`+`outerarm_hand`、保 `outerarm_upper` 当残端、**不换材质**（disco 伴舞式）；有 `_bone`/`UPPER2` 的才做显示残肢/换图。
- 同一语义部件可能按动作烘焙成多套独立轨道（雪橇队员的 `outerarm_lower/hand` 与 `outerarm_lowereating/handeating` 实证）；逐片段审计走路、啃食和其他稳态使用的全部部件轨，把隐藏与残端换图收敛到同一 helper，并在 `OnStartEating`/`PlayWalkAnimation` 切轨后按当前断肢状态重放，禁止只隐藏当前最常见的一套轨道。
- 断头隐藏头部组全体**含挂件**（hair/earing/tongue…逐 reanim 数）。
- 主人指定头部挂件“随头一起飞”时，把头与挂件预合成为一张专属粒子贴图并只发一颗粒子；`HeadDrop()` 在隐藏头部组前读取头轨世界锚点，再同步隐藏挂件轨。不要用两颗独立随机粒子冒充固定连接，否则旋转和弹道会立刻错位。
### `ZombieItemUpdate()` 与 Arm/HeadDrop 的轨道操作严格一致

### 逻辑库存与美术槽位必须分离

弹药、装备或召唤次数可高于 reanim 烘焙的可见槽位数；高库存阶段保持全部槽位显示，只在剩余量进入可见槽位范围后逐个隐藏，禁止复制轨道冒充更多库存。逻辑上限统一供 Setup 默认值、成员默认值和 Load 钳位使用；调高后同步断言初值、首个扣减、存档往返、进入可见阈值和耗尽总伤害。

### 入水/出水反馈只绑定真实介质边沿

通用僵尸以决定 `mInPool` 的同一对探针中点和水面裁剪底线作为水花世界锚点；C# `PoolSplash` 是一次性 `Splash.reanim` + `PlantingPool` 水滴两层，必须分别创建并按入水/出水选择 Foley。首次生成在水中、预览与读档恢复只静默同步介质，禁止伪造跨界声画；海豚等自管入水动作在 C# 进度节点调用共用水花视觉，动作结束提交 `mInPool` 时显式静默，避免末端重复一次。AutoTest 一负一正断言节点前计数 0、节点后两层各 1，并在快照重载后确认计数和声音请求都不再增加。

### 受击白光必须按实际承伤层驱动

禁止在 `TakeDamage` 分层前统一整身 `SetGlowingTimer`。原版本体/头盔/飞行额外生命共用本体计时器，报纸/铁门/梯子等二类护盾使用独立计时器和盾轨高亮；普通正面弹只伤盾就只闪盾，穿透或破盾溢出确实伤到后层才同时闪。所有 `Bullet` 的直接伤害统一走 `Zombie::TakeProjectileDamage`，按命中时 `velocityX` 与 `IsMovingRight()` 判断命中面：子弹与面向同向即从背后追上，完全绕过二类护盾并只闪后层；`velocityX=0` 保持正面口径。禁止按子弹类型或运动模式建**方向性**绕盾白名单，追踪弹须持续写回真实速度。弹丸自身能力若主动请求绕盾，必须通过同一入口的显式参数表达，并由目标侧 `BlocksProjectileShieldBypass` 虚接口按当前防具状态否决；方向背击优先保持原物理语义，目标否决不得顺带封死背击。`penetrateShield` 会让盾与后层同时承伤，不能用来冒充完全绕盾。围绕 `TakeExtraProtectionDamage`、`TakeShieldDamage`、`TakeHelmDamage`、`TakeBodyDamage` 的虚调用比较扣血前后值，避免派生覆写漏报；盾轨覆盖必须同时接入实例化与 `-NoInstance` 绘制路径。AutoTest 用 `hitFlashMask` 锁逻辑层、`renderedHitGlowMask` 锁实际轨道层，并同步截图检查铁门/报纸的正向、反向、主动绕盾、目标否决与静止弹。

### 静态贴图装备不要小题大做成子 Animator

没有独立播放头、clip 或帧事件，只需跟随父轨仿射变换的帽子、甲片、铃舌等，使用 `Animator` 的命名 track follower。每个调用方提供稳定且唯一的槽名，并显式设置贴图、层级策略和可见性；同一父轨的多个 follower 保存在向量中，按插入顺序绘制，更新或移除一个槽不得覆盖其他槽。装备默认保留 `inheritOverlayEffect=true`，状态贴花才显式关闭。特别审计 `SetupZombie()` 之后基类 `Zombie::Start()` 还会配置黄油等 follower：专项必须从自然生成起检查装备已出现，再覆盖同轨多槽共存、状态覆盖、换损伤贴图、隐藏/脱落和快照重建。普通装备只验证默认可见路径；改动后端或跨后端提交实现才补兼容矩阵。
### 同 reanim 独立附件

螺旋桨等确实需要自己的播放头、clip 或帧事件的部件才实例化第二个 Animator、只播放附件 clip，再挂到主 Animator 的稳定锚点；附件 clip 必须清除主轨下发的 clip 速度覆写，但保留冻结/减速 extra 倍率。一个 Animator 的全部轨道共享同一播放头，生成或手写小 reanim 时每条轨道必须拥有相同总 `<t>` 数；短 marker 轨在切到后段 clip 后会被同一帧号越界索引，实例和慢路径都可能在 `Animator::DrawInternal*` 崩溃。生成器应在运行前解析并断言全轨等长，不能用渲染空指针早退掩盖坏资源。父锚点隐藏不会自动阻止附件绘制；仅把子 Animator 的 Alpha 设为 0 也不等于完全不可绘，父级受击 additive glow 仍可能留下幽灵轮廓。装备永久脱落且没有恢复路径时应 `DetachAnimator` 并释放强引用，AutoTest 同时断言子 Animator 已销毁并检查破甲瞬间截图；临时隐藏才显式同步全部绘制层与播放态。附件帧、播放态和宿主 phase 一起入档。

### 共享循环音效要有物种级所有权

`AudioSystem` 的循环 key 是全局共享资源，一只实例直接 `StopLoopingSound` 会误停仍存活的同类。为品种维护静态引用计数，每实例用布尔值保证只申领/释放一次；只在正式出生钩子和 RUNNING 读档恢复时申领，在开盒/换态、掉头、死亡和析构时释放，计数归零才真正停止。Load 不得重播 boing/surprise/explosion 等一次性声音。AutoTest 至少断言循环实际播放状态与一次性请求计数；允许同品种并存时再造两只，验证一只退态后循环仍由另一只保持。

- **无 `anim_*` 剪辑标记的专属残骸要播放完整默认时间线**：把残骸做成独立 `AnimatedObject`，`SetFrameRangeToDefault()` 后从 0 帧 `PLAY_ONCE`，在主人给定的全时间线帧注册自身回收事件；禁止 `PlayTrack` 一个资源里不存在的 `anim_crumble`，也不要让残骸寿命延迟原僵尸本体死亡。专项分别断言本体同帧消失、残骸只剩一份、指定帧后残骸归零，并确认灰烬入口不叠普通爆炸。

### 能力驱动的装备换色必须保留损伤阶段并覆盖全部视觉终态

父类提供按当前能力/阶段选择材质、已部署样式和掉落效果的窄虚入口；能力切换只重放现有 `damage0/1/2` 映射，禁止重置护盾生命或破损档位。携带轨道、已放置 Board 对象、磁吸离体物、破盾粒子和读档重建必须消费同一状态；Load 在能力字段恢复后再次应用材质入口。AutoTest 先断言初始样式，再分别锁定完整态与二段破损态切换、非命中分支不换色、部署/磁吸/掉落颜色以及双方快照往返。
