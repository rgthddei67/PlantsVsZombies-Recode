# 存档与时间回溯

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

### 提交后延迟出生或回溯必须由 Board 持有独立事务

施法者只保存未提交 phase/倒计时；提交边沿把锁定类型、稳定实体 ID、行/X、核心生命/防具/控制状态和余时复制到 Board，之后施法者死亡不得删除事务。回溯普通死亡时用原稳定 ID 重建，存活目标只恢复数值和可选位置，不逐帧倒放 Animator；但 `HeadDrop` / `ArmDrop` 已经写入 Animator 的隐藏与换图覆盖不会随 `mHasHead` / `mHasArm` 自动反转，必须在目标拥有的窄恢复钩子里静默重建普通及异形骨架分件，不重放掉落粒子、声音或动作相位。本来没有断肢表现的品种保持空语义，禁止为了省分件映射而销毁全部存活目标再用同 ID 创建，否则会让仍引用旧对象的啃食、附件、碰撞与 Board 事务失效。目标若已进入 `mIsDying` 但尚未正式 `Die()`，它仍占一份 `mZombieNumber`：先构造不登记、不增计数的替身，让旧壳在注册表仍指向自身时走派生清理并以“计数所有权移交”模式静默退役，再把同一稳定 ID 登记给替身；旧壳不得发死亡光环/奖励、扣计数或触发胜利检查，禁止制造 `+1/-1` 的瞬态双计数。一次候选扩成多实体的编队不得进入这种单体回溯；新锚采集和旧档锚结算都要排除，避免复建孤立成员或破坏队伍计数。魅惑、吞食和小推车等不可逆移除，以及磁力剥离的不恢复装备，由对应正式入口给事务打窄标记，禁止 Board 反查攻击者类型。若规格要求回溯品种能力，用基类窄快照接口保存“品种自解释 phase + 剩余时间”，同类型目标恢复时覆盖本地能力并同步安全动作；若锚后取得的新状态也必须能撤销，捕获端必须把“尚未拥有能力/免疫”的中性状态同样返回为有效快照。`phase` 是目标品种解释的不透明编码，事务读档只能按该字段实际编码域校验，禁止用某个施法品种的 `0..N` 小枚举全局截断；恢复顺序在核心生命与防具之后，并原子修复派生状态、防具和 follower 表现。准备/重试/前摇/普通循环冷却可以退款，已提交/禁用态按规格恢复。循环能力应在旧枚举末尾追加冷却阶段而不改写既有编号，并让实体读档、Board 事务读档及能力快照共同夹紧到最长合法余时；旧永久提交态语义改变时提升 schema，把实体和有效锚快照一起迁移为完整冷却。锚定期间已经提交的裂隙、时间锚等 Board 外部事务始终保留，既不撤销也不重放；来源在建立自身事务的提交边沿必须排除局部能力快照，防止自我刷新，结算时也必须跳过该来源的旧 submitted 兼容恢复，否则会在锚结算边沿重新灌满冷却；其他来源仍可记录并恢复它。旧档缺窄快照时仅对非来源目标保持旧 submitted 兼容语义，禁止猜测历史阶段。边界保护若拒绝目标位置，存活者留在当前位置，复活者落到该行安全出生侧。待出生/待回溯事务是否阻止奖杯必须按关卡规格显式决定；选择沿用当前实体结算时，奖杯边沿清空所有未兑现事务。专项覆盖施法者死亡、事务中途存读档、存活/死亡恢复（含逻辑头手与实际轨道可见性）、垂死壳移交前后 `mZombieNumber` 不变、复合编队排除、位置拒绝、磁力剥离、三类不可逆死亡、能力阶段/余时恢复、来源不自刷、同类连锁、外部事务不回滚、旧档兼容和奖杯清理。
### 回溯完成后还必须对齐啮食表现

品种局部阶段恢复可以为非前摇态选择 walk/idle，但它不拥有存活对象保留的 `mIsEating` 和目标 ID。Board 必须在核心数值与全部局部阶段恢复后，调用目标拥有的对齐入口：有效关系重播该品种的 eat/开吃表现，失效植物关系走原子收尾并平衡 `mEaterCount`。禁止只改轨道后等碰撞“重新开吃”，因为主循环会被 `mIsEating` 早退永久卡住。专项覆盖回溯前后 `isEating/track`、目标 `mEaterCount` 以及位置已失效时的收尾。

## 存读档心智清单

### 出生防具倍率只在创建边沿应用

`Board::CreateZombie` 在各派生 `SetupZombie` 完成后调用 `ApplyHealthMultiplier`；全身倍率与额外防具倍率先合并，再同时缩放当前/最大生命并统一取整，额外保护层也须通过虚钩子覆盖。`CreateZombieWithID` 直接恢复已缩放的保存值；派生读档或时间锚修复不得把最大防具生命写回固定出生常量。模式开关若仅对新局生效，由 Board 锁定并存档，阳光奖励只在新局初始化叠加，续局及生存换轮不得重复发放。专项覆盖治疗夹紧、残甲连续读档、关闭菜单开关后旧局续接与新局恢复默认。

普通 AutoTest 仍会短路玩家 `saves/`，但可用 `save_level_snapshot` → 主动改局面 →
`reload_level_snapshot` 在脚本输出目录内验证“正式序列化 → 销毁旧 `GameScene` →
新场景正式反序列化”。这能覆盖实体与 Animator 的进程内往返；中央存档路径、跨进程
退出重进和迁移行为仍需按任务风险另行验证。禁止临时关闭 `GameAPP::mAutoTestMode`
绕过保护。

- 状态机枚举/计时器/关联 ID → `SaveExtraData/LoadExtraData`；Load 首行 `if (mIsEating) return;` 再动动画。
- 新字段能用中性默认值表示旧档时保持兼容；结构或语义变化无法只靠默认值表达时，提升 `SaveSchema::kCurrentLevelVersion`，增加连续迁移和 `SaveSchemaTests`。JSON 必须先升级成功，再恢复 `Board` 与实体。
### SetupZombie 先于 LoadExtraData 跑

Setup 里的出生预设（下沉、裁剪、初相位）在 Load 里按存档相位**显式撤销**，否则读档僵尸带着出生态复活。
- 关联僵尸 ID 经 `CreateZombieWithID` 保值可交叉引用；引用已死自然返回 null，无需清理回调。
- Board 保存的实体锁定 ID 要在全部实体完成 `CreateZombieWithID + LoadExtraData` 后再做一次 finalize 校验与派生态恢复；禁止 Board 字段一读出就重抽候选，也不能因实体尚未创建而误判取消。
- 轨道/帧位由 `RestoreAnimState` 统一恢复不用自己存；节拍驱动的僵尸在 Load 里把"上次段位缓存"置 -1 重新入拍即可。

不可回溯的经济副作用应由 Board 按稳定僵尸 ID 持有账本，不能放进时间锚能力快照。死亡后保留已返款记录；注意 `RetireForTemporalReplacement()` 会调用虚拟 `Die()`，此时只是替换濒死外壳，不能触发实际死亡返款。读档先恢复账本，重建实体再由当前记录派生阶段；专项覆盖存活回溯、死亡复活、重复清除与快照往返。
