# 查询索引与战斗推演

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

### 大规模血量文字不得重回动态整串纹理抖动

受伤本体与防具行继续使用共享字形图集，并在 worker 录制期按原对象顺序写入实例；若压力场景需要优化满血共同路径，只能为 `current == max` 的稳定文本取得 pinned 共享纹理，动态数值必须立即回退字形路径，禁止把每个历史血量永久缓存。整行纹理上传前要裁掉四周全透明像素并保存原 surface 偏移，绘制时补回原点；默认 Vulkan 可在当前位置写一条 `InstanceRecord`，`-NoInstance`、OpenGL 和裁剪路径保留同序 batch。不能假设“实例更少必然更快”：未裁整行会增加透明片元，把一行拆成多张纹理也可能因采样局部性变差而退化，候选必须在同一存档比较 GPU 时间、fragment invocation 与稳定对象数。真实关卡存档的 AutoTest 必须显式用只读 `-AutoTestLoadSave`；小推车等事件会快速改变僵尸数时，只比较数量仍稳定的早期 60 帧窗口，并用 `smoke_zombie_hp_glyph` 的默认、`-NoInstance`、OpenGL 截图复核字距、基线、护具行和层序。
### 逐帧稀有品种查询禁止扫描全体僵尸

血条、天气来源、地形光环等功能若每帧只关心一种或极少数品种，不得调用 `GetAllZombieIDs()` 后过滤，也不得在 `mZombies` 上写通用按类型全扫。优先在 `EntityRegistry` 维护该品种的 `ID → weak_ptr` 专用索引：普通生成和 `AddZombieWithID` 读档恢复两个入口都登记，同 ID 被其他类型覆盖时撤销，沿既有清理节奏删除过期弱引用；查询时只遍历稀有候选，并即时复核 `IsPreview/IsActive/IsDying/health` 等易变状态。需要“最小实体 ID”稳定语义时使用有序索引；需要同帧安全批量遍历时仿照黄色冰道生成 `shared_ptr` 快照；真正由 Board 唯一拥有的单例可保存实体 ID 并在读档后重建。只有查询集合本来就覆盖大量普通僵尸或按行移动频繁时，才用每帧惰性重建的行桶。交付时必须告诉主人所选索引、复杂度和所有维护入口，避免功能正确但压力场景退化。
### 专用品种索引是附加镜像，不是所有权迁移

`TrackXxx` 只把同一个实例登记成 `weak_ptr`，不得从 `mZombies` 擦除或移动主 `shared_ptr`；全体遍历、`ForEachZombieInRow`、存档和碰撞仍以主表为全集。AutoTest 同时比较专用索引计数与按行遍历计数，防止优化悄悄改变可见实体集合。
### 按行裸指针桶必须在生命周期边沿立即失效

`EntityRegistry::mZombiesByRow` 只为热路径缓存非拥有 `Zombie*`，唯一真相源仍是 `mZombies` 弱索引。运行期换行必须走 `Zombie::CommitRow()`，最终 `Die()` 必须在 GOM 延迟销毁前调用 `InvalidateZombieRowIndex()`；不能只依赖 Board 稍后的 `CleanupExpired()` 每帧兜底，因为下一帧 GOM 会先释放对象、较早更新的射手就可能虚调用悬空地址。`ForEachZombieInRow` 回调前还要复核 active/dying，以覆盖同帧前一个回调改变后续候选状态。`smoke_zombie_row_index_lifetime` 固定“先构建行桶、同帧杀两只、下一帧射手查询”的 UAF 窗口；换行专项沿用同一先查询后变更结构，防止堆布局变化把错误偶然隐藏。

### 范围攻击的贪心落点要按实际结算集合评分

先从合法行/格或实体建立候选落点，再用与最终伤害完全相同的活动状态、阵营过滤、圆/碰撞框相交和组合植物拦截规则累计每个爆点覆盖目标的价值；位置倍率、经济产出预期等权重施加到每个受影响目标，而不是只看被瞄准单体或硬切目标优先级。新增南瓜等外壳或邻格保护后，先以原几何找出命中层，再通过 Board 唯一解析入口按逻辑范围选择保护者；重叠范围须稳定选择最近者并打破并列，命中外壳只选自己以阻断连锁，最后按保护者实体 ID 归并为每次攻击一次承伤。无保护者才保持原逐层伤害；不要只遍历全植物直接扣血，也不要让普通版本误接精英专属拦截。贪心与蒙特卡洛/轻量推演须保存层类型，并复用相同保护范围、选择和归并规则。无合法目标时不空投且用有界短间隔重试，最高分并列可随机择一。专项覆盖陆地、水路 under+normal+壳、多命中归并、重叠保护、无保护旧行为、倍率伤害和明确豁免的普通版本。
### 可复用的短视未来选点由 `Board` 采集、纯数值模块推演

`Board` 是唯一读取 GameObject/当前卡槽/正式 `CanPlantAt` 的边界，快照记录当前敌方僵尸的真实行、X、移速、本体/头盔/护盾生命与攻击力，以及玩家实际已选卡、冷却、费用和 gamedata 植物画像；已有交互不能只存 `isEating` 等布尔量，必须用实体 ID 带入当前啃食目标等精确关系，否则简化几何会把正式状态误判成尚未接触。推演器不得按僵尸类型写 `switch`，只用能力维度固定预算推进；需要让时域外的未完成交互参与决策时，可在终点用剩余生命、合并后的交互速率和有界权重结算一次廉价终局分，而不是延长完整逐步模拟。候选与无攻击基线共用 rollout seed，并使用局部 RNG，禁止消费 `GameRandom`；诊断状态应单独导出终局分差，便于确认决策来自协同而非噪声。总开关放 `GameAPP` 且旧档默认开启，关闭或推演失败必须保留原确定性/贪心策略；AutoTest 同时锁定开启时的 rollout/候选/僵尸/卡槽数量、关闭时确实走回退，并用一例“协同改变目标”和一例“更高即时收益仍胜出”约束终局权重。
### 普通支撑植物不得挤占详细植物预算

由植物 gamedata 的 `simulation.supportOnly` 声明普通花盆/睡莲；Board 按稳定实体 ID 把它们写入独立、每格至多一项的支撑数组，完整保留 ID、生命、战略价值、碰撞框与啃食资格。详细植物维持 128 株容量，支撑层按棋盘格硬限 64；避雷花盆等带特殊推演能力的 under 植物保持完整画像。纯数值推演中的范围伤害、蹦极单株移除、当前锁定啃食和终局阻挡价值都必须同时消费两类数组，并以 `pumpkin > normal > under` 而非实体创建顺序解析同格重新索敌；不能用“under 全部忽略”的快捷分支。当前模型不表达“未来先种支撑、再种宿主”的两步占格，因此 `supportOnly` 卡牌不进入未来种植候选。
### 蒙特卡洛的单株移除必须按实体而非爆炸半径表达

候选携带目标植物 ID，纯数值推演在时间线起点只删除该实体；`Board` 负责按正式组合植物优先级为每格选出实际会被带走的一层，并过滤已被其他实例预订的 ID/格。多个候选最高分并列时用局部 seeded RNG 随机，不得消费正式 `GameRandom`。若总开关关闭，必须走该品种原版选择算法（例如蹦极的“有植物格 10000、空格 1”加权随机），禁止把现有贪心回退误当所有品种的统一原版行为；专项以同一 Seed 分别锁定开启/关闭的模式、目标与 rollout 数。

### 稀有品种来源的热路径查询

若每个目标每帧只需查询少量特殊僵尸来源，不要借通用行索引扫描整行后对每个候选 `dynamic_cast`。在 `EntityRegistry` 的所有新增/恢复入口维护按实体 ID 的品种专用弱索引，每帧首查生成强引用快照并在 `CleanupExpired` 释放；快照只缩小候选集，回调仍须复核同帧死亡/失活、当前行与精确几何覆盖。移动区间或多独立来源的最终层数仍应即时计算，不能缓存成布尔值或静态计数。
### 稀有的每实例状态优先冷热分离，但必须按真实总量验收

先用目标工具链的 record layout 与代表性数量确认常驻字段确实显著，再把大数组、容器、回调或仅少数品种启用的附件移到首次生效才分配的侧车；高频资格查询需要的稳定 ID/小标志继续内联，不能为了缩 `sizeof` 让热路径多一次指针追逐。活跃元素用显式计数和紧凑前缀推进，未生效热路径必须 O(1) 早退。侧车不得变成任意组件系统，宿主仍独占状态与生命周期；Save/Load 保持原 JSON 字段与中性默认，只在读到有效状态时分配。到期、魅惑、死亡和孤儿恢复按各状态正式生命周期释放；若侧车持有计划复用的附件，可保留休眠分配，但必须隐藏/停用并计入真实总量。报告内存时同时列对象 `sizeof`、常见侧车、附件与分配开销，禁止只报缩小后的热对象或仅凭布局宣称 FPS 提升；专项至少覆盖未生效、满层刷新、到期或休眠、正式快照往返和倍速等价。

### 可关闭的蒙特卡洛主动决策只放在动作边沿

由 `Board` 一次采集实体、装备层、卡槽、已提交但未结算动作和确定的全局事件，纯数值模块用共同随机数比较全部合法候选与“不执行本次动作”基线，局部 RNG 禁止消费正式 `GameRandom`。候选若是“立即停机、延迟销毁”，必须从 t=0 禁用目标能力并按真实间隔/目标专属次数推进伤害，不能复用蹦极的立即移除近似；已经离膛或越过提交边沿的效果作为来源无关事件继续结算，尚未提交的能力则随来源停机取消。高操作玩家可控的范围能力应集中声明冷却、伤害和几何，由推演按命中数优先、有效收益次之与稳定 ID 选择默认落点，禁止在决策僵尸侧识别植物类型。详细实体数必须有共享硬上限；无上限范围效果把样本外对象折算成有界汇总量，不能改变正式结算数量。不同决策族可以共享实体硬上限，但 rollout 预算必须按各自时域、步数与候选规模使用独立可调常量；禁止为了调高短时域能力的精度而经同一个全局常量同步放大其他长时域推演。候选数会随防线密度增长的决策还要用“候选数 × rollout 数”总评估量封顶，候选少时保留完整样本数，避免错峰后单次推演仍在满防线形成尖峰。等待候选用有限延迟副本表达，累计等待和重试计时入档，达到上限后只比较立即动作；同收益严格偏好立即执行，等待必须靠真实未来收益胜出。总开关关闭、阵营模型不适用或推演失败时，原子回退该品种原有确定性/随机规则。性能验收不能只看60帧平均 FPS：用同步放开全部施法者的确定性压力夹具，并把快照与 rollout 分段计时，同时记录报告窗口调用次数和单次最大耗时；否则动作边沿尖峰会被 VSync 等待和窗口均值掩盖。多名施法者的同步峰值仍超预算时，在 `Board` 按稳定实体 ID 与固定逻辑步间隔发放推演名额，间隔至少覆盖一次渲染帧允许追赶的最大固定步数，未领取者保持动作就绪后续再试；禁止改按渲染帧发放而让逻辑时序随机器性能漂移。AutoTest 同时导出决策模式、动作、rollout/候选/样本计数，覆盖开关两路、等待读档、同步压力和共享上限；纯数值单测另锁定关键事件对收益的改变。

### 全场稀有能力禁止靠每帧全表扫描维持锁定

在 `EntityRegistry` 维护该品种的 `ID → weak_ptr` 稀疏索引，覆盖普通 Add、带 ID 读档重建和周期清理；只在能力阈值边沿遍历候选一次，Board 保存稳定实体 ID，后续锁定 Update/Draw 都做 O(1) 查询。若玩法另明确要求“场上存在任意该品种”持续改变积累速率，热路径也只能扫描这份稀疏索引并在首个有效候选处提前返回，禁止改扫全体僵尸或每帧创建候选向量。全场结算先快照全部目标再批量应用，先清除施法者锁定 ID，避免容器遍历顺序、死亡回调或同类连锁改变本帧结果。一次性锁定加当前/最大生命时保存 `boostApplied` 标志；Board 读档 finalize 重放锁定展示必须幂等，旧档缺标志可在这次 finalize 补应用一次，新档不得重复回血。AutoTest 同时覆盖并存择优/并列、持续增量多只不叠加、晴天归零、取消不转移、锁定生命存读档不重复和结算同帧快照。
