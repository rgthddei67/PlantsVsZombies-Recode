# 天气、出怪与掉落

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

### 天气条件变异

同时使用 `adding-rain-weather`。`spawnlists.json` 与波次点数预算只放基础类型，正式生成路径在扣点前经唯一 resolver 决定实际变异类型；`CreateZombie`/`spawn_zombie` 保持直造确定性。每波上限只在推进新波时清零，不能被天气切换重置；已生成数必须入存档，`weight: 0` 的变异体不得独立进入随机池。
### 无尽候选池的品种排除必须只收窄候选池资格

把明确禁入类型放进 `BuildSurvivalSpawnList()` 和冻结池读档共用的统一资格查询，使选卡预览、正式波次与旧档恢复共用同一 `mSpawnZombieList`；不得把排除扩大到冒险 `spawnlists.json`、开发者直造、AutoTest `spawn_zombie`、已存在僵尸实体的读档恢复或其他显式召唤来源。专项导出“候选资格”和“本轮实际池中是否存在”两层状态，并用同类普通版本作允许对照，避免固定 Seed 恰好没抽中而假绿。
### 普通基础类型的每波上限也走唯一正式 resolver

把上限计数放 `Board::ResolveWaveZombieType` 等正式波次解析入口，超额返回失败哨兵且不消费候选预算；`CreateZombie`/`spawn_zombie` 保持直造确定性。计数只在 `SummonNextWave()` 与明确的新生存轮边界清零并进入存档，不能按教学关例外，除非规格明说。若还规定场上同时上限，resolver 必须同时统计未死亡敌对实体与已提交的延迟出生事务；魅惑、死亡或事务结算后释放同时名额，但不得返还本波累计名额。专项应在自然出怪表不含该类型的关卡直测解析器，分别锁定每波、同时、换波与快照语义，避免换波后自然抽中同类干扰“已清零”的断言。
### 成功能力后的跨波刷新冷却必须覆盖完整波次

由 `Board` 同时保存“当前波是否封锁”和“未来仍需封锁的完整波数”；能力只有在正式结算边沿成功提交时才同时封锁本波余下候选并写入未来波数，提前击杀、取消或无效结算不得启动。`SummonNextWave()` 必须在本波任何候选解析前把一份未来冷却转为当前波封锁，再由唯一正式 resolver 返回失败哨兵且不扣预算；不能只保存一个在换波时递减的数字，否则最后一个冷却波生成完成后，同波稍后的正式候选会提前解封。两字段都入档，旧档用中性值；生存换轮默认不清零，明确教学保证才在 resolver 处窄豁免。`CreateZombie`、预览、直造测试和读档恢复保持确定性且不消费冷却。AutoTest 覆盖成功边沿、本波余下候选、后续每个完整波、最早恢复波、取消路径、快照往返与轮次边界。
### 僵尸主动改变天气

同时使用 `adding-rain-weather`。僵尸只保存并推进自身施法节奏、次数或生命跨段，实际雨势升档必须调用 Board 的语义窄入口；入口显式规定不支持地图/锁定天气 no-op、强天气是否允许降级、同档是否续期及是否附带台风。固定周期触发应在本次动作确实完成后记数，生命阈值触发要排除同次致死并只在跨边沿调用；Board 现有雨势/过渡/余时已经入档时禁止在实体复制。专项覆盖不支持地图、弱转强、已有更强天气、同档续期、后续受击/施法不刷新和双方快照往返。
### 地图积累器联动

同时使用 `adding-rain-weather`。由 `Board` 在满值边沿一次性收集普通路线与实体能力候选；简单替换规则可按位置与稳定 ID 选唯一候选，智能路线则让全部候选在同一组共同随机 rollout 中比较，但都只能锁定既有一次事件，不能扩大目标数量。实体用语义虚接口声明“类型身份、当前资格、视觉锚点”，`EntityRegistry` 用有序弱索引避免热路径扫描普通僵尸。Board 保存最终路线、行及必要的稳定实体 ID；WARNING 中死亡、换行、破甲、后来出生和跨波残留均不得重抽，锁定实体失效时按既定路线结算、只跳过依赖实时资格的自身增益。蒙特卡洛开启时不得先消费正式 RNG，关闭或推演失败才走规格指定的稳定回退。若能力只强化该僵尸自身位移，在 `Zombie` 提供实例倍率虚入口并乘 Board 基础速度，禁止升级成整行光环。AutoTest 覆盖候选数、锁定存读档、失效不重抽、正式回退及普通/能力路线的效果差异。
### 外部区域压制僵尸的天气承接能力

区域所有者声明位置语义，Board 提供只读聚合查询，僵尸在自己的承接资格和直接受击后续状态入口分别消费；禁止让植物或 Board 修改僵尸私有计时器，也不要把“拒绝承接/拒绝过载”误扩大成免除本次胸甲伤害、麻痹或品种其他抗性。若承接与自身直击会走不同函数，两处都必须显式审计；专项至少同时放一只被保护目标，证明区域内提供者不承接、目标恢复原伤害/控制，而提供者自身仍按原直接伤甲但不进入被压制状态。
### 地形限定刷新必须放正式选行入口

只允许陆地或水路刷新的品种统一登记到 `Board::IsSpawnRowCompatible` / `CanZombieTypeSpawnInPool`，让 `SelectSpawnRow` 在加权前把非法行权重清零；零条合法行必须返回失败哨兵并由波次调用方跳过候选，禁止兜底成 `row 0` 后仍创建。地图解禁时同步复核品种自己的坐标基准、场地效果和出生 Y，不能只删兼容性门禁。`CreateZombie` / AutoTest `spawn_zombie` 继续保留直造确定性；专项先用 `assert_zombie_spawn_row` 锁定边界行，再以固定 Seed 走 `SummonNextWave()` 并断言正式实体实际覆盖多条合法行。
### 地图出生改道只能接在正式波次创建边界

雪穴等入口在候选类型、预算和行已经提交后，只允许延迟并改变这一只的出生 X；不得重抽类型、行或返还预算。预警期间入口被封时回退右侧出生，已创建实体不追溯。内部召唤、预览、开发者直造和 `CreateZombieWithID` 读档恢复不经过改道。延迟事务保存实际类型、行、原波次、锁定入口与余时，读档仍在同一提交边沿决定入口是否有效；出生奖励和正式遭遇记录只在真正创建成功后分配。待出生队列非空时禁止按残血提前出波；兑现边沿必须同步刷新血量，不能等周期采样。提前出波血量阈值由 `FinalizeWaveSpawnThreshold()` 在本波全部候选兑现后锁定，不能用预警期间缺少实体的血量计算；过期波次事务不得重算当前波阈值。专项开启自然出波，覆盖五路全改道、部分改道、倍速、预警读档与封穴回退，并证明未受伤不连跳、达到残血阈值仍正常推进。
### 新增无尽地形只登记模式，不复制出怪池或冒险脚本

关卡号、背景、显示名和解锁大关统一加入 `SURVIVAL_ENDLESS_DEFINITIONS`，让选关、`mIsSurvival`、背景与独立存档自动消费；僵尸继续走 `CanZombieTypeEnterSurvivalPool()` 和 gamedata `survivalRound`，除非规格明确要求地形专属白名单。背景特有的 Board 环境可以复用，但必须用 `mIsSurvival` 隔离原冒险区域的教学保证、固定关序和收官波脚本。AutoTest 至少锁定“区域末关尚未通关 / 进度越过末关”两侧的入口数量，并验证真实进入、背景环境、代表性僵尸轮次资格和快照往返。

### 击杀掉落资源先在正式出生时预分配并按波封顶

死亡、灰烬群杀和其他 `Die()` 路径只领取出生时锁定的奖励，禁止按本次死亡数量临时 roll，否则范围灰烬会把经济成倍放大。若设计要求关内前宽后紧，用当前波/总波数建立独立归一化曲线，同时收紧携带概率、单团价值和单波预算；跨波累计器只补偿未命中，预算命中硬闸后不再累加。AutoTest 用正式 `SummonNextWave()` 和至少两种总波数断言首尾参数及最终波实际上限。

### 预先锁定整波的地图

预先锁定整波的地图必须把教学保底和每波上限放入预报计划生成过程，并在扣预算后构造计划；验证全部波的计划、实际出生 `spawnWave` 和计划读档一致性，不能只验证直接生成单只的夹具。
