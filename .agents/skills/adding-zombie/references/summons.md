# 召唤、编队与延迟攻击

按当前任务读取命中段落，各专项只在对应机制受影响时适用；流程与审批遵循 [技能入口](../SKILL.md) 和 [AGENTS.md](../../../../AGENTS.md)。

### 编队齐舞/同步动作

动画速度必须 `SetAnimationSpeed(固定值)` 锁死——基类 `Start()` 给每僵尸随机 1.1~1.4，不锁必散拍。全队同步时钟用现成的 `Board::mBoardFrame`+`GetDanceBeatFrame()`（0~22 拍，12 逻辑步/拍，入存档），按拍映射轨道、缓存上次段位防每帧重播。
### 单个正式候选扩成多实体编队

随机池、`weight`、首次登场和每波上限只登记可抽中的领队身份；唯一正式 resolver 接纳一次候选并扣一次编队预算后，领队等拿到稳定实体 ID 再创建随员，随员不得再次经过候选解析或重复计上限。`CreateZombieWithID` 只恢复存档逐只列出的成员，禁止自动补齐队伍。选卡/图鉴的候选语义仍是 1；若宣传画面需要展示完整编队，可显式创建 N 个无稳定 ID、无碰撞、无玩法注册的展示实体，并由对应预览容器逐一持有和销毁，绝不能复用正式随员生成入口。Board 预览每个展示实体的 `mZombieNumber++` 必须与一次基础 `Zombie::Die()` 严格平衡；整队死亡不得依赖已登记的 `memberIDs[0]` 才回收领队，否则单体预览或正式首帧死亡会留下幽灵计数。图鉴 `board=nullptr` 不参与计数，但切换条目也必须销毁整组展示对象。每名正式成员都保存 `role/slot/leaderID/memberIDs/phase`；运行时按稳定 ID 解引用，缺领队或缺槽位时跳过缺员并降级到可独立行动的安全 phase，禁止读档、阵亡或孤儿修复时复活/补召。专项至少锁定“一次候选=N 个正式实体、同波第二次候选被拒、预览候选=1 但展示槽位齐全、预览销毁后 `zombieCount==zombieNumber==0`、完整编队与缺员快照往返”；最终波零实体旧档还应验证计数归零并出现奖杯。
### 编队出界回收必须使用当前阶段的位置权威

乘车、推车或其他附着编队若把后排成员的逻辑原点放在领队右侧，通用逐实体右边界会在自然出生区先 `Die()` 后排，再经队伍死亡联动误删整队。附着/落地阶段通过基类窄虚入口统一按领队 X 判断；损坏引用先走安全脱队，独立步行后恢复每名实体自己的出界回收。AutoTest 用正式自然出生 X，等待超过边界轮询周期后仍断言完整成员数和附着 phase，不能只等两帧。
### 累计释放上限必须绑定正式提交结果

仅成功提交独立召唤事务才消费一次，前摇中断和无合法落点不得扣次数；封顶后停止进入前摇但保留普通移动与啃食。次数同时审计实体存档与钟匠窄能力快照；是否随时间锚回溯须按主人明确口径实现，不能默认为不可逆或漏存后复建归零。专项覆盖中断不扣、封顶往返，以及存活和死亡目标的时间锚恢复。
### 召唤僵尸

`mBoard->CreateZombie(type, row, x)`（y 恒由 row 派生）；关联用 EntityRegistry 整型 ID（死亡自动失效）；**槽位有效性 = `GetZombie(id)` 非空 且 `IsMindControlled()` 与本体一致**——只判空则被魅惑的随从永远占位、补召失灵；行越界/永久不可用的槽要豁免，否则无限重触发召唤动作。持续补召必须把“最多维持数量”和“补召间隔”集中为匿名 namespace 可调常量，并明确计时使用哪种 delta：精英舞王实证为冻结暂停、减速按 scaled delta 拖慢，天气动画倍率不得重复加速召唤逻辑。

### 历史范围召唤池必须逐项显式列举

规格写“某大关以前所有僵尸”时，禁止遍历 `[0, NUM_ZOMBIE_TYPES)` 或复用会继续扩张的注册表；把当时允许的基础、精英和必然派生子单位逐项列入固定数组，并用 AutoTest 分别锁定允许的边界类型与下一大关/首领/特殊禁入类型。实际抽取再按目标行调用 `Board::CanSpawnZombieInRow` 过滤，历史白名单包含泳池形态不等于能把它生成到屋顶。未来新增枚举不得无意进入旧首领召唤池。
### 残血召唤压迫必须同时提高质量

只缩短间隔或增加数量仍可能连续抽到低威胁杂兵。把历史白名单显式拆成标准/高威胁子池，由当前生命等权威阶段状态派生高威胁概率，不另存易漂移字段；若最终阶段规格要求硬压制，就让概率达到 100%，而不是保留随机放水。AutoTest 导出当前概率，并分别锁定满血、中段和最终阶段；最终阶段至少连续两批断言“高威胁数=实际生成数”，避免单批固定 Seed 假绿。

### 投掷召唤物的离手事件必须先成功创建、后消费库存

持有标志是背部/手中子单位显隐与能否再次投掷的唯一权威；创建失败保持库存和轨道，创建成功后再配置阵营、飞行参数与剩余减速，并最后清标志。巨人等投手保存动作 phase、是否已经越过离手帧、投掷距离和唯一持有标志；召唤物保存飞行/落地 phase、高度、水平/竖直速度与方向。读档分别覆盖离手前、离手后但动作未完和动作完成，禁止从现场是否存在召唤物反推库存。原版离手动作若是 `PlayOnceAndHold`，必须用一次性播放并在剪辑末帧停住；`PlayTrack` 会强制 `PLAY_REPEAT`，当物理飞行长于剪辑时回绕首帧会造成空中回弹。旧档缺 `animPlayState` 而按循环恢复时，应保留当前帧只修播放状态，禁止重新起播。按世界 X 分界且只允许在一侧起手时，触发距离必须保留相对分界线的符号，禁止取绝对值后让单位越线越远反而重新满足条件；AutoTest 在分界线两侧各放一只半血静止投手，分别锁定允许起手与持续禁投。只抬高离手高度会延长重力飞行并带偏水平落点；若规格只要求视觉起点上抬，应先用旧高度和旧初速解出原落地时刻，再按新高度反算竖直初速，保持飞行总时长、水平速度和落点不变。若还明确要求水平距离乘倍率且水平速度不变，必须把“倍率后的落点仍位于哪些地图格”写成合同，再把原落地时长乘同一倍率作为新目标时长并结合新高度反算竖直初速；禁止无落点断言地盲乘完整飞行时长，因为屋顶的额外距离修正可能掩盖草地越过第一格的错误。AutoTest 用网格相对投影锁定落地列，并覆盖至少一个无屋顶修正的地图；屋顶与非屋顶公式分叉时两者都要覆盖。

### 僵尸临时持有植物必须建立双向关系和三层绘制契约

植物保存持有者实体 ID、抓取/离地状态与视觉偏移；抓取起禁用行为、承伤、啃食资格、碰撞和显式阴影附件，离地后跳过植物常规 `Draw()`，由僵尸在“后层身体 → `Plant::DrawAsBungeeCargo` → 前臂专用 Animator”顺序提交，不能只调对象 draw order 期待跨对象夹层。僵尸保存目标格与植物 ID，`LoadExtraData()`/`ZombieItemUpdate()` 在实体恢复后重建关系、前臂显隐和双层影子；抓取未离地时僵尸死亡应释放植物并恢复原状态，已经离地则按能力规格结算植物。AutoTest 必须覆盖抓取中禁用、离地截图、双方快照往返、两阶段死亡和退出清理。
### 离体但仍由僵尸持有的延迟攻击要按投出瞬间锁定

保存飞行起终点、已飞时间、目标行、下一次倒计时和投出时阵营；飞行更新必须放在冻结、掉头和死亡动画的新攻击门禁之前，使已经离手的攻击继续结算。投出时隐藏手持轨、落地后恢复，`LoadExtraData()` 与 `ZombieItemUpdate()` 都按飞行状态重建显隐；若设计要求投掷者被立即回收后仍保留攻击，则不能继续把投射物只存在僵尸对象内，必须改成独立实体。
